# 함정 12 — 계기 구성이 제품 구성에서 도출되지 않으면 한쪽만 바뀌어도 아무도 모른다

Stage 0/1a 설계에서 명시적으로 등재. 규범: **계기 기본값은 항상 제품 코드에서 도출**,
별도 하드코딩 금지.

이 규범이 나중에 §5(부호-필드 디커플)의 배선 원칙이 됨: 부호는 수밀 전신 표면
flood-fill로 단일 산출, per-part 필드는 무부호 전용 — 계기가 두 갈래로 나뉘면서도
근원은 하나.

관련: [[함정13-jitter]] — 계기 오류가 이틀 만에 2번(스무딩 기본값, jitter 정의)
발생했는데 둘 다 이 함정의 하위 사례.

## 사례 추가 — 링 rest (29회차)
`ringRestM`(하네스)이 제품 코드에서 도출되지 않고 `necklineRing` 3D 합에
`2 × SEAM_REST_LENGTH`를 **더해 재구성**했다. 그런데 정작 그 rest와 비교되는
`ringLenM()`은 접합 2쌍을 **안 센다** — 분자와 분모가 다른 집합이다.

결과: 25·26·27회차 보고 배율이 전량 과소(2.114→2.167 / 1.093→1.120). 집행은
절대값 비교라 무사했지만 **판정 근거로 쓰인 숫자가 4회차 동안 틀려 있었다.**

규범: **계기가 쓰는 rest는 제약이 실제로 순회하는 집합에서 직접 뜬다.**
집합이 다르면 이름이 같아도 다른 양이다.

## 사례 추가 — **문자열 리터럴 「15」 4건** (99회차 §5-3 자체 판정 · **규범 신설 0 · 수리 0줄**)

`scripts/dressPattern.ts`의 흡착 국면 인쇄가 **경계값을 문자열에 박아 두었다.**

```
:3612   ` · 국면1(자석 d>15) … 국면2(안착 0<d≤15) …`   ← 「15」가 **문자열 리터럴**
:1473 · :1477   **「15.0mm」 문자열 하드 2건**(밑단/링 국면 3분할 인쇄)
:3901   함정22 대조 인쇄 · **「15」 문자열 하드**
⟹ `COLLISION_MARGIN` **상수를 바꿔도 안 따라온다**
```

**상수를 «읽는» 인쇄는 따로 있고, 그쪽은 다른 어긋남을 낸다**

```
:3616  `경계 = COLLISION_MARGIN 15.0mm`                      상수는 따라간다
:3677  `[35계기·흡착 파라미터] margin 15.0mm(clothConfig …)`   **clothConfig 상수**를 인쇄
그런데 99 계획의 처치는 **호출부 리터럴**을 바꾸는 것이다 —
⟹ 물리는 3mm로 도는데 계기 두 줄은 **15mm를 인쇄**한다
   이 두 건은 [[함정19-계기가다른대상]] 계열이다(98 §0-3 (b) 분류를 잇는다)
```

**이 함정에 붙인 근거**: `:3677`은 「계기가 문서 대신 **코드**에서 인쇄한다」([[함정13-jitter]] 대응)로
세운 안전장치인데, **호출부 리터럴 변경이 정확히 그것을 무력화한다.** 문자열 4건은 그보다 약해
**아무것도 읽지 않는다** — 이 노트의 한 줄 요지(**「한쪽만 바뀌어도 아무도 모른다」**)가
그대로 성립한다.

**갈라 본 결과**: [[함정13-jitter]] 규범 6은 대상이 **계기의 정의**(축·시점·정규화·집합·값역)라
100% 지켜도 문자열은 남는다 → **계열 아님**. [[함정19-계기가다른대상]]은 「다른 대상을 **잰다**」인데
문자열 4건은 **아무것도 안 잰다** → **부분만 덮는다**.

**수리 0줄**(99회차 코드 0줄). 처분은 99 §1 선행 조건 ①②가 이미 못박았다 —
**호출부에 실제로 넘어간 값에서 인쇄하거나, 판정 채널에서 내린다.**

**병기(계기 아님)**: `correctPlacementPenetration`(`:329` · `:2082`)은 **상수를 받는다** —
호출부 리터럴을 바꾸면 **배치 교정은 15mm 껍질 · 정착 물리는 3mm 껍질**이 된다.
이것은 인쇄가 아니라 **물리 불일치**이고 어느 함정에도 붙이지 않는다(사실 등재만).

→ [[../회차/2b-99-margin처방]] §1(c) · §1(e) · §5-3

### 해소 (100회차 · **원문 무삭제** · 위 99 블록은 그대로 둔다)

**문자열 하드 「15」 4건이 수리됐다 — 전부 «보간»으로 바뀌었다.**

```
:1473  「경계 margin 15.0mm」      → **보간**
:1477  「흡착 margin 15.0mm」      → **보간**
:3612  「d>15」「0<d≤15」 **2건**   → **보간**
:1581 · :3616 · :3677             → **세 값 병기**(정착 물리 / 배치 교정 / 상수)
:1470 · :1570 · :3604-3605 · :3901 → **`MESH_MARGIN`**(호출부에 넘어간 값)에 배선
회귀   **25항목 비트 재현 · 게이트 전 항목 일치 · dress-state md5 불변** ⟹ **인쇄 전용 수정**
```

**열거 차이 1건(사실 등재 · 판정 0)**: 99 §5-3이 문자열 하드로 든 4건은
`:3612`·`:1473`·`:1477`·`:3901`이었고, 100 이행표 ②의 4건은 `:1473`·`:1477`·`:3612`(2건)이며
**`:3901`은 ①의 `MESH_MARGIN` 배선 대상**으로 적힌다. **어느 열거가 옳은지는 판정하지 않는다.**

**`correctPlacementPenetration`(`:329`·`:2082`)**은 100회차에 **`PLACE_MARGIN`으로 분리·병기**됐다.
**어느 값으로 «고정»할지는 정해지지 않았다**(채택 회차 몫) — 위 99 병기 블록의
「물리 불일치」 진술은 **그대로 유효**하다.

## 규범 추가 — **호출부에 넘어간 값** (100회차 승격 · 문턱 0 · 처방 0)

> **계기는 상수가 아니라 «그 소비처의 호출부에 넘어간 값»을 읽는다.**
> **소비처가 갈리면 갈린 값을 «전부 병기»한다.**

이번 실측에서 도출된 것만 적는다:

```
① 같은 상수(`COLLISION_MARGIN`)를 읽는 **물리 소비처가 8곳 · 발화 6곳**이고
   **코드가 강제하는 결합은 0건**이다 ⟹ **상수 하나를 인쇄하는 계기는
   «어느 소비처의 값»인지 가르지 못한다**
② `MESH_MARGIN`/`PLACE_MARGIN`으로 갈라 호출부 값을 읽게 하고 **세 값을 병기**했더니
   **25항목 전부 비트 재현**됐다 ⟹ **인쇄 전용이다**
```

**범위**: 이것은 **계기 인쇄의 규범**이다. margin 값의 **«도출»과는 무관**하고
100회차는 도출을 확정하지 않았다([[../원리/사전등록]] 규범 4·5).

→ [[../회차/2b-100-margin선행이행]] §2 · §3 · §5-1

## 사례 추가 — **위 규범의 «게이트 하네스 판» 미이행** (102회차 §5-2 자체 판정 · **신설 0**)
