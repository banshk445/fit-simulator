# 함정 37 — 이분 탐색의 «브래킷»을 바꾸면 답은 같아도 마지막 비트가 흔들린다

## 무슨 일이 있었나

v3-88 은 소매 반지름의 **하한** 하나를 고쳤다:

```
 RMIN = CAP_W/π            →      RMIN = (2·CAP_W + SEP)/(2π)
```

겨눈 대상은 **소매 7칸**이었다. 그런데 108칸 조립 드라이런에서 **101칸 중 78칸의 패턴해시가
바뀌었다** — 하한에 «안 붙은» 칸까지 전부. 사전 등재한 회귀 기대(「소매 7칸 외 비트 동일」)를
어겼고, 그 판은 **갈래 B(즉시 복원)** 로 닫혔다.

원인은 탐색의 «시작점»이다:

```ts
 let lo = RMIN, hi = RMIN;
 while (probe(x0, hi) < SEP && hi < 0.30) hi *= 1.15;   // 기하 사다리
 for (let i = 0; i < 40; i++) { ... }                    // 40회 이분
```

`RMIN` 이 바뀌면 **사다리의 발판이 전부 옮겨가고 이분 브래킷 `[lo, hi]` 가 달라진다.**
40회 이분은 같은 임계값으로 수렴하지만 **마지막 비트는 브래킷에 의존**한다.

**규모**: 실측 최대 좌표차 **2.6e-16 ~ 1.7e-14 m** — 재현 규칙(4·ULP_f32 ≈ 6.2e-7 m)의
**약 1/40,000,000**. 물리적으로 무의미하지만 **sha 는 전부 바뀐다**.

## 왜 그렇게 되나

**해가 같다 ≠ 비트가 같다.** 수치 탐색의 출력은 (해, 경로)의 함수이고, 브래킷·초기값·
반복 횟수는 전부 «경로»다. 경로를 건드리면 해가 안 변해도 부동소수 꼬리가 변한다.

## 규범

1. **하한·초기값을 탐색 브래킷과 «같은 변수»로 쓰지 말 것.** 물리적 하한(제약)과
   탐색 시작점(경로)은 다른 역할이다 — 붙여 두면 제약을 고칠 때마다 전 산출물이 흔들린다.
2. 회귀 기대를 **비트 동일로 걸 때는 경로 변경이 없는지 먼저 본다.** 제약 상수 하나만
   바꿨다고 「그 칸만 바뀐다」고 가정하지 않는다.
3. **회귀 기준을 수로 정한다** — [[함정35-정규화자기상쇄]] 의 4 ULP 규칙.
   비트 동일과 수치 재현이 갈릴 때 **어느 쪽으로 판정할지 미리** 정해 둔다(v3-88 에서 실제로 갈렸다).
4. 그래도 **문면이 비트 동일이면 문면을 따른다** — 기대를 사후에 완화하지 않는다(함정 14).
   조정은 다음 판의 «발주»에서 한다.
