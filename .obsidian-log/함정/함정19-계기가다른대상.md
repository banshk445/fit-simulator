# 함정 19 — 계기가 다른 대상을 찍고 있었다

## 사례
`scripts/capture.ts`의 기본 BASE:
```
http://localhost:5173/?autofit=1&newcore=1
```
**`patterncore=1&patternstate=1`이 없다.** 그래서 2b 회차의 5뷰 캡처는 그 회차의
착장 상태(`public/dress-state.json`)가 아니라 **v1 제품 경로**를 찍는다.

34회차 1차 캡처 5장이 그랬다. **5장 전부 정상적으로 산출됐고** 파일 크기·해상도·
구도 어디에도 실패 신호가 없었다. `CAPTURE_URL`을 지정해 재촬영한 뒤에야 드러났다 —
**5/5 MD5 상이 · hem +54% · neck +31%**.
```
CAPTURE_URL='http://localhost:5173/?patterncore=1&patternstate=1' npm run capture front,back,neck,cuff,hem
→ /tmp/fit-capture/{front,back,neck,cuff,hem}.png · dress-state.json 128,863B(실행 5분 내)
```

## 규범
**계기의 입력 경로(URL · 파일 · 해시)를 판정 전에 인쇄하고 확인한다.**
산출이 성공했다는 것은 옳은 대상을 쟀다는 뜻이 아니다.

[[함정08-fixture표류]](입력 데이터가 조용히 바뀜)와 [[함정13-jitter]](라벨이
계산되지 않은 것을 주장)의 형제다. 셋 다 "계기가 돌았다"를 "계기가 맞다"로 읽는다.

## 회수 — 확인 필요
과거 2b 회차의 화면 판정이 `CAPTURE_URL` 없이 이뤄졌다면 **v1을 본 것일 수 있다** —
**재검토 대상**(단정하지 않는다. 각 회차 노트·로그에서 캡처 명령줄을 확인해야 한다).
→ [[2b-34-핀rest처방]]
