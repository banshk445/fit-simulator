# 함정 19 — 계기가 다른 대상을 찍고 있었다

## 사례
`scripts/capture.ts`의 기본 BASE:
```
http://localhost:5173/?autofit=1&newcore=1
```
**`patterncore=1&patternstate=1`이 없다.** 그래서 2b 회차의 5뷰 캡처는 그 회차의
착장 상태(`public/dress-state.json`)가 아니라 **v1 제품 경로**를 찍는다.

34회차 1차 캡처 5장이 그랬다. **5장 전부 정상적으로 산출됐고** 파일 크기·해상도·
구도 어디에도 실패 신호가 없었다. `CAPTURE_URL`을 지정해 재촬영한 뒤에야 드러났다 —
**5/5 MD5 상이 · hem +54% · neck +31%**.
```
CAPTURE_URL='http://localhost:5173/?patterncore=1&patternstate=1' npm run capture front,back,neck,cuff,hem
→ /tmp/fit-capture/{front,back,neck,cuff,hem}.png · dress-state.json 128,863B(실행 5분 내)
```

## 가장 강한 실례 (57회차) — 통계 정의역이 화면 표적을 구조적으로 제외했다

밑단 요동 채널 `hemWobble`의 `interior` 필터가 사슬 **양끝 W/2씩**을 제외한다
(`dressPattern.ts:1076`). `chainOf`가 **패턴 x로 정렬**하므로(`:1045`)
**사슬 끝 = 옆선 시접**이다.

```
W=16 → 앞뒤 사슬 4끝 × 8cm = **32cm** ≈ 밑단 폐곡선 112cm의 **29%**
제외된 29%가 정확히 **옆선 4곳 근방**
```

**화면 표적은 「옆선 프릴」인데, 그 판정에 9회차에 걸쳐 인용된 숫자는
옆선을 구조적으로 제외한 채널이었다.** 계기는 매번 정상 산출됐고 실패 신호가 없었다.

옆선을 실제로 재는 **β-1**이 같은 두 로그(54회차)에 **이미 있었고**
**6/6 채널 −63~92%로 화면과 일치**한다(0홉 −66/−70 · 1홉 −71/−92 · 2홉 −63/−90).
단서: β-1도 세로 사슬이라 수평 접선 `|t|` 조건수 문제가 활성 → **크기의 하계**로 읽는다.

## 사례 (76 → 77회차) — **저장소 밖 스크립트가 함수와 다른 입력을 봤다**

76회차가 「테두리 8% 띠 표본 14,720 · 유효 **119(0.8%)**」로 적어
**「대표색 근거가 얇다」**를 결론했다. 그 표본은 `borderRepresentativeColor`가
**실제로 순회하는 집합이 아니었다** — 저장소 밖 파이썬으로 **업로드 원본(750×1000)**을
쟀는데 **그 함수는 crop 산출물(723×668)**을 본다.

```
실제(crop본 · 함수 식 그대로)
  컷아웃  띠 표본 141,830 · 유효 **18,937 (13.35%)** · 최빈 10,246 (54.1%)
  흰 배경 띠 표본 141,830 · 유효 **19,379 (13.66%)** · 최빈 10,142 (52.3%)
0.8%의 출처 재현  원본 8% 띠 1,812/220,800 = **0.82%** · 220×220 축소면 표본 14,544
```

**「근거가 얇다」는 무효**(실제 18,937px · 최빈 54.1%). **「자산 교체로 안 바뀐다」는 유효.**

**앞 사례들과 다른 점**: 34 · 57회차는 **계기의 정의역**, 73 · 74회차는 **촬영 대상**이
빗나간 것인데, 여기서는 **계기를 저장소 밖에서 재현하면서 입력 단계가 어긋났다.**
파이썬 산출은 정상이었고 숫자도 그럴듯했다 — 실패 신호가 없다.
**자체 귀책**(전략 세션 지적이 아니라 77회차가 이식 대조 중 스스로 잡았다).

## 사례 (79회차) — **주석이 말하는 대상이 코드의 대상과 다르다** (`rayMin 5mm`)

`coverageMetric.ts:336`의 레이 t 하한 5mm. 주석(303-306)은
「**표면 자기 자신(두께 0의 몸 메시)을 안 맞히도록**」이라고 적었다.
그런데 **그 레이가 쏘는 `tris`는 옷 삼각형뿐이고 몸 메시가 들어 있지 않다** —
이 하한이 걸러내는 것은 **전부 실제 옷 히트**다.

```
top-back 노출 98개의 최근접 옷 정점 거리 중앙 **6.2mm** vs 피복 판정 103개 **8.7mm**
  → **노출로 찍힌 쪽이 오히려 옷에 더 가깝다**
tMin 5mm(현행) → 0mm   전체 637 → 507 · **top-back 98 → 28** · **bot 142 → 142(불변)**
```

**어깨 상단 노출의 71%가 이 하한의 산물**이고 `bot`은 전혀 안 움직인다(진짜 맨살).
34 · 57회차는 **정의역**이, 73 · 74회차는 **촬영 대상**이, 76 → 77회차는 **입력**이
빗나간 것인데, 여기서는 **주석이 서술한 대상 자체가 코드에 없다** — 계기를 읽는 사람이
「몸 메시 자기 히트 방지」라는 무해한 설명을 그대로 믿게 만든다.

**※ 하한 제거가 옳다는 판정은 아니다** — 관통도 t<5mm로 들어오므로 제거하면 관통을
피복으로 셀 수 있다([[함정11-관통vs노출]]). 위는 **현행 값이 얼마를 만드는가**의 실측이다.

## 규범
**계기의 입력 경로(URL · 파일 · 해시)를 판정 전에 인쇄하고 확인한다.**
**주석이 서술하는 대상이 그 코드가 실제로 다루는 집합에 있는지 확인한다**(79회차) —
주석은 검증되지 않은 진술이고, 틀린 주석은 채널을 옳은 것으로 읽게 만든다.
**계기를 저장소 밖에서 재현할 때는 함수가 실제로 받는 입력을 먼저 확인한다**(77회차) —
원본이냐 가공물이냐가 갈리면 같은 식도 다른 대상을 잰다.
**화면 판정은 이미지를 열어 대상을 확인한 뒤에만 한다** — 픽셀 통계·md5는 **보조**다(74회차).
**그리고 통계 정의역이 화면 표적을 포함하는지 확인한다**(57회차) —
끝단 절단·마스크·필터가 표적 대역을 빼고 있으면 산출은 성공해도 대상이 다르다.
산출이 성공했다는 것은 옳은 대상을 쟀다는 뜻이 아니다.

[[함정08-fixture표류]](입력 데이터가 조용히 바뀜)와 [[함정13-jitter]](라벨이
계산되지 않은 것을 주장)의 형제다. 셋 다 "계기가 돌았다"를 "계기가 맞다"로 읽는다.
