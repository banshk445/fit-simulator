# 함정 17 — 전제가 반납된 결정은 자동으로 재검토되지 않는다

## 사례
21회차가 링 전용 제약을 봉합 전까지 해제했다. 근거는 한 문장이었다:
> 착장 중 유지력은 **하드 핀이 담당하고**(잔차 0.00mm 실증) 링이 조여 있을 이유가 없다.

이후 §4 개정이 "앵커 층위 4연속 실패로 소진"을 선언하고 착장 앵커를 기본 off로
반납했다. **그런데 21회차의 결정은 그대로 남았다.** 근거가 사라진 결정이
11회차 동안 배선에 살아 있었고, 30·31회차가 "목선 제약이 성장 구간 내내
배선상 부재"를 발견하고서야 드러났다.

## 더 나쁜 두 번째 층 (33회차)
반납 자체도 **절반만** 이뤄져 있었다. `anchors: () => []`는 소프트 앵커 경로만
끄고 하드 핀 경로(`setAnchorHard` → `sim.pin`)는 살려 뒀다. 그래서
"앵커는 껐다"는 진술과 "t=0에 앵커 목표 좌표가 찍혀 있다"는 실측이 동시에 참이었다.

## 사례 추가 — **`PINDRESS` off인데 하드 앵커가 발화한다** (105회차 · 자체 판정 · 위 문언 수정 0)

**33회차 「더 나쁜 두 번째 층」과 같은 시그니처이고, 같은 코드 쌍이 v2 착장 경로에서 살아 있다.**
105회차가 **폭 소비처 정리 중 앵커 36개를 추적하다** 확정했다(신규 확정 · **배선 변경 0**).

```
소프트   dressPattern.ts:1886  anchors: () => (PINDRESS ? anchorList : [])   → **꺼진다**
하드     dressPattern.ts:2051-2093  setAnchorHard(→ sim.pinned[a.i] = 1 · setParticle)
         → **`PINDRESS`를 참조하지 않는다**
로그     dressPattern.ts:497  「착장 앵커 off(기본)」 = **소프트 경로만** 가리킨다
실측 정황 104의 e=3cm 실행이 던진 자리가 **「앵커 하드 핀 위치 램프 시작 … 36개」 직후**이고,
         34게이트 호출도 `setAnchorHard` **안**(`:2091`)이다
```

**33회차와 같은 것**: 「앵커는 껐다」는 진술과 「하드 경로가 돌고 있다」는 실측이 **동시에 참**이다.
**33회차와 다른 것**: 33은 반납 커밋의 **절반 이행**이었고, 여기서는 **상태 인쇄 문구가 그 절반을
「off」로 요약**한다 — **계기 층위의 결함이 하나 더 얹혀 있다.**

**계열 대조 (105 §4-2 자체 판정)**

```
[[함정12-계기하드코딩]]   **부수 · 사례 «후보»** — 100회차 규범(「소비처가 갈리면 갈린 값을
                        **전부 병기**한다」)의 **앵커 판 미이행**이다(로그가 두 경로 중 하나만 인쇄).
                        **확정 0 · 오염 산출물 0**(105 판정에 그 로그 줄이 실린 것 0건)
[[함정13-jitter]]        **대조만 · 사례 신설 0** — 「이름이 계산되지 않는 것을 주장한다」와
                        같은 줄이나 **대상이 계기 채널이 아니라 «상태 인쇄 문구»**다
주 귀속                  **함정 17** — 스위치 하나를 끈 것이 **전 경로를 끈 것이 아니다**.
                        아래 규범의 「진입점 grep」 항목이 바로 이 자리다
```

**처분**: **등재만 · 배선 변경 0 · 로그 문언 수정 0 · 규범 신설 0 · 문언 수정 0.**
어느 쪽이 옳은 기본값인지는 **앵커 층위를 여는 회차가 판정**한다.
→ [[../회차/2b-105-폭소비처]] §1-3 · §4-2

## 규범
**어떤 층위를 반납할 때, 그 층위를 근거로 삼았던 과거 결정 목록을 함께 회수한다.**
- 반납 커밋에 "이 층위를 근거로 한 결정" 목록을 적고 각각 재판정 여부를 표시
- 반납이 경로 하나가 아니라 **전 경로**에서 이뤄졌는지 확인한다(진입점 grep)
