# 함정 32 — 처방이 결정항에 **닿되 «일부 소비처»에만** 닿았다

**정의**: 어떤 값의 **도출이 성립**하고 그 값이 표적의 **결정항에 실제로 닿아 표적을 움직였는데도**,
**같은 값을 읽는 다른 소비처가 옛 값으로 남아** 계가 **두 기준으로 갈린 채** 돌고,
그 상태에서 난 부수 손상이 **「도출이 틀렸다」로 오귀속될 수 있다.**

**[[함정31-절제작용점]]의 «거울상»이다.**

```
31   처치가 결정항에 **닿지 않는다** ⟹ 표적이 **원리적으로 안 움직인다**
32   처치가 결정항에 **닿는다 · 표적도 움직인다** ⟹ 그런데 **일부에만** 닿았다
```

**판정 규범이 먼저다**: **부분 적용 상태에서 난 실패는 «도출의 반증»으로 읽을 수 없다.**
읽으려면 소비처가 **전부 같은 값 위에 선 상태**의 산출이 있어야 한다.

## 규범 (101회차 실측·등재에서 도출된 것만)

1. **처방을 설계할 때 그 값을 읽는 «소비처 전량»을 먼저 열거**하고, 각 소비처를
   **바꿀 것 / 안 바꿀 것**으로 **실행 «전»에 갈라 적는다.** 안 바꾸는 쪽에는
   **왜 안 바꾸는지**(도출 불가 · 해시 파괴 등)를 함께 적는다.
2. **부분 적용으로 실행할 때는 «그 실행이 무엇을 반증할 수 없는지»를 사전등록에 적는다.**
   부분 적용에서 난 실패는 **도출의 반증이 아니다** — 갈래 이름은 실패를 말할 수 있어도
   **「도출이 틀렸다」는 그 실행의 산출이 아니다**.
3. **소비처가 갈리면 갈린 값을 «전부 로그에 병기»한다**([[함정12-계기하드코딩]] 100회차
   규범 승격분과 같은 자리) — 101은 이 항을 이행했고 그래서 갈림이 **판정 시점에 보였다**.
4. **문턱은 여기 박지 않는다.** 「몇 개 소비처까지 갈려도 되는가」는 그 처방을 채택하는 회차가
   **실행 전에** 도출한다([[../원리/사전등록]] 규범 4·5).

**기전 귀속 0**: 이 노트는 「부분 적용이 부수 손상의 «원인»이다」를 말하지 않는다.
101이 등재한 것은 ① 도출값이 작동했다(문턱 ①) ② 소비처가 갈려 있었다(차 11.8mm)
③ 부수 손상이 문턱을 넘었다 — **셋의 병렬 사실**이고 그 사이의 인과는 **미귀속**이다.

## **전량 적용 결과 (102회차 실측 · 원문 무삭제 · 이 함정을 «폐기하지 않는다»)**

102회차가 **네 소비처 전부**(정착 물리 · 배치 교정 · 배치 기하 · 제도 시접)에 같은 값
**3.212mm**를 넣었고, 사전등록 문턱 ⑥이 **적용이 실제로 전량임을 실증**했다
(`margin 채널` 원문: 「정착 물리 3.2 · 배치 교정 3.2 · 배치 기하 3.2 · 제도 시접 3.2mm」).
`patternHash`는 파기가 **승인된 사항**이었다(102 §0(2)).

```
cov 몸통    6.8%(기준선 A) →  87.4%(101 부분)  →  85.4%(102 일관)   개선 **2.0pp**
관통          50           →    692            →    628             개선 **64건**
자기교차     1889           →   3272            →   2986             개선 **286건**
```

**부분 → 일관의 개선폭이 A와의 격차에 비해 미미하다** — cov는 **78.6pp 격차 중 2.0pp만** 회복했다.

### 무엇이 기각됐고 무엇이 남는가 (**구분이 이 블록의 요지다**)

```
진술 A  「101에 소비처 **부분** 적용이 «있었다»」            = **참 · 유지**
        (로그가 스스로 「두 채널 상이(차 11.8mm)」를 인쇄했다 · 99 전제 7의 예고 그대로)
진술 B  「그 부분 적용이 부수 손상의 **«주 원인»**이었다」    = **이 사례에서 기각**
        (전량 적용 후에도 cov 85.4% · 관통 628 · 자기교차 2986 — **거의 그대로다**)
⟹  **이 함정의 «진단»은 참이고, 기각된 것은 «주 원인» 귀속이다.**
⟹  **cov 붕괴의 원인은 «부분 적용»이 아니다.** 그 원인이 무엇인지는 **미규명**이고
    **102도 기전을 귀속하지 않았다**(v1 스윕 붕괴 기전도 미규명 그대로)
```

**노트 문언과 충돌하지 않는다** — 이 노트는 처음부터 **「기전 귀속 0」**을 명시했고
①도출 작동 ②소비처 갈림 ③부수 손상을 **병렬 사실**로만 등재했다. 102가 더하는 것은
**「그 사이의 인과가 «주»는 아니었다」는 실측 한 줄**이다.

### 규범 1~4 — **전부 유효** (수정 0)

**규범 1(소비처 전량 열거)·3(갈린 값 전부 병기)을 102가 이행했기 때문에 이 판정이 가능했다** —

그 산출이 **101 실패값보다 «덜 나쁘다»**(102 문턱 ③ 충족)까지 보여줬다.
**규범 문언 수정 0 · 규범 신설 0 · 문턱 0 · 처방 0.**

## **폭 판본 — 판별 조항 «아니오» (105회차 · 자체 판정 · 이 노트 문언 수정 0)**

**이 블록은 «분류 판정과 이행 기록»이다. 위 사례 1·규범 1~4·102 블록의 문언은 한 자도 안 바꿨다.**

### 새 국면 — **「갈림은 있는데 «값을 넘기는» 갈림이 0곳」**

규범 1은 소비처를 「**바꿀 것 / 안 바꿀 것**」으로 가르라고 하는데, 이 사례에서는 그 «안 바꾸는»
쪽이 **죽은 입력 · off · 인쇄 전용**이었다. **101(값이 갈린 채 둘 다 살아 있었다)과 다른 상태**다.

```
101 사례 1   정착 물리 3.2mm ↔ 배치 교정 15.0mm — **둘 다 «살아서» 다른 값을 쓴다**(차 11.8mm)
105 폭 판본  ㉮ 27.50cm ↔ ㉯ 55.00cm(반폭 환산 **27.50cm** · **항등 상태**) —
             갈리는 6곳이 **전부 죽었거나 꺼졌거나 인쇄**다
```

**규범 승격 0 · 문언 수정 0 · 문턱 0 · 신설 0.** 「갈림을 셀 때 «값을 넘기는가»를 함께 적는다」를
규범으로 올릴지는 **사례 1건**이고 105는 판정하지 않았다(102 「승격 보류」와 같은 처리 — **자리만 남긴다**).

**기전 귀속 0**: 이 블록은 「104 throw의 원인이 폭 갈림이 아니다」를 말하지 않는다.
