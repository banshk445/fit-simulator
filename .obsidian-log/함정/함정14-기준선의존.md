# 함정 14 — 기준선이 결함에 의존하면 마진 게이트가 그 결함을 동결

Stage 1a에서 발견: 기준선의 top-front 커버리지가 BVH 면 법선의 기하 편향(29°)에 의존하고 있었음.
∠(∇d, 기하방향) 4.1° vs ∠(∇d, BVH법선) 29° — 어긋난 쪽이 BVH인데, 그 어긋남이 커버리지를 만들고 있었음.

부호를 고쳐서 "더 옳은" 방향으로 밀면 오히려 기준선 대비 마진 게이트에서 짐.

**규범: 결함 수정 실험의 게이트에는 기준선-상대 마진 외에 절대 채널(화면·오라클)을 반드시 병행.**

"보조 힘은 결핍된 물리의 대체품" 패턴의 게이트 층위 버전.
→ [[보조힘은-대체품]]

## 경계선 — **이 함정이 금지하는 것과 금지하지 않는 것** (60회차 등재)

59회차는 접음단 폭 `w`를 **"스윕해서 좋은 값 채택 = 함정 14 정면"**으로 읽고
후보 4종을 전량 제외했다. 전략 세션이 그 경계를 다음으로 확정했다:

```
금지     **결과에 맞춰 값을 옮기는 것**(스윕 후 좋은 값 채택 · 실패 뒤 값 조정)
비금지   **문헌·설비 대표값의 사전 고정 채택** — 기존 재단 손 상수 5종
         (NECKLINE_EASE_M · FRONT_NECK_EXTRA_M · ARMHOLE_DEPTH_EASE_M ·
          SLEEVE_CAP_EASE_M · ARMHOLE_ARM_CLEARANCE_M)과 **같은 계열**이면 허용
조건     ① `w`를 **사전 고정**한다  ② 결과가 나쁘면 **값을 바꾸지 말고 실패로 기록**한다
```

**함정 14의 본질은 결과에 맞춘 값 이동이지 대표값 채택이 아니다.**
조건 ②를 어기는 순간(값을 재조정하는 순간) 다시 이 함정 안이다.

### 적용 3건째 — **조건 ①② 이행 · 열거 «미추가» 판정** (104회차 자체 판정 · 위 열거 5종 **수정 0**)

104회차가 **몸통 폭 여유 `WIDTH_EASE_M`**을 이 경계선에 걸어 집행했다.
**두 조건을 모두 이행했고, 그럼에도 열거 5종에는 넣지 않는다.**

```
조건 ① 사전 고정        **이행** — `WIDTH_EASE_M = 0.030 m(3cm)`을 **실행 «전»에** 확정했고
                      출처를 명시했다(`patternDraft.ts:49 ARMHOLE_DEPTH_EASE_M = 0.030`
                      「티셔츠 진동 여유 3cm」 · **같은 파일·같은 옷·같은 계열** · **새 손 상수 0**)
조건 ② 나쁘면 값을      **이행** — 결과는 **사전등록 갈래 C(실패)**였고(배치 단계 throw ·
       바꾸지 말고            34게이트 위반) **e 조정 0 · 재시도 0 · 값 스윕 0**으로
       실패로 기록            **원복하고 정지**했다. 다른 e 값은 **시도하지 않았다**
```

**그런데 열거에는 넣지 않는다(판정 · 근거 3건)**

```
① 열거 5종은 **채택돼 코드에 살아 있는 재단 여유 상수**의 목록이다.
   앞선 두 적용(60회차 접음단 `w` · 71회차 상속 10건)도 **채택**으로 끝났다.
   폭 여유의 문헌 계열값 **3cm는 채택되지 않았다** — 실패하고 **원복**됐다
② 원복 뒤 코드에 남은 `WIDTH_EASE_M` 값은 **항등 역산값 6.497769876168244cm**이고
   이는 **문헌·설비 대표값이 아니라** 기존 손 상수(`garmentSize.width 55`)의 **재표현**이다
   (기존 값과 **비트 동일**이 성립 조건이었다). 열거에 넣으면 그 값이 **대표값 채택인 것처럼
   읽힌다**
③ **조건 ①② 이행은 «준수 기록»이지 «계열» 편입의 근거가 아니다** — 열거는
   「어떤 계열이면 사전 고정 채택이 허용되는가」의 **정의**이지 준수 목록이 아니다
```

**상태 표기(정확히)**: 폭 여유 = **「채택 대기」**. 열거 **미추가** ·
**조건 ①② 이행 실증 1건 보유** · **채택된 대표값 0건**.
**재개 = 폭 여유의 문헌·설비 대표값이 «채택»돼 코드에 남는 회차**가 열거 추가를 판정한다.

**처분: 열거 문언 수정 0 · 조건 ①② 문언 수정 0 · 문턱 0 · 신설 0 · 이행 기록만 등재.**

## 사례 — **21회차 브리지 색 `#6b7f8c` 선정** (75회차 등재)

**기준선이 결함에 의존한 것이 아니라, 값이 기준선에 맞춰 골라진 형태다.**
21회차는 브리지 색을 **체커 텍스처 위에서** 골랐다 — 주석이 그 사유를 적고 있다
(「채도가 높아 천보다 먼저 눈에 들어왔다」 → 저채도 회청으로 낮춤).
**그 기준선(체커)이 실물 원단으로 바뀌자 같은 값이 화면 최대 결함이 됐다.**

```
색거리  브리지 ↔ 체커 평균  **81.9**
        브리지 ↔ 원단      **164.2**  → **2.0배**
밝기    회청 띠 117.9 vs 원단 3.07     → 약 **38배**   (71회차 화면 실측)
```

**체커에서 고른 값이 원단에서 틀린 이유는 값이 나빠서가 아니라
기준선이 바뀌었기 때문이다** — 문헌·설비 대표값이 아니라 **그때의 화면에 맞춘 값**이라
기준선과 함께 유효기간이 끝난다.

**해소(75회차)**: 리터럴을 **도출값**으로 대체했다 —
`color={composited ? composited.solid : "#6b7f8c"}`
(`composited.solid` = 합성 캔버스 (0,0) 픽셀 = **원단 대표색** · v1과 같은 출처).
**손 상수 신규 0 · 순증감 −1**(무업로드 폴백 분기에는 21회차 값이 남는다).
