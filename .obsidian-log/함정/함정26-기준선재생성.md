# 함정 26 — **기준선을 값으로만 들고 다녔다**. 그 값을 **다시 내는 명령(env)** 이 어디에도 없었다

> **재작성 고지(82회차)**: 이 노트의 81회차 판본은 기전을 「**런타임 드리프트 + 버전
> 기록 부재**」로 적었다. **그것은 틀렸다.** 82회차가 원인을 `RINGTOTAL=0` env 누락으로
> 확정했고 런타임 후보를 반증했다. **오진 자체가 이 함정의 2차 증상**이므로 아래
> §「2차 증상」에 남겨 둔다. → [[../회차/2b-82-런타임포렌식]] · [[../회차/2b-81-기준선재계산]]

## 기전 (82회차 확정)

```
기준선을 **값**으로만 들고 다녔다. 그 값을 **다시 내는 명령**(env 포함)이
로그에도 노트에도 어디에도 없었다.
→ 재현 실패 시 무엇이 달라졌는지 대조할 축이 없어, 코드·입력·의존성을 배제한 끝에
  **관측 불가능한 후보(런타임)로 잘못 수렴**했다.
```

**결정적 증거**: 같은 날 **13:52 실행(`r80.log` · `RINGTOTAL=0`)이 기준선 A를 냈고,
14:25 실행(`RINGTOTAL` 누락)이 1917을 냈다.** 코드도 런타임도 동일하다.
차이는 **명령줄 한 토막**이었고, 그 토막은 **로그에도 노트에도 인쇄되지 않았다.**

`RINGTOTAL`은 출력 스위치가 아니라 **물리 제약**이다(링 총길이 상한 ·
`scripts/dressPattern.ts:611`). CLAUDE.md **§실행**이 「목선 진단의 표준 기준선은
`RINGTOTAL=0`」이라고 명시한 그 스위치다.

## 사례 (81회차) — 「기준선 A가 오늘 재현되지 않는다」

`v2-2b-78-baseline`(9fbd66c)은 **태그로 고정**돼 있었고 태그 메시지에 patternHash ·
fixture · dress-state md5 · A 17채널 전량이 적혀 있었다. 그런데 그 태그를 임시 워크트리로
체크아웃해 실행해도 값이 달랐다.

```
채널        등재 기준선 → 81회차 실행(env 누락) → 82회차 실행(RINGTOTAL=0)
cov 몸통     118 → 119  → **118**
covShoulder  637 → 632  → **637**
자기교차     1889 → 1917 → **1889**
maxStrain    2.661 → 2.463 → **2.661**  (argmax 2146 동일)
관통②        50 → 51    → **50**
dress-state md5  14e50b89… → a20ff9e3… → **14e50b89…**
```

**82회차 3회 연속 비트 재현. 기준선 A는 살아 있다.**

### 반쪽 ① — **아무도 다시 내보지 않았다**

60 · 71 · 75 · 78 · 80회차가 「**A 17채널 비트 대조 전부 불변**」을 반복 등재했다.
그 실행들은 **각자 그 시점의 값끼리 비교한 항등 비교**였다.

```
주장 형태   "이번 실행이 기준선과 비트 동일하다"
실제 형태   "이번 실행의 전/후가 서로 비트 동일하다"
→ 둘은 다르다. 앞의 문장으로 적히면 **기준선이 검증됐다고 읽힌다**
```

*(82회차 보강: 그 다섯 회차의 실행 명령은 실제로 **전부 `RINGTOTAL=0 PATTERNCORE=1`**
이었고 전부 1889를 냈다 — 세션 트랜스크립트에서 확인됐다. 즉 값 자체는 옳았다.
문제는 **그 명령이 볼트에 없었다**는 것이다.)*

### 반쪽 ② — **다시 내는 데 필요한 것을 안 적었다**

노트·로그 어디에도 **실행 명령 전량(env 포함)** 이 없다. 그래서 재현이 깨진 날
「무엇이 달라졌나」를 대조할 축이 없었고, 격리는 저장소 안(코드·입력·의존성)을
배제한 뒤 **저장소 밖의 관측 불가능한 후보**로 밀려났다.

## 2차 증상 — **오진**: 대조가 아무것도 증명하지 않았다

81회차는 태그 워크트리 체크아웃 실행이 HEAD 실행과 **같은 값**을 낸 것을
「**코드 무관**」의 증거로 읽었다. 실제로는 **두 실행이 같은 누락을 공유**한 것이었다.

```
통제했다고 믿은 변수가 양쪽에 똑같이 오염돼 있으면, 대조는 아무것도 증명하지 않는다.
```

그 결과 원인 후보가 코드 → 입력 → 비결정성 → 의존성 순으로 지워지고
**관측 불가능한 런타임(V8)만 남아** 「원인 미확정 · 정지」로 마감됐다.
82회차 포렌식(npm 로그 · Homebrew 수령증 · 세션 트랜스크립트 · shell history)에서
**node는 7/29에 이미 v25.9.0이었고 업그레이드 이력이 없다**는 것이 확인돼 후보는 반증됐다.

**유형 구분**: 이것은 **계기 정의역**이 틀린 유형([[함정13-jitter]] 계열)이 아니라
**실행 구성**이 틀린 유형이다. 계기는 정상이었고 사람이 다른 구성을 실행했다.

## [[함정08-fixture표류]]와의 관계 — **축이 다르다**

```
함정 08   **입력 파일**이 조용히 바뀐다(fixture · 패턴 메타) → 처방 = 커밋 고정 + 해시 병기
함정 26   **실행 구성**(env)이 조용히 달라진다 — 입력 파일도 코드도 그대로인데 산출이 바뀐다
```

81회차 시점에 함정 8의 처방은 **전부 이행돼 있었다**(태그 · 해시 3종 · fixture 해시).
**그런데도 발생했다** — 고정 범위가 **파일**까지였고 **명령줄**은 포함하지 않았다.

## 처방 — **계기가 스스로 환경을 인쇄한다. 노트 규율에 맡기지 않는다**

82회차 §2 집행분(`scripts/dressPattern.ts:222` · 판정 로직 0줄):

```
줄1  node · v8 · platform/arch · three · three-mesh-bvh
줄2  env 20개 전량 — **미설정도 `미설정`으로 인쇄**(이번 사고는 「안 찍힌 것」이 원인이었다)
줄3  pattern/fixture 해시 + 「재현하려면 위 env 줄을 그대로 쓴다」
```

`existsSync(META_PATH)` **밖**에 둬서 메타 파일 유무와 무관하게 항상 찍힌다.
`src/lib/*.ts`에 `process.env` 참조 0건이라 **스탬프 1곳이 전 구성을 덮는다.**

## 규범

- **기준선은 절차다.** 등재할 때 **재생성 명령 한 줄**을 값과 함께 적는다.
  캠페인 기준선 A = `RINGTOTAL=0 PATTERNCORE=1 npm run dress:pattern`.
- **환경 스탬프 줄을 로그에서 인용해 적는다. 값만 옮겨 적지 않는다**
  (→ [[../규칙/기점대조]]).
- **「기준선과 비트 동일」을 적으려면 기준선을 그 회차에 실제로 다시 내야 한다.**
  전/후 항등 비교만 했으면 **그렇게 적는다** — 두 문장은 다르다.
- **해시는 파일 상태가 아니라 재생성해서 대조한다.** 유효한 조항이다 — 이번에
  dress-state md5가 `a20ff9e3…` ↔ `14e50b89…`로 갈린 것이 유일한 신호였다.
  **다만 그 채널은 「무엇이 다른지」를 못 짚는다** — 그래서 env 스탬프가 필요하다.
- **대조 실험을 근거로 쓰기 전에, 통제했다고 믿은 변수가 양쪽에 같은 방식으로
  오염돼 있지 않은지 확인한다.**
- 재현이 깨지면 **그 자리에서 정지한다.** 흔들린 기준선 위의 추가 측정은 대조 기반이
  없고, 그때 나온 부호 역전은 처방의 효과와 분리되지 않는다(81회차 §4-6의 역전 4건은
  82회차에 **아티팩트로 확정**됐다 — 열①②③이 45·43 대조쌍이 아니었다).
