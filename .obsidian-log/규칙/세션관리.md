# 세션 관리 규칙

## 기본 구조
- 이 채팅(전략 채팅) = 판단·프롬프트 작성
- 개발 CC 세션 = 코드 구현
- 리뷰 CC 세션 = 머지 전 검토
- 사용자가 CC 보고를 이 채팅에 붙여넣고 판정받아, 다시 CC에 프롬프트를 붙여넣는 루프

## 브랜치 공유 사고 (2b-07 직후 발각)
`v2-stage2a`를 두 CC 세션이 동시에 push하고 있었음 — 회차 번호·전제가 조용히 갈라짐.
"기록에 없는 수치" 경보로 발각, 정정 완료. 피해는 없었으나 재발 방지 규칙 신설:

> **한 브랜치 = 한 세션.** 병행하려면 브랜치를 분리한다.
> CC 보고 서두에 `git log -1 --oneline` + 워크트리 경로 스탬프를 의무화한다.

## 구버전 프롬프트 재실행 위기 (2b-08 직후)
새 CC 세션에 **이전 턴의 구버전 프롬프트**가 붙어, 이미 완료된 작업(7회차 하드 핀)을
재구현하기 시작. 사용자가 도중 인지·중단해서 피해 없음.

> **프롬프트는 최신 1개만 유효.** 이전 턴 프롬프트 재사용 금지.
> 새 세션 착수 전 `git log`로 "이미 반영된 작업인지" 확인 의무.

## 정직한 인계 (2b-08, 2b-13→14 재개 세션)
세션 컨텍스트가 소진됐을 때, 반쯤 구현해서 t=0을 또 실패시키는 대신
**설계 결함을 정직하게 보고하고 멈추는 편**을 두 번 선택함 — 옳은 판단으로 승인됨.

> **대형 재작성은 t=0 통과 시점에 커밋·체크포인트 보고 허용.**
> 물리 실행·캡처는 다음 사이클로 분리해도 된다.

## /clear 기준
커밋·기록·푸시로 단위가 닫히고, 다음 단위가 문서+프롬프트만으로 시작 가능할 때.
실험 중간(미커밋 임시 변경 잔존)엔 금지.

## 3연속 규칙
같은 층위의 단일 변경이 3회 연속 실패하면 자동 진행을 멈추고 외부(전략 채팅) 판단을 받는다.
- 2b-04~07: 앵커 층위 5연속 → 구조 전환으로 판정
- 2b-13(a,b)+14: 배치 사상 3연속 → 계기 교체로 판정

## 모델 사용
- 상위 모델(Fable) 필요하면 먼저 알릴 것. auto는 Fable로 라우팅 안 함.
- Fable은 Max 주간 한도 50%, 세이프가드 오탐 가끔 있음 → 설계 검토처럼 드문 고가치 작업에만.
