# 기점 대조 — **해시 3종 + 코드 diff 0**. 노트·docs 커밋은 기점을 깨지 않는다

**자리 판단 근거**: 회차 헤더 검수 절차(=실행 규칙)이지 물리·계기 층위의 원리가
아니므로 `원리/`가 아니라 `규칙/`에 둔다. 기존 규칙 3종
([[밑단형상계기-체크리스트]] · [[세션관리]] · [[화면판정]]) 중 어느 것의 하위 항목도
아니라 신설한다.

## 구 정의 — **자기모순** (80회차에서 발현)

```
기점 동일 = HEAD SHA == 태그 SHA
```

**회차 노트를 커밋하는 순간 HEAD가 태그에서 떨어진다.** 즉 회차를 정상적으로
마감하기만 해도 다음 회차의 기점 대조가 반드시 실패한다 — 어떤 회차도 통과할 수
없는 조건이었다([[../원리/사전등록]] 실패 양식 14와 같은 형태 · **전략 세션 귀책**).

실제 발현: [[../회차/2b-80-계기감사및수리]] §1 검수 블록이
「HEAD `bee3c78` ≠ 태그 `9fbd66c` / 차이는 **79회차 노트 커밋 1건뿐**」을 적고
**"실질 기반 동일로 보고 진행"** 으로 우회했다. 우회 자체는 옳았으나 그것이
**정의가 틀렸다는 신호**였다.

## 신 정의 (81회차 §0 + **82회차 §6-4 3항 추가** · 이것이 정본)

```
기점 동일 = ① 해시 3종 일치
              patternHash · fixture · dress-state md5
          + ② `src/` · `scripts/` 코드 파일이 태그 대비 **diff 0**
          + ③ **실행 구성(env) 일치**  ← 82회차 추가

노트 커밋 · docs/ 커밋은 **기점을 깨지 않는다**
```

## 조항 추가 (82회차 §6-4) — **실행 구성(env)을 대조 항목에 넣는다**

```
조항   기점 대조와 회차 실행은 **환경 스탬프 줄을 로그에서 인용**해 적는다.
       **값만 옮겨 적지 않는다.**
```

**근거**: 해시 3종·코드 diff만으로는 **81회차 사고를 못 잡는다.** 81회차는 이 문서의
신 정의를 그대로 이행했고(코드 diff = 계기 수리 2파일 명시 예외 · patternHash·fixture 일치)
**태그 워크트리 체크아웃까지 했는데도** 실행 구성이 기준선과 달랐다 —
`RINGTOTAL=0`이 명령줄에서 빠졌고, 그것을 인쇄하는 채널이 없었다.
`RINGTOTAL`은 출력 스위치가 아니라 **물리 제약**이다(`scripts/dressPattern.ts:611`).

**근거 스탬프**(82회차 §2 집행 · `dressPattern.ts:222` · 판정 로직 0줄 —
줄2는 **미설정도 `미설정`으로 인쇄**한다):

```
[dress] 환경 스탬프: node v25.9.0 · v8 14.1.146.11-node.25 · darwin/arm64 · three 185 · three-mesh-bvh 0.9.10
[dress] env: RINGTOTAL=0 · TORSOCAP=미설정 · SINGLE=미설정 · … · PATTERNCORE=1 · …
[dress] 해시: pattern 9f7ba80b3497 · fixture 9e8b2bf13925 — 재현하려면 위 env 줄을 그대로 쓴다(함정 26)
```

캠페인 기준선 A의 재현 명령: **`RINGTOTAL=0 PATTERNCORE=1 npm run dress:pattern`**
→ [[../회차/2b-82-런타임포렌식]] §4 · [[../함정/함정26-기준선재생성]]

## 조항 추가 (81회차 §5 실측 후) — **해시 3종은 재생성해서 대조한다**

```
금지   파일 상태만 비교하고 「3종 동일」로 통과
필수   dress-state md5는 **하네스를 다시 돌려 나온 파일**로 대조한다
```

**근거**: 81회차에 patternHash · fixture는 **파일 비교로 일치**했으나
dress-state md5는 **재생성해야만 비교가 성립**했고, **불일치가 거기서만 나왔다**
(등재값 `14e50b89…` vs 재생성 `a20ff9e3…`). 파일 상태만 봤으면 **못 잡았다.**

세 해시는 성격이 다르다 — 앞 둘은 **입력**의 해시(파일이 그대로면 같다), 마지막은
**산출**의 해시(같은 입력이 같은 산출을 내는지를 묻는다). 앞 둘의 일치는 뒤 하나의
일치를 **함의하지 않는다**. → [[../함정/함정26-기준선재생성]]

**보강(82회차 · 이 조항은 유효하다)**: 82회차에 dress-state md5가
`a20ff9e3…` → `14e50b89…`로 갈린 것이 **실제로 신호였다** — 코드도 입력도 런타임도
같은데 **산출만 달랐다**는 사실을 가리킨 유일한 채널이다.
**다만 이 채널은 「무엇이 다른지」를 못 짚는다** — 81회차가 그 지점에서 관측 불가능한
후보(런타임)로 수렴했다. 그래서 위 3항(**실행 구성 env**)이 필요하다.

## 예외 — 계기 수리분

**계기 수리분은 `src/`·`scripts/`에 diff가 있음이 정상이다**
(79회차 §8-4 「해시 불변 예외」 등재분).

```
조건   해당 **파일명을 헤더에 명시 예외로 보고**한다
       (해시 3종은 그대로 일치해야 한다)
```
