# 원리 — "근사 곡선을 만들지 말고 몸에서 가져와라"

이 캠페인에서 가장 많이 반복 검증된 원리. 배치 사상에서 매개변수화된 근사 곡선(사분타원,
관계식, x 룩업)을 쓸 때마다 실패했고, 몸의 실측 폐곡선/선분을 직접 참조할 때마다 성공했다.

## 적용 사례 (성공)
1. **코너 8개** ([[../회차/2b-08-구조전환]]) — 목점=ridge(s=0) 등 몸 랜드마크에 직접 사상.
   코너 일치 오차 0.0000mm.
2. **목선** ([[../회차/2b-12-목선호장대응]]) — loopAt(h) 폐곡선 + 호장 비율.
   자기교차 806→0. **첫 완전 성공.**
3. **내부 행 (부분)** ([[../회차/2b-14-높이호장재구성]]) — 사상 자체는 성립(반곡선 1.5% 안)
   했으나 폐곡선 계기(loopAt)가 둘레 측정용이라 정점을 얹기엔 부적합했음.
4. **sliceOutline 계기** ([[../회차/2b-15-sliceOutline]]) — 마지막 미적용 지점.
   근사(껍질/bin 반경) 대신 레이캐스트로 몸 표면을 직접 취득.

## 다음 적용 예정
vN(상단 경계까지의 상대 높이)을 x 기반 함수에서 상단 경계의 **호장 좌표**로.
목점에서 접선이 불연속(4분 타원 끝점 특이점)이라 발생한 자기교차의 원인.

## 일반화된 교훈
"근사"가 실패하는 지점은 대개 **경계 조건**(코너, 극점, 접합부)이다.
경계에서 두 근사가 서로 다른 값을 주면 사이 영역이 접히거나 뒤집힌다.
해법은 항상 같다 — 근사를 개선하지 말고, 경계를 몸에서 직접 읽어 특수해로 만든다.

## 확장 — **「변조 «전» 몸에서」** (v3-84 등재)

원리에 한 줄을 덧댄다: **몸에서 가져오되, «아직 손대지 않은» 몸에서 가져온다.**

v3-84 이전의 `unitScale` 은 몸에서 가져오긴 했다 — 다만 **자기가 이미 배율을 걸어 놓은**
그 몸에서 가져왔다. 두 번째 계산은 1.70 을 재서 몫 1 을 내고 **앞의 적용을 되돌렸고**,
구운 몸 27개가 전부 1.038266배 커졌다(코드 변경 0 · 적재 순서만 달랐다).

처방도 원리 그대로였다 — 재는 대상을 **지오메트리 공간 bbox**(바인드 포즈 · 배율 무관)로
바꾸자 4회 계산이 전부 1.765052 로 고정됐다.

```
 판별 질문: **「이 값을 쓰면 내가 재는 대상이 바뀌는가?」**
   바뀐다면 그 참조는 «몸에서 가져온» 것이 아니라 **자기 출력을 되먹인 것**이다.
```

## 확장 — **「게이트는 «제어하는 양»을 잰다」** (v3-85 등재)

게이트가 **결과**를 재면 문턱이 표본 분포에 묶인다. **제어하는 양**을 재면 안 묶인다.

v3-84 의 ㉰ 는 「구운 몸이 몇 m 인가」(결과)를 쟀고, 문턱을 그 집합의 최대값에서 뽑는 바람에
최대값 자신이 경계에 서서 3칸이 떨어졌다. v3-85 의 ㉰′ 는 **「정규화가 씬에 실렸는가」**
(= 파이프라인이 실제로 «제어하는» 양)를 쟀다:

```
 ㉰′ = |씬 배율 − unitScale_geom| ≤ 1e-4      (문턱은 기존 상수 인용 · 표본값 0)
   결함 없음 ⟹ 27/27 통과 · ㉰′ 최대 **0**
   결함 주입 ⟹ 27/27 실패 · ㉰′ **0.036855** (문턱의 369배)
```

```
 판별 질문: **「이 문턱을 정하려고 판정 대상을 들여다봤는가?」**
   그랬다면 그 게이트는 표본에 묶여 있다. 제어량을 재면 문턱이 «장치»에서 나온다.
```

관련: [[../함정/함정36-판정집합의최대값문턱]] · v3-85 §1-②′


## 확장 — **「제약과 «탐색 경로»를 분리하라」** (v3-88 등재)

v3-88 은 소매 반지름의 **물리적 하한** 하나를 고쳤는데, 그 하한이 **이분 탐색의 브래킷
시작점**을 겸하고 있어 **108칸 중 78칸의 산출물 비트가 바뀌었다**(값 차이는 2.6e-16 ~ 1.7e-14m —
물리적으로 0). 겨눈 것은 7칸이었다.

```
 제약(무엇이 적법한가)과 경로(어떻게 찾는가)는 **다른 역할**이다.
 한 변수가 둘을 겸하면, 제약을 고칠 때마다 **안 겨눈 산출물까지 흔들린다.**
```

판별 질문: **「이 상수를 바꾸면 «답»이 바뀌는가, «찾아가는 길»이 바뀌는가?」**
둘 다면 분리한다 — 하한은 하한대로 두고 브래킷은 따로 잡는다.

### v3-89 — **값으로 증명됐다**

같은 목표를 두 번, 다르게 갔다:

| 판 | 손댄 곳 | 소매 7칸 결과 | 안 겨눈 칸의 비트 |
|---|---|---|---|
| v3-88 | **하한(경로 겸용)** `RMIN` | 4 통과 · 3 bb | **78/101 흔들림**(1e-14m) |
| v3-89 | **제약만**(probe 항 1개) | **4 통과 · 3 bb · 수치 동일** | **100/101 그대로** |

`RMIN` 을 **한 글자도 안 바꿨는데** R 이 `RMIN` 의 **1.0064 ~ 1.0074 배**로 올라섰다 —
**제약이 스스로 답을 민다.** 경로를 밀 필요가 없었다.

```
 **하한을 옮기지 말고 «검사»를 넣어라.** 답은 같고, 안 겨눈 산출물이 안 흔들린다.
```

### RMIN′ 유도식 — **등재만 · 코드 0**(v3-89 §0-1 판정문 조항)

한 바퀴에 분리 거리 하나를 더 벌리려면 둘레가 `2·CAP_W + SEP` 여야 한다:

```
 2πR ≥ 2·CAP_W + SEP   ⟹   **RMIN′ = (2·CAP_W + SEP) / (2π)**
```

`CAP_W` 는 패턴에서 · `SEP = 2·THICK` 는 등재 상수 ⟹ **손 상수 0**.
★ **이 식은 노트에만 있고 코드에는 들어가지 않았다** — v3-88 이 그 자리를 건드려
  안 겨눈 78칸을 흔들었기 때문이다. 제약(probe 항)이 같은 일을 **경로 없이** 한다.
