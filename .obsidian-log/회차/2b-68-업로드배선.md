## §3 처방 (§1 — 무엇을 배선했는가)

**`PatternPreview.tsx` 단일 파일.**
`garmentImage` 구독 → `THREE.TextureLoader`로 로드 → 패널 머티리얼의 `map`.
**null이거나 로드 실패면 기존 체커 폴백**으로 되돌아간다.

**표시 파라미터는 v1을 그대로 따랐다 — 임의 값 0건.**
근거: v1이 쓰는 drei `useTexture` 구현이 `useLoader(TextureLoader, url)` +
`gl.initTexture`뿐이고 **colorSpace · flipY · wrap을 하나도 설정하지 않는다**
(three 기본값 그대로). 따라서 v2가 값을 새로 정하면 v1과 어긋난다.

**ObjectURL은 해제하지 않는다.**

```
저장소 전체 `revokeObjectURL`   **0건** → 해제 위험 없음
소유                            store (v1도 같은 문자열을 쓴다)
여기서 해제하면                  **v1이 깨진다**
텍스처                          교체 · 언마운트 시 `dispose`
```

## §7 UV 겹침 **기록** (T7 실측 근거 · 판정 아님)

예상대로 **4패널이 UV 공간의 같은 영역을 샘플링한다.** 관측 그대로 적는다.

```
img-front   앞판에 512² 이미지가 **통째로 한 장**
            (TL 적 / TR 청 / BL 황 / BR 녹 · 화살표는 가슴 중앙 세로)
            **양 소매에도 같은 이미지의 적색 대역이 반복**
img-back    뒤판에 같은 이미지가 **좌우 반전**(청이 좌상 · 녹이 좌하)
            화살표는 등 중앙 세로 · 소매에는 **회색 패치**(옷 없는 자리)
img-cuff    소맷부리 근방 적 / 황 대역 · ~~**격자 축척이 몸판과 다르다**~~
```

→ **"옷 한 벌에 그림 한 장"이 아니라 "패널마다 같은 그림 한 장씩"이다.**

### **정정(69회차) — 관측 2건 반증 · 1건 유지. 원문 무삭제**

근거: 69회차 §1 사전 반증 실측(`docs/metrics-log.md` 2026-08-06 · 69회차 · metrics 커밋 31c1a19).

```
~~img-cuff 격자 축척이 몸판과 다르다~~   **반증** — 4패널 du/w가 전부 **0.01429/cm**로 동일.
                                       관측된 차이는 **카메라 6.14배**(front 화면 세로 2.498m
                                       vs cuff 0.407m) + 팔 축 31.0° 경사(피치 1.167배).
                                       **UV 몫은 6.5%뿐.** 원 진술에 픽셀·cm 측정치가 없다
~~cuff 겨드랑이 검정 = 미덮개 코너 후보~~ **반증** — 소매 UV 상자 u[0,0.514]×v[0.686,1.0] =
                                       원본 좌상 사분면 + **화살표 왼쪽 날개**.
                                       **테스트 이미지의 화살표이지 구멍이 아니다**
"패널마다 같은 그림 한 장씩"              **유효** — 네 패널 전부 **u=0에서 시작**(패널별 bbox 원점) ·
                                       겹침 6쌍 전부
img-back 좌우 반전                      **원인이 미러링이 아니다** — 미러링 코드가 없다.
                                       front `corr(u,worldX)=+0.980` · back **+0.976**로
                                       둘 다 같은 세계 x 방향이고, back 한 장이 뒤집혀 보이는 건
                                       **카메라가 반대편(pos z=−3)** 이기 때문.
                                       남는 사실 = **UV에 handedness 개념이 없다**
```
