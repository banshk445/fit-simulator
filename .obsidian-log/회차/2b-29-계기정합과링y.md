# 2b-29 — 계기 정합과 링 y 시계열

물리·제약 **0줄**. 신설: 링 y 시계열 계기 + `RINGTOTAL=0` ablation.

## 1. 계기 정합 — rest 불일치 원인 **확정**

```
제약이 쓰는 ringRestM      49.44cm   ← scripts/dressPattern.ts (하네스)
경계 감사 necklineRing 합  48.24cm
제도 necklineGirthM        48.27cm
차이                        1.20cm = 2 × SEAM_REST_LENGTH(0.006) — 정확히 일치
```

원인은 **셋 중 첫째, 시접 포함**이다. 그런데 단순 정의 차이가 아니라 **불정합**이다:

- `ringLenM()`은 `g.necklineRing`만 순회한다 — **접합 2쌍을 안 센다**
- `ringRestM`은 같은 합에 `2 × max(seam.targetM)`을 **더한다**
- → 분자(접합 없음)와 분모(접합 있음)가 **다른 집합**이다. rest가 1.20cm 부풀려져 있다

### 제품 값 확정
**rest = 48.24cm**(= `necklineRing` 합, 제도 48.27과 0.03 이산화 차). `ringLenM()`이
재는 대상과 같은 집합이다. `+2×SEAM_REST_LENGTH`는 하네스가 지어낸 항이고
`ringLenM()`이 세지 않는 길이를 더한다.

### 소급 정정 (전량)
| 회차 | 링 길이 | 기존 배율(rest 49.44) | **정정 배율(rest 48.24)** |
|---|---|---|---|
| 25 봉합 전 최대 | 123.73 | 2.502배 | **2.565배** |
| 25 최종 | 104.54 | 2.114배 | **2.167배** |
| 26·27 최종 | 54.05 | 1.093배 | **1.120배** |
| 26 상한 계수 | 54.05 | 1.093 | **1.120** |

집행에는 영향이 없다 — 총 길이 상한은 `L > ringTotalMaxM`(54.05cm) 절대값 비교라
rest가 안 들어간다. **보고된 배율만 전량 과소**였다.

### 미집행 정정 1건 (물리 영향)
`ringLimitStart = max(COLLAR_STRAIN_LIMIT, ringLenM()/ringRestM)` — 여기엔 rest가
들어간다. 고치면 **물리가 바뀐다**. 이번 회차 금지 사항이라 등재만 한다.

### [[함정12-계기하드코딩]] 사례 추가 — **성립**
`ringRestM`은 제품 코드(`draft.dims.necklineGirthM` / `g.necklineRing`)에서
도출되지 않고 하네스가 상수를 더해 **재구성**했다. 그 결과 같은 이름의 양을 두
계기가 다르게 재고, 4회차 분량의 보고 수치가 전부 어긋났다.
→ 규범: **계기가 쓰는 rest는 제약이 순회하는 집합에서 직접 뜬다.**

## 2. 링 y 시계열

`RINGTOTAL=0`이 25회차를 **비트 재현**한다(f=260 · 링 104.54 · 축소 일량 0.00).

기준선: 목밑점 y **145.23** · 어깨 능선 최상단 y **147.95** · 어깨 관절 y **137.54**

| | 25회차(상한 없음) | 26회차(상한 on) |
|---|---|---|
| 링 **최상점** 시작 | 145.12 | 143.29 |
| 링 최상점 최종 | 141.55 | **141.24** |
| 낙차 | 3.57cm | 2.05cm |
| 목밑점 대비 | −3.68cm | −3.98cm |
| 어깨 관절 대비 | +4.01cm | +3.71cm |
| 링 길이 | 104.54 | 54.05 |

**중심 y는 판정에 못 쓴다** — 목선이 곡선이라 배치 시점부터 중심이 목점보다
앞목 9.12 / 뒤목 5.19만큼 아래다(f1 중심 139.54). 최상점이 "미끄러졌는가"의
채널이다. 계기 신설 직후 이 정의 결함을 잡아 최상점·최하점을 함께 남기게 했다.

### 자유 평형 대조 (정식 채널 등재)
```
링 자유 평형(상한 없음) 104.54cm
어깨 통과 둘레          107.00cm @ y137.54 단면 (= body.shoulderPassGirthM,
                        2a 통과 조건이 쓰는 그 값. 어깨 관절 높이 단면이다)
링/어깨통과             0.977배
```
사용자 추정 ≈90.8cm은 실측과 다르다 — 자유 평형은 **어깨 통과 둘레 바로 아래**다.

## 3. 사전 등록 판정 → **분기 ⓑ**

> ⓑ 링 y는 거의 안 내려갔는데 둘레만 벌어졌다 → 미끄럼 아님. 목선 대역 인장 /
> 하중 경로로 이동

결정적 근거는 ablation 대조다: **링 둘레를 104.54 → 54.05로 절반 가까이 조여도
링 최상점은 0.31cm밖에 안 움직인다**(141.55 → 141.24). 링 y가 둘레의 함수가
아니다 → "미끄러져 내려가 굵은 단면에 걸렸다"는 기전은 **배제**된다.

**분기 ⓐ와의 문구 충돌은 있었다.** 링 최상점은 목밑점보다 3.7~4.0cm 아래에
앉는다(ⓐ의 "목밑점 아래"에 해당). 그러나 ⓐ가 전제한 건 *내려가서* 그렇게
됐다는 것이고, 실측은 낙차 2.05~3.57cm에 위치가 둘레와 무관하다. 문구가 아니라
기전으로 가른다 → ⓑ.

27회차 strain 지도(상위 11이 전부 목선 대역 안쪽)와 정합한다.

### 부수 실측 1건 — 26회차 상한의 대가
26회차 상한은 f1부터 발화해 **배치 직후 최상점을 1.83cm 끌어내린다**(145.12 →
143.29). 중심 기준 등방 축소라 최상점이 중심 쪽으로 내려오기 때문이다. 최종도
25회차보다 **0.31cm 더 낮다**. [[2b-26-링총길이상한]]의 V1 통과 → 실패 정정과 정합.

**이번 회차 처방 집행 없음**(사전 등록대로).

## 정정 (30회차) — 0.977배는 사실이나 기전이 아니다
"링 104.54 vs 어깨 통과 둘레 107.00 = 0.977배"는 **수치로는 참**이지만 기전이
아니다. 이 회차가 이미 한 번 흔들었고(둘레를 절반으로 조여도 최상점 0.31cm),
30회차가 두 번째로 흔들었다 — 중력 0에서 링이 앉는 높이의 몸 단면은 **63.95cm**,
링은 101.56cm = **1.588배**. 몸이 안에 꽉 차서 멈춘 게 아니다.
**"어깨에 걸렸다" 가설 기각.** 일치하는 숫자를 기전으로 승격시킨 사례로
[[함정16-수치근접]]에 등재했다.
