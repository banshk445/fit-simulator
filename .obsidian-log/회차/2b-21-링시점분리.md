# 2b-21 — 링 원주 제약의 시점 분리

## 변경 (변수 하나 · 새 상수 0)
넥밴드는 **봉제 완료된 옷의 부품**이다. 착장 중 유지력은 하드 핀이 담당하고
(잔차 0.00mm 실증) 링이 조여 있을 이유가 없다. [[2b-03-링스케줄]]의 완전판.
```
봉합 완료 전 : 링 **전용** 상한 해제 → limitStrain의 전 제약 상한에 위임
               (완전 off 아님 — 1.2를 다시 적으면 [[함정12-계기하드코딩]])
봉합 완료 판정: S1→S2 전이식 그대로 재사용 (gap ≤ target + seamSlack = 16mm)
완료 후      : 실측 신장 → 1.02로 smoothstep 램프(길이 = 기존 rampFrames)
```

## 결과 — **20회차 정체는 해소됐다**
```
[링·시점분리] f=110 **봉합 완료 판정** → 램프 시작 2.2556 → 1.02
f=171 정체(24.9mm) → RETRY1 · f=238(29.0mm) → RETRY2 · f=307 **ABORT**(28.1mm)
넥밴드 발화 58.9 → **33.6/프레임**
링 원주 봉합 전 최대 **129.50cm** → 최종 101.26cm (rest 48.24)
maxStrain 6.167 · cov 몸통 10.5% · 경과 23.6s
```
20회차까지 27.8mm에서 꿈쩍 않던 seamGap이 **f=110에 16mm 아래로 내려갔다** —
[[2b-20-앵커목표상향]]의 진단(병목 = 넥밴드 원주 상한)이 **직접 확인**됐다.

## 국소화 — 실패는 기전이 아니라 **전이 타이밍**
`dressingMachine`의 S1→S2는 **and** 조건이다:
```
stateFrame >= rampFrames(120)   AND   gap <= target + seamSlack(16mm)
```
f=110에 두 번째는 만족했는데 첫 번째가 아직이었다. 그런데 램프를 **완료 판정
시점(f=110)부터** 시작해 링이 조이자 갭이 24.9mm로 **되열렸다**. **10프레임 차.**

부작용: 링 전용 상한을 풀자 링이 **129.50cm(rest의 2.68배)**까지 부풀었다.
`limitStrain`의 **제약당** 1.2배 상한은 **총 길이를 못 막는다**(누적된다).

## 판정 (전략층)
세 회차 연속 병목이 한 칸씩 앞으로 옮겨갔다: 승모근 교착(19) → 앵커 목표 도달
불가(20) → 넥밴드 상한(21). 이번엔 **기전이 실제로 풀렸고** 남은 건 스케줄
타이밍이다. 다음 수는 1줄짜리다.

## 정정 (34회차) — 원문은 위에 그대로 둔다
[[2b-32-t0정합지도]] §3이 이 회차의 전제("착장 중 유지력은 하드 핀이 담당")를
**소멸**로 판정했으나, 34회차가 그 **소멸 판정을 취소**한다.
하드 핀은 반납되지 않았다 — `anchors: () => []`는 소프트 경로(`applyAnchors`)만 껐고
`setAnchorHard` → `sim.pin` 경로는 살아 있으며 S1 봉합 전 구간(f=0~110) 내내 활성이다
(34회차 `[pin·검증]` f=60 pinned=1 · f=120 pinned=0 · 앵커 36개). **전제 유효.**

단 근거로 쓴 "**(잔차 0.00mm 실증)**"은 34회차 램프 도입으로 **무효**다 —
f=60 잔차 **105.65mm**(램프 s=0.488), f=120 잔차 79.84mm. 전제는 살아 있으나
근거 강도는 낮아졌다. → [[함정17-반납된전제]] · [[2b-34-핀rest처방]]
