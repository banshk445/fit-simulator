## §5 후보 **E** — 넥라벨 분리

### 계기 교정 1건 (먼저)

**71회차 판별자의 `328×423px @(243,47)`은 원본 좌표가 아니라 crop 산출물 좌표다**

crop을 재현하니 대표색 rgb(30.49, 28.39, 33.79) = **브라우저 실측과 일치**하고
단일 bbox도 `243,47,328×423`으로 **정확히 같다** → 아래 성분 분석은
**계기가 실제로 보는 격자 위**에서 이뤄졌다.

→ **[[2b-71-프린트합성]] §7에 좌표계 정정 블록을 넣었다**(원문 무삭제).

### 성분 분석

```
마스크 화소 1,076(128×128 격자) · 8-연결 성분 **21개**
  857 (79.6%)  crop bbox 243,167,243×266   ← 곰 그래픽 본체
   68 ( 6.3%)  crop bbox 305, 47,124× 47   ← **넥라벨**
  나머지 19개 = 151 (14.0%) — 전부 y 235~465 · 프린트 부속(기타 · 물감 · 하단 문구)
4-연결이면 성분 57개 · 최대 691 · bbox h 266 → **193으로 더 잘린다**
빈 행 구간  단 1곳: 128칸 중 14칸(crop 73px) · 라벨(행 9..17)과 프린트(행 32..89) 사이
```

### 「최대 성분만」 — 손 상수 0이지만 프린트를 잘라먹는다

```
밖으로 나가는 마스크   **15.0%**(151화소 · 19성분)
bbox 면적            정답 대비 **65%**(243×266 vs 328×303)
화면 효과            destH 233.4 → **167.2px**
```

**연결도 4 vs 8이 선택인데 저장소에 도출 근거가 없고 결과를 바꾼다**(h 266 vs 193).

### 문턱이 필요한 대안 — **실측으로 걸러졌다**

```
성분 크기 문턱     **불가** — 라벨(68) > 프린트 부속 최대(28)
                  → **크기 순서가 둘을 못 가른다**
기존 상수 재사용   BORDER_BAND_FRACTION 0.08 = crop 높이 668의 53px인데
                  라벨 bbox가 y 47..94 → **띠를 벗어난다** → 「띠 안에 완전히 든
                  성분 제외」 **불발**
최대 y-공백 분할   **문턱 없이 분리되고 정답 bbox를 낸다**(243,167,328×303).
                  단 **표본 n=1**이고, 세로로 벌어진 프린트(가슴 로고 + 밑단 문구)에서는
                  **프린트를 가른다**
```

「상단 N% 제외」는 crop 결과에 상대적이라 값이 자산마다 이동한다(이번 자산에서 라벨은
crop 높이의 7.0~14.1%). 색·채도로 가르는 경로는 **새 경계값**을 만든다.
