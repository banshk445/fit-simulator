# 2b-33 — 배치 rest 정합 (용의자 확정)

## 1. 용의자 확정 → **(a) 아니고 (b)도 아니다 — 배치가 아니라 S0의 하드 핀이다**

`place()`는 무죄다. 몸판 사상은 앞뒤가 **완전히 같은 코드**를 탄다:
```ts
const p = mapTorso(panel, pos2[gi*2], pos2[gi*2+1], offsetScale);
// x = centerX + xp · y = topY − clamp(yp) · z = centerZ ± torsoOffset
```
평면 등거리 사상이라 패널 내부 3D 거리 = 2D 거리다. 뒤판 신장총 0.0cm가 그
증거다 — **같은 기계가 뒤판에서 완벽하다.**

### 범인: `setAnchorHard(true)` → `sim.pin(a.i, a.x, a.y, a.z)`
```ts
const setAnchorHard = (hard: boolean): void => {
  ...
  for (const a of anchorList) {
    if (hard) sim.pin(a.i, a.x, a.y, a.z);   // ← 좌표를 앵커 목표로 **덮어쓴다**
```
`anchorList`의 목표는 20회차가 올린 **어깨 능선 표면 + `COLLISION_MARGIN`**이고,
대상은 "어깨 시접 **앞판** 쪽 정점 38개"다. 앞판만, 어깨선 대역만 — 32회차
지도의 결함 분포와 정확히 일치한다.

**rest 길이를 보존하지 않는 정점 이동이 일어나는 지점은 여기다.** `sim.pin`은
한 정점의 좌표를 목표로 순간이동시키고 그 정점이 속한 엣지의 rest는 건드리지
않는다. 그래서 이웃 엣지가 저장 신장을 떠안는다. 실측 해부:
```
#1120[앞] 2D(−21.70, 2.59) → 3D(−18.51, 143.38, **−2.65**)   ← 능선으로 끌려갔다
#1329[앞] 2D(−21.73, 3.25) → 3D(−21.73, 142.86, **17.07**)   ← 앞판면 그대로
rest 6.64mm · 2D 거리 6.64mm · **3D 거리 199.80mm (30.1배)**
배치 상수: 앞판면 z 17.07 · 뒤판면 z −13.98 · centerZ −2.79
```
#1120의 z(−2.65)는 **어느 패널면도 아니고 몸 중심면**이다. 평면 배치가 만들 수
없는 좌표다.

### 왜 "앵커 off"인데 걸리는가
`anchors: () => (PINDRESS ? anchorList : [])`가 끄는 것은 **소프트 앵커
경로**(`applyAnchors`)뿐이다. **하드 핀 경로(`setAnchorHard`)는 별개로 살아 있고**
상태기계가 S0/S1에서 부른다. 즉 "앵커 층위 4연속 실패로 소진 → 기본 off"라는
반납이 **절반만** 이뤄졌다. → 아래 함정 ①의 정확한 재발 사례다.

## 2~4. 처방·게이트·실행 — **미집행**
용의자 확정까지 하고 컨텍스트가 소진됐다. 처방(`sim.pin` 대신 rest 보존 이동),
배치 자기검사 게이트, RINGTOTAL=0 실행·대조표·5뷰 캡처는 **하나도 실행하지
않았다.** 다음 회차로 그대로 넘긴다 — 확정된 지점이 있으므로 선행 조사 없이
바로 착수 가능하다.

### 다음 회차가 쓸 재료
- 참조 구현은 **뒤판 경로**: 하드 핀이 안 걸리는 패널이 신장총 0.0을 낸다
- 처방 방향: 앵커 목표로 정점을 **옮기지 말고**, 그 정점을 목표 쪽으로 당기는
  힘을 주거나(소프트), 옮긴 만큼 이웃 rest를 재산출하거나(정합 유지), 애초에
  하드 핀 자체를 반납한다(20·24회차가 이미 앵커 층위를 소진 판정했다)
- 게이트 문턱은 **뒤판 실측에서 도출**: 신장총 0.0 · 최대 1.000. 이산화 오차
  허용분만 별도 명명. (결과에 맞춘 문턱이 아니라 **같은 기계가 이미 달성한**
  수준이다 — 이 구분을 주석에 명기할 것)

## 5. 등재만 (구현 금지)
- **소매 균일 신장 1.108** — 전 소매 엣지 **중앙값** 11% 신장(앞판의 국소·계통
  결함과 달리 전역·균일). 배치 반경/스케일 불일치 후보(`sleeveRadiusM +
  COLLISION_MARGIN` vs `wrapShrink`). V2 개더·V3 겨드랑이 들뜸과 연결 가능성 있음
- **목선 제약 S1 배선** — 21회차 전제(하드 핀·앵커)가 전량 반납돼 근거 소멸.
  재배선은 살아 있는 후보이나 이번 변수 아님. 단 33회차가 발견한 것 —
  **하드 핀은 실제로는 반납되지 않았다.** 21회차 전제의 소멸 여부 자체를
  다시 판정해야 한다

## 정정 (34회차) — 원문은 위에 그대로 둔다
- §1의 앵커 개수 "어깨 시접 **앞판** 쪽 정점 ~~38개~~" → **36개**. 어깨 시접 38쌍 중
  링 정점 2쌍이 제외된다(24회차 배선). 34회차 `[pin·검증]` 실측 = 앵커 36개.
- §2~4 "미집행"은 **34회차가 집행 완료**했다 — 처방 (B) 위치 램프 + 34게이트 신설 +
  RINGTOTAL=0 실행 + 5뷰 캡처. 결과는 갈래 ②(링 최종 배율 불변).
- §1의 용의자 지목("`sim.pin`이 rest를 찢는다") 자체는 34게이트 (i)/(ii) 비트 동일로
  **처방 후 해소 확인**. 다만 그것이 링 신장의 원인이라는 32회차 귀속은 무효다.
