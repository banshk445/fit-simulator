## §4 규명된 것 1건 — **`img.decode()`가 영영 settle되지 않는다** (**유효**)

```
실측  await img.decode()  →  **8초 타임아웃**(Promise.race)
      같은 시점 img.naturalWidth = 723  (= 로드는 이미 끝났다)
```

탭이 백그라운드일 때 Chrome이 decode를 정지시키는 것으로 보인다.
그리고 **71회차 구현이 v1과 갈려 있었다** —
v1은 `Garment.tsx:336`에서 **`.catch(() => {})`로 디코드를 기다리지 않고 진행한다.**

→ 진행 조건을 **로드 완료**(`complete && naturalWidth > 0` 또는 `onload`)로 바꾸고
decode는 시도만 하게 정정했다. **새 상수 0**(타임아웃 값을 두지 않았다).

**이 실측과 정정은 74회차 이후에도 유효하고 되돌리지 않는다.**

### 당시 「규명 안 된 것」 — 두 번째 원인 (74회차에 소멸)

decode 정정 후에도 화면이 안 바뀐다고 봤다. 당시 좁혀진 사실:

```
합성 함수 자체는 정상   수동 호출 36ms · 512×512 · 대표색 rgb(30,28,33) · 문턱 미발동
소스는 최신            서빙본에 `73회차 정정`·`합성 실패 → 체커 폴백` 문자열 존재
store는 갱신됨          garmentImage가 업로드마다 새 blob URL로 바뀐다
FitCanvas는 재렌더됨    경고가 업로드마다 4회 찍힌다
**PatternPreview의 합성 effect는 로그를 하나도 안 낸다** — 판별자도, 실패 warn도
```

즉 **effect 본문이 실행되지 않는다**고 읽었다(`React.lazy` + Vite HMR / 구독 단절 —
**가리지 못했다**). dev 서버 재시작으로도 안 바뀌었으므로 모듈 그래프 stale 가설은 약해졌다.

> **정정(74회차)**: **「decode 정정이 화면을 못 고쳤다」는 진술이 근거를 잃는다** —
> 화면은 실제로 합성되어 있었다. 로그 부재는 **버퍼 설치 시점** 문제였다(74회차 §6). → §6

## §6 **정정(74회차) — 원문 무삭제 · 무엇이 무효이고 무엇이 유효인가**

74회차가 브라우저 복구 후 같은 상태를 재촬영해 **이미지를 열어 확인**한 결과,
**합성은 정상 작동하고 있었다**(`docs/captures/2b-74-verify/front-composited.png`
md5 `435a7f64…` — 검정 원단 + 가슴 프린트 + 소매 단색으로 **71회차와 같다**).

```
유효   `img.decode()`가 백그라운드 탭에서 settle되지 않는다(8초 타임아웃 · naturalWidth 723)
       그 구현이 v1과 갈려 있었다(v1 `Garment.tsx:336` `.catch`로 대기 안 함) → **정정은 옳다**
무효   「합성이 화면에 안 붙는다」 · 「5회 시도 전부 실패」 · 「원인 미규명 2번째」
       → **관측 자체가 무효였다.** decode 정정이 화면을 못 고쳤다는 진술도 근거를 잃는다
유지   §5 변경 2건(실패 경로 인쇄 · decode 대기 제거)은 **되돌리지 않는다** —
       둘 다 독립적으로 옳고 v1 정합이다(74회차 §4 지시와 같다)
```

**왜 틀렸나**: 73회차는 「가슴 평균 rgb → 체커/원단」을 **자동 판정 스크립트**로 돌렸고,
그 표본은 `screencapture`가 담은 **Chrome 창이 없거나 뒤에 있을 때의 화면**이었다.
**69·71회차가 규칙에 넣어둔 「촬영 후 이미지를 열어 대상을 확인한다」를
자동화로 대체하면서 스스로 어긴 것**이다. **md5·픽셀 통계는 오염을 못 잡는다.**
