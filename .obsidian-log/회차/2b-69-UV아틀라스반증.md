## §5 **전략 세션 화면 판정 정정 — 3건 중 2건 + 부수 1건 반증** (이번 회차 최대 산출)

§0이 등재한 UV 결함 3건 중 **①③이 반증**되고 **②만 남는다.**

### ① 좌우 반전 — **반증**

**미러링 코드가 없다.** 정착 상태 상관계수가

```
front  corr(u, worldX) = **+0.980**
back   corr(u, worldX) = **+0.976**   ← 둘 다 같은 세계 x 방향
바깥면 법선            반대 (meanZ +9.5 / −5.9cm)
```

즉 **UV가 "이 패널의 겉면이 어느 쪽인가"(handedness)를 모르는 것**이고,
유일한 출처는 `patternGarment.ts:449-453` `mapTorso`가 두 패널에 **같은 x**를 주면서
**z만 부호를 가르는 것**이다.

후보 3종 전부 탈락:

```
flipPanelMeshX   **소매 전용** — 호출 1곳(:207)
뒤판 pos2.x      부호 반전 없음 (x ∈ [−27.50, 27.50] 앞뒤 동일)
v축              무관 — 화살표가 앞·뒤 캡처 **둘 다 위**
```

그리고 **`img-front`는 원본 그대로다**(적=왼쪽 / 청=오른쪽).
뒤집혀 보인 건 **back 한 장**이고, 그건 **카메라가 반대편(pos z=−3)** 이기 때문이다.

### ② 패널마다 통째로 한 장 — **참**

네 패널 전부 **u=0에서 시작**한다(원점이 패널별 bbox). **겹침 6쌍 전부.**
→ 68 §7의 **"패널마다 같은 그림 한 장씩"은 유효**하다.

### ③ 소매 축척 차이 — **UV에서는 반증**

```
UV/패턴 공간   du/w = dv/h = **0.01429 /cm** — 4패널 전부 동일. 차이 0
정착 3D        소매 73.61 · 73.52 vs front 69.14 / back 70.44 = **+6.5%**
카메라         front 화면 세로 2.498m vs cuff **0.407m** → **6.14배**
```

**`img-cuff`와 `img-front`를 가로질러 비교한 판정은 6.14배 계기 차를 UV에 귀속시킨 것이다.**
`img-cuff` **한 장 안에서** 재면 1.2~1.3배인데 팔 축이 수직에서 **31.0°** 기울어
수직 스캔 피치가 `1/cos31° = 1.167배`로 늘어난다 → `1.167 × 1.065 = 1.24`로 맞는다.
**UV 결함으로 남는 몫은 6.5%뿐이다.**

### 부수 관측 「cuff 겨드랑이 검은 띠 = 67 §6 미덮개 코너 후보」 — **반증**

소매 UV 상자 = `u[0, 0.514] × v[0.686, 1.0]` = 원본 **좌상(적) 사분면 + 화살표 왼쪽 날개**.
→ **그 검정은 테스트 이미지의 화살표다. 구멍이 아니다.**

### 등재 — **전략 세션 정정 21건째**

```
유형 1  **원경/근경 프리셋을 가로질러 비교해 계기 차를 대상에 귀속**   (③)
유형 2  **테스트 이미지의 내용을 결함으로 오독**                    (부수 관측)
```

유형 1은 [[../규칙/화면판정]]의 **「원경으로 국소를 판정하지 않는다」의 크기 판정판**이다
→ 같은 규칙에 절을 추가했다.

## §7 (c) 손 상수 2건 — **정지 사유**

**도출되는 것**

```
4패널 bbox        55.00×70.00 / 55.00×70.00 / 36.00×22.00 / 36.00×22.00 cm
총 면적           9,284cm² (√ = 96.35cm = 하한)
최소 외접 정사각형 **110.0cm** — 55×70 두 장이 x로 갈리면 110(y면 140)이라 하한이 강제되고
                  남는 110×40 띠에 소매 2장이 들어가 **하한이 달성**된다
결과 축척         1 uv = 70cm → **110cm**(텍셀 밀도 **0.636배** · 면적 40.5%)
                  512² 기준 앞판 7.3 px/cm → **4.65 px/cm**
점유율            9,284 / 12,100 = **76.7%**
```

**도출되지 않는 것 — 이것이 정지 사유다**

1. **배치 자유도** — 110×110이 **유일하지 않다**. 아래 110×40 띠 안에서 소매 2장의 (x,y)가
   자유이고 **90° 회전(22×36)해도 변은 110** 그대로다. **"최소 정사각형"이 동점을 못 깬다.**
   재단 마커라면 **원단 폭**이 정하는데 `GarmentDims`에 원단 폭이 **없다**
   (lengthM / widthM / shoulderWidthM / sleeveLengthM / sleeveWidthM 5종뿐).
2. **패딩** — 업로드 텍스처는 three 기본값이고 실측 확인:
   `magFilter LinearFilter` · `minFilter **LinearMipmapLinearFilter**` · `generateMipmaps **true**`.
   **밉맵이 아틀라스 경계를 가로질러 평균한다.** 현행이 무사한 건 **겹쳐 있어 이웃 텍셀이 같은
   내용**이기 때문이고, 체커는 `NearestFilter`라 애초에 블리딩이 없다.
   → **패딩 요구는 아틀라스가 새로 만드는 요구**이고 값의 **단위(텍셀 수 or cm)조차 도출 경로가 없다**
   (업로드 해상도는 사용자 입력이다).
