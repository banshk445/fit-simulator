## §3 §1 판별 계기 — **배선 완료**

전부 `console.log`만이고 **early return·await보다 앞**에 있다.

```
L1  렌더 본문   `[74판별·L1 렌더] #N garmentImage=null | string:<앞 40자>`
                (모듈 스코프 카운터 `__r74`로 렌더 횟수를 센다)
L2  uploadedTexture effect 최상단(`if (!garmentImage)` 판정 **앞**)
L3  composited effect 최상단(판정 앞) + async 본문 각 await 전후
    L3 진입 · L3a import 직전 · L3b import 직후 ·
    L3c 로드 대기 직후(naturalWidth) · L3d composite 호출 직전(uMax) ·
    L3e composite 반환(캔버스 크기)
```

→ 사전 등록 3분기(①구독/값 전달 ②effect 미실행 ③특정 await)가
**로그 위치만으로 갈리게** 설계했다.

### 1차 실행 — **정지(브라우저 부재)**

```
1) 브라우저 확장 연결 끊김 — `tabs_context_mcp` 재시도 포함 2회 모두
   "Browser extension is not connected"
2) Chrome 창 없음 — osascript가 `window 1을(를) 가져올 수 없습니다 (-1719)`
3) 우회(`?autofit=1`로 파일 입력 없이 garmentImage 주입)도 같은 이유로 실행 불가
   — 화면 표본 rgb(45.5, 45.5, 46.5)는 **창이 없는 상태의 배경**이다
     (체커 판정이 아니라 **측정 무효**로 기록했다)
```

사용자가 Chrome을 복구한 뒤 재실행했다.

## §5 무효 판정의 정체 — **자동 픽셀 판정이 다른 대상을 쟀다**

**함정 19 계열 · 자체 귀책.**

73·74회차에서 **5회 반복한** 「가슴 평균 rgb … → 체커(미적용)」은 전부
`screencapture`가 **Chrome 창이 없거나 뒤에 있을 때의 화면**을 담은 것을
표본으로 잰 값이다.

```
73회차 5회 시도의 "체커" 판정          전부 **무효**
74회차 `?autofit=1` rgb(45.5,45.5,46.5)  이미 「측정 무효」로 기록해 뒀다(창 없음)
직전 rgb(94.2, 97.0, 117.9)            창이 뒤에 있을 때의 화면 — **체커가 아니었다**
```

**69·71회차가 규칙에 넣은 「촬영 후 이미지를 열어 대상을 확인한다」를
73회차에 자동 판정 스크립트로 대체하면서 스스로 어겼다.**
**md5·픽셀 통계는 오염을 못 잡는다** — 69 §10이 이미 적어둔 그 문장이
이번엔 **자동화된 형태로** 재발했다.

**이전 사례들과 다른 점**: 함정 19의 종전 사례는 **계기의 정의역**이 표적을 빗나간 것인데,
여기서는 **촬영 대상 자체가 화면이 아니었다.** 그리고 **규칙을 이미 갖고 있으면서
자동화로 우회한 형태**라 [[../함정/함정24-가진채널미열람]](가진 것을 안 씀)과 **겹친다**.
→ [[../함정/함정19-계기가다른대상]]에 **두 함정의 교차 사례**로 등재했다.

## §7 사전 등록 판정 — **3분기 전제가 거짓 · 표적 소멸**

> 사전 등록 3분기 ① 구독/값 전달 ② effect 미실행 ③ 특정 await

①②③은 전부 **「합성이 화면에 안 붙는다」를 전제**한다. 그 전제가 무효이므로
**분기 판정을 하지 않는다.**

**「판정 불가」가 아니라 「표적 부재」다.** 사후 갈래 신설 **없음.**
