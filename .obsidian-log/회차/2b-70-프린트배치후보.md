## §6 후보 A 상세 — 참이어도 어긋나는 것 (**도출된 예측 · 새 상수 아님**)

`compositeGarmentTexture`는 512² 캔버스를 **테두리 기반 원단 대표색**(`:43`)으로 채우고,
대표색과 색거리 55 이상인 픽셀의 bbox(= 프린트)만 **원본 비율 그대로** 가슴 중앙에 합성한다.
**crop 산출물은 이미 쓰고 있다** — `Controls.tsx:99 cropToGarmentRegion` → store →
`PatternPreview.tsx:70`.

**v1 상수는 「몸판 UV가 u∈[0,1] 전체」라는 전제 위에 있는데 v2 몸판은 `u ∈ [0, 0.7857]`만 쓴다.**

```
프린트 가로  0.45 × 70 = 31.5cm / 패널 폭 55cm = **57.3%**   (v1 의도 45%)
프린트 중심  u 0.500 vs 패널 중심 u 0.3929 → **+x로 7.5cm 치우침**
프린트 세로  v 0.75부터 = 어깨선에서 17.5cm 아래 (v는 0~1 전량 사용 → **v1과 동일**)
```

**가로만 어긋나고 보정값은 `uMax`에서 도출된다**(손 상수 아님).

**거짓 갈래 2 — 판별자는 이미 v1에 있다**

```
테두리 띠 8%가 배경이면      대표색이 **배경색**이 된다
프린트가 프레임 90% 이상이면 `PRINT_MAX_FRAME_FRACTION`에 걸려 **단색만** 나온다
판별자                      **캔버스 (0,0) 픽셀 rgb** — v1에 이미 있다
```

**crop은 배경 제거가 아니다** — 사각형 크롭 + **피부색 픽셀만** 원단색으로 덮어칠이고,
플랫레이(전경 92% 이상)면 **원본 그대로** 반환한다(원본 반환 폴백 5경로).

## §7 후보 C 상세 — **v1의 상수 `1`을 그대로 옮기면 틀린다**

v1 대응물 `Garment.tsx:603-612`의 `clone.repeat.x = -1; clone.offset.x = 1;`은
**u∈[0,1] 전체** 전제다. v2 패널은 **자기 bbox만** 쓴다:

```
몸판  u ∈ [0, 55/70 = **0.7857**]   v ∈ [0, 1]
소매  u ∈ [0, 36/70 = **0.5143**]   v ∈ [0.6857, 1]
```

올바른 반사는 **`u' = uMax − u`**(손 상수 0)이고, `offset.x = 1`을 쓰면 반사가 아니라
이미지의 **다른 대역으로 이동**한다. 또 `Garment.tsx:598-604` 주석에 **보정 대상을
앞판으로 오판한 이력**이 있다.

### 검토 3의 답 — 뒤판이 단색이 되면 handedness는 소멸하는가

**화면에서는 뒤판 한정으로 잠복하고, 항목은 소멸하지 않는다.**

```
1  단색에는 좌우가 없어 **보이지 않게 될 뿐** — 대상이 사라진 것이지 고쳐진 게 아니다
2  **소매 2장의 u 방향이 서로 반대다** — `patternGarment.ts:207 flipPanelMeshX`가 `pos2.x`를
   음수화한 뒤 자기 bbox로 재정규화하므로 산술적으로 `u_L = uMax − u_R`.
   → **소매에 그림을 넣는 순간 되살아난다**
3  **앞판 프린트 방향의 정오는 계속 판정 대상**이다
4  **T7 재개 시 전면화**된다(69 §11이 「아틀라스와 별개 항목」으로 등재)
```
