## §1 확인 (코드 고치기 «전»)

### §1-1 roll 자유도와 채택 규약

**현재 코드가 roll을 다루는 방식**(`boneUtils.ts:201~227`):
`setFromUnitVectors(currentDirWorld, targetDirWorld)`는 **최소호**(shortest arc)라 목표 축 둘레
roll을 «추가하지 않는다». 따라서 최종 roll은 **직전 `bone.quaternion`이 갖고 있던 roll을 그대로
물려받는다** — 규약이 명시적으로 정해진 적이 없고 **궤적이 정한다.**

**채택: (a) bind(rest) 기준 최소호.**

```
q = minimalArc( normalize(q_bind · d0), R_parentWorld⁻¹ · target ) ∘ q_bind
    d0 = normalize(child.position)   // 자식의 bind 로컬 오프셋(상수)
```

근거: ① 본의 **원래 자세를 유지**하므로 가장 보수적이다. ② **첫 프레임에서는 누적곱판과 같은
결과**다(그때 `quaternion`이 곧 bind이므로) — 규약 교체의 불연속이 최소다.
③ 입력이 (bind 회전 · 자식 bind 오프셋 · 부모 월드 회전 · 목표 방향) 넷뿐인
**순수 함수**다. **현재 `quaternion`을 읽지 않는다** ⟹ 궤적이 남지 않는다.

(b)(고정 up 프레임)는 채택하지 않았다 — 정의는 유일하나 bind roll과 어긋나 포즈가 더 크게 바뀐다.

**실행 «전»에 적어 둔 한계**: 조상에 **비균등 스케일**이 있으면(가슴둘레가 몸통 본에 축별로
다른 스케일을 건다) 월드 방향은 회전만으로 정해지지 않는다. 누적곱판은 실제 월드 위치 차이를
매 프레임 다시 재서 그 왜곡을 «따라갔고», 절대판은 따라가지 않는다.
⟹ **정확도를 조금 내주고 결정성을 얻는다.** 그 대가가 §3의 값이다.

### §1-2 부모 체인 의존 — **루프 안에는 없다**

`boneGroups.arm`은 **조상-자손 필터링을 거친 최상단 본만** 담는다
(`Mannequin.tsx:151~157` `filter(node => !isDescendantOfAny(node, set))`).
⟹ A포즈 루프가 도는 두 본은 **형제**이고 서로의 부모가 아니다. 루프 내 순서 의존 0.
부모(어깨/Spine)의 월드는 읽기 «전»에 `parent.updateWorldMatrix(true, false)`로 갱신한다.

### §1-3 `bodyPos`가 팔 회전에 반응하는 경로 — **특정**

`meshCollision.ts:162~170`:
```ts
const positionAttr = this.geometry.getAttribute("position");
const position = Float32Array.from(positionAttr.array);       // ← 전량
const torsoOnlyIndex = excludeArms(positionAttr, this.geometry.index, armSegments);
```
**`excludeArms`는 «인덱스»(삼각형 목록)만 걸러내고 `position`은 팔 정점을 그대로 포함한다.**
`bodyPos`는 그 `position`의 해시다 ⟹ 팔 회전이 바뀌면 직접 바뀐다. **경로 특정 완료.**

**「키 축은 `bodyPos` 비트 동일인데 가슴 축은 갈렸다」(P26 §3-4)는 부분 특정에 그친다**:
`position`은 `Float32Array`라 팔 회전의 f64 차이가 float32 아래면 흡수된다 — 키 축은 흡수됐고
가슴 축은 아니었다는 관측과 일관되지만, **「왜 가슴에서 더 큰가」는 값으로 확정하지 않았다.**
**미특정으로 적는다.**
