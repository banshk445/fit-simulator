## §0 결론

회차가 세운 유력 가설(**「핏 맵 토글이 다른 렌더 경로로 보낸다」**)은 **거짓**이다.
증상 2건은 **원인이 서로 다르다**.

```
① 핏 맵을 켜도 색이 안 입혀진다   → 결정적 결함. v2에는 **색 경로가 아예 없었다**(코드 사실)
② 옷이 납작한 판으로 보인다        → 렌더 «순서» 문제. 착장 결과가 반영된 «직후»
                                     지오메트리가 다시 설치되어 정착 좌표를 정적 배치로 덮는다
                                     (로그 순서로 **값 확인**)
```

둘 다 고쳤고, ②의 **뿌리**(마네킹이 늦게 오는 동안 조용히 커밋 fixture로 돌던 것)도 막았다.

## §1 재현과 범위 특정

### §1-1 핏 맵 on/off — **토글은 렌더 경로를 가르지 않는다**(코드 사실)

`showFitMap`의 소비처를 저장소 전량에서 확인했다:

| 소비처 | 무엇을 하는가 |
|---|---|
| `Garment.tsx`(**v1**) | 정점색·재질 분기 — v1에는 색 경로가 있다 |
| `DressButton.tsx` | **리포트 표**를 보일지만 정한다 |
| `Controls.tsx` | 범례를 보일지만 정한다 |
| **`PatternPreview.tsx`(v2 렌더)** | **읽지 않는다** |

⟹ v2에서 토글은 **표와 범례만** 켰다. 3D는 어느 경로로도 가지 않는다.
**「범례는 뜨는데 색이 안 입혀진다」의 원인이 이것이고, 가설(경로 분기)은 성립하지 않는다.**

### §1-2 납작판 — 통제 조건 **5종 전부 정상**

| 조건 | 결과 |
|---|---|
| 로컬 · 핏맵 off | **정상 드레이프** · 「착장 결과 반영」 로그 |
| 로컬 · 핏맵 on | **정상** |
| 배포 · 핏맵 off | **정상** |
| 배포 · 핏맵 on(P16과 같은 클릭 순서) | **정상** |
| 배포 · **탭 hidden 상태로 착장** | **정상**(35.6s로 느려질 뿐) — 「캔버스가 옛 프레임을 유지한다」 가설도 **반증** |

⟹ 타이밍이 맞아야만 나는 **간헐**이다. 핏맵 on/off도 로컬/배포도 갈림이 아니다.

### §1-3 **기전 확정 — 값으로 잡았다**

계기를 먼저 붙였다(지오메트리 설치 세대 · 결과 반영/버림). 배포에서 잡힌 순서:

```
12:17:08  [patternPreview] 착장 결과 반영(이벤트) — … 설치 세대 #1
12:17:08  [patternPreview·P17] 지오메트리 설치 #1 — 정점 5244      ← **반영 «다음»에 설치**
```

**정착 좌표가 입혀진 직후 정적 배치 지오메트리가 다시 설치되어 덮는다.** 그 상태가
「납작한 판」이고, 103 §0-1의 「평면 상자」와 같은 그림인 이유도 그것이다(같은 좌표다).

**왜 그 시점에 다시 서는가** — 그때 같이 잡힌 로그:

```
[dress] 마네킹 미정착(frames 0 · 잔차 Infinity) — 커밋 fixture로 돈다
[dress] 마네킹 루트/어깨 본 미준비 — 커밋 fixture로 돈다(몸 슬라이더 미반영)
[patternPreview] 마네킹 미정착 — 커밋 fixture로 그린다   ← 정점 5244(테이퍼 없는 구 판본)
설치 #1 … 설치 #1 … 설치 #1      ← 세대가 계속 #1 = **컴포넌트가 remount되고 있다**
```

배포는 마네킹이 **38MB**라 「아직 안 온」 창이 넓다. 그 창에서 「착장하기」를 누르면
**조용히 커밋 fixture(P10 이전 판본)로 돌고**, 마네킹이 도착하는 동안 미리보기가
반복해서 다시 서면서 결과를 덮는다.

### §1-4 「언제부터인가」 — **P14·P15·P16이 만든 것이 아니다**

셋 다 렌더를 안 건드렸다는 기록이 맞다. 이 경로는 **P2c(f)에 리스너가 붙은 뒤로 계속**
그랬고, 조건(마네킹 지연 + 그 사이 클릭)이 맞을 때만 드러났다. **P13까지의 캡처가 멀쩡했던
것은 그 조건을 안 만났기 때문**이고, P16 캡처는 만난 것이다. **시점 특정 불가**로 적는다.

## §2 수리 — 렌더만 만진다

| # | 무엇 | 왜 |
|---|---|---|
| 1 | **결과를 모듈 스코프에 보관하고, 지오메트리가 (다시) 설 때마다 다시 입힌다.** 치수 서명(`renderSig` — 옷·몸·소매타입·**원단**)이 다르면 입히지 않는다 | 순서가 어떻게 되든 「정착 좌표가 정적 배치에 덮이는」 일이 없어진다. **컴포넌트 ref로는 부족하다** — remount에 함께 사라진다(§1-3이 그 증거다) |
| 2 | **핏 맵 정점색을 v2에 배선한다.** 워커가 정점별 부호거리(`fitPerVertex`)를 함께 넘기고, 렌더가 색을 만든다 | 술어는 **핏 리포트와 같은 것**을 쓴다(몸판 = 앞/뒤판 메시 · 소매 = 전신 메시) — 표와 색이 다른 것을 말하면 안 된다. **새 술어 0 · 새 문턱 0**(경계는 워커가 실어 보낸 흡착 margin 15.0mm) |
| 3 | **마네킹이 오기 전에는 「착장하기」를 못 누른다.** 버튼 비활성 + 「마네킹 불러오는 중 — 준비되면 «착장하기»가 켜집니다」 | ②의 **뿌리**다. 조용한 fixture 폴백이 사라지면 remount 폭풍도, 「몸 슬라이더가 반영 안 된 결과」도 안 만난다. P4/P9가 세운 「입력이 삼켜지면 그렇다고 말한다」와 같은 계열 |

부수 2건:

- **말없는 실패 경로를 말하게 했다**(함정 25) — 결과가 왔는데 그릴 대상이 없으면
  조용히 버려졌다. 이제 경고를 찍는다.
- **검정 옷 방지** — 색 속성이 없는데 `vertexColors`를 켜면 three가 (0,0,0)으로 읽어
  옷이 **새까맣게** 나온다(배포에서 실측). 색이 실제로 있을 때만 켠다.

### §2-1 범례 정정

옛 문구 「관통(디버그) / 타이트 / 적정 / 헐렁」은 **v1의 0/1/3cm 눈대중 스케일**이었고
v2에는 그 색이 아예 안 입혀지고 있었다. 실제 경계에 맞춰 다시 썼다:

```
눌림 (≤ 0mm) 빨강 · 밀착 (≤ 15.0mm) 노랑 · 여유 (> 15.0mm) 파랑 · 산출 불가 회색
「옷↔몸 간극 · 경계는 핏 리포트와 같다(흡착 margin). «착장하기»를 눌러야 색이 입혀진다.」
```

회색은 **부호거리를 못 구한 자리**이고, 없는 값을 색으로 지어내지 않는다는 뜻이다.
