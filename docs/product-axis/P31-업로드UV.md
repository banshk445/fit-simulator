```
[uv] 패널 4매 · 총장 70.00cm / 품 55.00cm
[uv] FRONT    pos2 x[-27.50, 27.50] y[0.00, 70.00]cm · uv u[0.0000, 0.7857] v[0.0000, 1.0000]
[uv] BACK     pos2 x[-27.50, 27.50] y[-0.00, 70.00]cm · uv u[0.0000, 0.7857] v[0.0000, 1.0000]
[uv] SLEEVE_L pos2 x[-18.00, 18.00] y[0.00, 22.00]cm · uv u[0.0000, 0.5143] v[0.6857, 1.0000]
[uv] SLEEVE_R pos2 x[-18.00, 18.00] y[0.00, 22.00]cm · uv u[0.0000, 0.5143] v[0.6857, 1.0000]
[uv] 앞판 uMax 0.7857 · 축척 70.00cm/uv1 · v[0,1] ↔ 패턴 y[0.00, 70.00]cm
```

| 항목 | 값 |
|---|---|
| 패턴 2D 규약 | `patternDraft.ts:8` — **y는 아래로 증가, y=0 = 어깨선(HPS)** |
| 변환 | `u = (x−xMin)/scale` · `v = 1 − (y−yMin)/scale` (`patternGarment.ts:318-320`) |
| `scale` | **전 패널 공통** = 패널 최대변 = 앞판 높이 **70.00cm** |
| 앞판 | `v=1` ↔ 어깨선 · `v=0` ↔ 밑단 · `u∈[0, 0.7857]`(폭 55/70) |
| 텍스처 | `THREE.CanvasTexture` **flipY=true**(`three/src/textures/Texture.js:281`, CanvasTexture 재정의 없음) ⟹ `uv.y=1` = 캔버스 **위쪽** |
| 공유 여부 | **패널별 텍스처가 아니라 «한 장을 공유»한다.** 4패널이 같은 uv 규칙을 쓰고 bbox만 자기 것으로 옮긴다 |

**⟹ 어깨선 = 캔버스 위쪽. 합성 상수의 주석(`PRINT_TOP_FRACTION` = 「캔버스
상단(어깨선)에서부터의 비율」)과 v2 구현이 «일치»한다. v2에 세로 뒤집힘은 없다.**

### §1-3 배치 상수 — 전부 「실측 아님, 눈대중 초기값」

`garmentTextureComposite.ts:102-118` 원문 주석 그대로:

| 상수 | 값 | 원문 주석 |
|---|---|---|
| `PRINT_COLOR_DIST_THRESHOLD` | 55 | 실측 아님, 눈대중 초기값 |
| `PRINT_MAX_FRAME_FRACTION` | 0.9 | 실측 아님, 눈대중 초기값 |
| `PRINT_WIDTH_FRACTION` | 0.45 | 실측 아님, 눈대중 초기값(요청 범위 40~50%의 중간값) |
| `PRINT_TOP_FRACTION` | 0.25 | 실측 아님, 눈대중 초기값 |

배치식(`:316-324`):

```
panelW = 512 × uMax          destW = panelW × 0.45      destH = destW ÷ 원본종횡비
destX  = (panelW − destW)/2  destY = 512 × 0.25
```

**원본에서 오는 것은 «종횡비 하나»뿐이다.** 원본에서 프린트가 옷의 어디에
어느 크기로 있었는지(위치·상대 크기)는 `drawImage`의 src 인자로만 쓰이고
**dest에는 반영되지 않는다** — 폐기된다.

### §1-4 체커는 왜 정상으로 보였는가

두 가지가 겹쳐 **원리적으로 안 보인다**:

1. 체커는 **반복 무늬**다 — 세로 오프셋·뒤집힘·좌우 반전이 모두 같은 그림을 낸다.
   랜드마크가 없으므로 어긋남이 화면에 신호를 만들지 않는다.
2. 체커 경로는 `panelSurface`의 **폴백 가지**다(`PatternPreview.tsx:206`) —
   업로드가 없으면 **4패널 전부** 같은 체커를 받는다. 즉 「앞판만 map」이라는
   실제 배선조차 체커에서는 발동하지 않는다.

**⟹ 이 결함은 처음부터 있었고(상수는 도입 시점부터 눈대중), 실사용이 처음
드러낸 것이다.** 체커로는 앞으로도 못 잡는다 — 방향·위치 랜드마크가 있는
합성 이미지가 있어야 한다(§5 이월).

### §1-5 뒷면 단색 — «의도»다 (결함 아님)

`PatternPreview.tsx:204-207`:

```ts
const panelSurface = (i: number) => {
  if (composited) return i === 0 ? { map: composited.tex, color: "#ffffff" }
                                 : { map: null, color: composited.solid };
  return { map: texture, color: "#ffffff" };   // 업로드 없음 → 체커 폴백
};
```

패널 0(FRONT)만 합성 텍스처를 받고, 나머지(BACK·SLEEVE×2)는 **map 없이 대표색
단색**을 받는다. 「뒤판 UV가 이미지 밖으로 나갔다」가 **아니다** — 뒤판 uv는
앞판과 같은 `v[0,1]`로 멀쩡하다(§1-2 표). 배선이 의도적으로 map을 안 준다.
