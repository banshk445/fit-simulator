# P4 — wearable 게이트 정리 (P1 ⑤)

**기점**: `ee92c8e` (P3) · **정의역**: 화면의 문언/동작 모순 하나를 닫는다. 몸 연속화는 P5.
**바뀐 파일**: `src/components/DressButton.tsx` **1개뿐**. 게이트 상수·물리·스크립트 0줄.

## 결론

문언을 고치지 않고 **동작을 문언에 맞췄다**. BLOCK은 실행을 막고 WARN은 돌린다.
덤으로 **P3 §4-3이 「원인 미상」으로 남긴 34게이트 throw가 이 판에서 재현·특정됐다**(§4-4).

## §1 현황 — 문언과 동작이 어긋난 이유

| 무엇 | 자리 |
|---|---|
| 판정식·문언 | `src/lib/garmentFitLimits.ts` `checkGarmentFit()` → `FitCheck.message` |
| 배너 렌더 | `src/components/Controls.tsx:86` |
| **실행 차단** | `src/components/FitCanvas.tsx:76-77` `const wearable = fit.verdict !== "impossible"` |

**어긋난 이유는 문언이 틀려서가 아니라 게이트를 읽는 경로가 하나뿐이었기 때문이다.**
`wearable`은 v1 분기에서만 쓰인다:

```
{!patternCore && (!garmentImage || !wearable) && <GarmentMesh />}      // 불가 → 파란 원통(플레이스홀더)
{!patternCore && garmentImage && wearable && <Garment …/>}            // 가능할 때만 v1 물리 옷
{patternCore && PatternPreview && <PatternPreview />}                 // ← wearable을 **안 읽는다**
```

⟹ v1에서는 「시뮬레이션을 실행하지 않습니다」가 **참**이었다(불가면 `Garment`를 아예 마운트하지 않는다).
v2(`?patterncore=1`)는 그 게이트를 통과하지 않고, P2c가 붙인 `DressButton`도 게이트를 안 봤다
⟹ 경고를 띄운 채 워커가 돌아 **DONE f=260 · 50.1s**가 같이 떴다(P3 캡처).

**P1 ⑤와 같은 것이다.** P1은 렌더 분기(`FitCanvas.tsx:105-108`)를 지목했고, P2c 이후로는
**실행 진입점(`DressButton`)** 이 더 중요한 자리가 됐다 — 같은 결함의 같은 뿌리다.

### §1-3 상수 3종과 반둘레 규약의 정합 — **검증만**(값 변경 0)

**차원은 정합한다.** `ratio = 품 ÷ (chest × 1.194 / 2)` = 옷 평면폭 ÷ 몸 반둘레 =
(옷 폐둘레/2) ÷ (몸 폐둘레/2) — P3 §1이 확정한 **반둘레:반둘레** 비교다.
`garmentFitLimits` 주석의 「이 비율이 1이면 딱 맞게 감김」도 같은 규약이다. ✓

**산수도 맞는다.** 129 × 1.194 / 2 = 77.013 → ×0.76 = **58.5cm** (화면과 일치) ·
100 → 59.700 → **45.4cm** (화면과 일치).

| 가슴 슬라이더 | 게이트 반둘레 | minWidth(BLOCK) | comfort(WARN) |
|---|---|---|---|
| 100 | 59.700 | 45.4 | 51.0 |
| 110 | 65.670 | 49.9 | 56.1 |
| 120 | 71.640 | 54.4 | 61.3 |
| 129 | 77.013 | 58.5 | 65.8 |
| 140 | 83.580 | 63.5 | 71.5 |

**그런데 교정 상수가 v2의 몸 실측과 어긋난다(등재 · 안 고침).**
`CHEST_PERIMETER_RATIO = 1.194`는 「슬라이더 100 = 마네킹 단면 둘레 119.4cm」를 뜻하는데,
v2의 `measureBody`가 **같은 슬라이더 위치의 같은 fixture**에서 재는 값은 **84.01cm**다
(dress 로그 「몸 가슴둘레 84.01cm」). **1.421배 차이**다.
두 값은 방법이 다르다 — 119.4는 「어깨선 아래 10~25cm · 1cm 슬랩 · XZ convex hull 둘레 최댓값 ·
팔 제외는 슬랩 내 최대 빈틈」, 84.01은 `measureBody`의 팔 제외 볼록껍질이다.
`patternDraft.ts:226`이 이미 「119.4는 «슬라이더 가슴둘레»이지 메시 실측이 아니다」로 등재해 뒀다.

그 결과 문턱을 **v2 메시 기준으로 환산하면**:

| 문턱 | 게이트 정의 | v2 실측 환산(옷 폐둘레 ÷ 몸 폐둘레 84.01cm) |
|---|---|---|
| BLOCK 0.76 | 품 45.4cm @가슴100 | **1.080** (여유 8%) |
| WARN 0.855 | 품 51.0cm @가슴100 | **1.215** (여유 22%) |

즉 게이트는 **여유 8% 미만을 「천이 몸을 감쌀 수 없다」로 막는다** — v2 메시 기준으로는
보수적이다. 상수 재도출은 **P5**로 넘긴다(몸이 살아나면 두 수치를 «같은 메시»에서 뽑을 수
있고, 그때가 재도출의 자연스러운 시점이다). 이 판은 프롬프트대로 **검증만** 했다.

## §2 채택한 동작 — **단계 구분**

| 판정 | 동작 | 문언(기존 그대로) |
|---|---|---|
| `impossible` (ratio < 0.76) | **차단** — 버튼 비활성 + 사유 표시 · 클릭해도 실행 0 | 「… 시뮬레이션을 **실행하지 않습니다**」 ⟹ 이제 참 |
| `tight` (0.76~0.855) | **실행** + 경고 병기 | 「아주 타이트한 핏입니다 …」 ⟹ 실행을 막는다고 말하지 않는다 ⟹ 이미 참 |
| `ok` | 실행 | 문언 없음 |

**고른 이유**:
1. 상수가 이미 `WIDTH_RATIO_BLOCK` / `WIDTH_RATIO_WARN`으로 갈려 있고 **두 문언도 이미
   다르게 쓰여 있다** — 한쪽만 「실행하지 않습니다」라 단정한다. 설계 의도가 단계 구분이다.
2. v1이 이미 그렇게 동작한다(불가 → `Garment` 미마운트). v2를 같은 규칙으로 맞추면
   **두 경로의 동작이 하나가 된다.**
3. 문언을 고치는 선택지(「정확하지 않을 수 있습니다」로 완화)는 **이미 있는 판정을 약화**시킨다.
   판정식이 틀렸다는 근거가 없는데(§1-3: 차원·산수 정합) 문언을 낮출 이유가 없다.

**부작용(등재)**: P3 §4-3에서 돌던 **품 35cm(가슴 100)가 이제 차단된다.** 그때는 DONE f=270로
돌아 cov 18.7%를 냈다 — 「돌긴 하지만 심하게 안 맞는」 상태였다. §1-3의 환산대로 BLOCK 문턱이
보수적이므로, 상수를 재도출하면 이 조합이 다시 열릴 수 있다. **값을 바꾸지 않고 기록만 한다**.

**렌더는 막지 않는다**: `patternCore` 분기의 `PatternPreview`(정적 배치)는 그대로 그린다.
그건 시뮬 결과가 아니라 «지금 편집 중인 패턴»이라, 막으면 사용자가 무엇을 고치는지 못 본다.
문언은 「시뮬레이션을 실행하지 않습니다」이고 시뮬은 실제로 안 돈다 — 모순 없다.

### §4-4 **실패 표시 발화 — P3의 「원인 미상」이 닫혔다**

위 품 48 실행이 정착하지 못하고(S3 f=930까지 진행) **RETRY 뒤 34게이트에서 던졌다.**
UI는 크래시 없이:

> 착장 실패 — 배치 실패 — 34게이트 위반 **(ii) 핀 발화 직후**: 몸판 신장비
> 0.068672~22.656033 (문턱 1.000000±3.33e-5 …) · **신장총 14841.6cm** (87.6s)

좌표는 반영하지 않고 이전 결과가 남는다. 버튼은 다시 활성화된다. (P3 §3③ 배선이
드디어 실측됐다 — P3에서는 「미발화」로 적었던 항목이다.)

**P3 §4-3 미상 항목 해소**: 104 §3의 throw는 `0.067~22.669 · 신장총 14841.6cm`였다.
**신장총이 소수점까지 일치**하고 위치도 같다 ⟹ 104의 throw를 「폭이 좁아서」로 귀속한 것은
**틀렸다**. 실제 자리는 **RETRY 재배치 뒤 「(ii) 핀 발화 직후」 게이트**다.
P3에서 품 35cm가 통과한 것도 이것으로 설명된다 — 그 조합은 RETRY 없이 첫 배치에서 정착했다.

**남는 의문(등재 · 이 판에서 안 팜)**: 옷 폭이 다른 두 실행(104의 e=3cm ≈ 품 42 등가 vs
이번 품 48)이 **같은 신장총 14841.6cm**를 냈다. 폭에 의존하지 않는 항이 지배한다는 뜻이고,
그 자체가 「(ii) 게이트가 무엇을 재고 있나」에 대한 질문이다. 드레이프 캠페인 복귀 시 표적 후보.
