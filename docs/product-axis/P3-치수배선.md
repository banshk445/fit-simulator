# P3 — 치수 조정이 실제로 동작하게

**기점**: `6cca41c` (P2d) · **회귀 조건**: 슬라이더 기본값에서 기준선 A 9채널 일치.
**결과**: 기본값 회귀 **통과**. 옷 슬라이더 4종이 살아났다. **몸 슬라이더는 §2에서 멈췄다**(범위 초과).

## §1 규약 결정과 품 배선

### 규약: **평면 실측(반둘레)** — `patternDraft.ts` `GarmentDims` 주석이 정본

> **품 55cm = 몸판 1매 평면 폭 55cm = 완성 폐둘레 110cm**

고른 근거는 이미 저장소가 그 규약으로 쓰고 있었다는 것이다 — 새로 만든 규약이 아니다:
- `patternDraft.ts` `sleeveWidthM` 주석 「소매통(평면 실측) → 소매 둘레 = 2×이 값」
- `useFitStore.ts:117-127` 기본값 주석 「실제 가슴단면(품)은 가슴둘레의 절반 안팎이
  정상이라(100cm 가슴둘레 기준 약 50~55cm)」
- 라벨 정합: 가슴둘레 100cm 몸에 품 55cm는 폐둘레 110cm ⟹ 들어간다.
  품을 «폐둘레»로 읽으면 55 < 100이라 애초에 못 입는다 — 그 독법은 성립하지 않는다.

**알려진 불일치 1건(안 고침)**: v1 미리보기 원통 `FitCanvas.tsx:48`
`radiusM = width/(2π)/100`은 품을 «폐둘레»로 읽어 반지름이 절반이 된다.
v1 렌더 전용이고 이 판의 정의역 밖(「v1 경로 수정」 제외)이라 그대로 뒀다. §6에 남긴다.

### 품 배선 — 104의 몸 도출 형식을 되돌렸다

`patternDraft.ts`
```
before: halfWidthM = body.chestGirthM / 4 + WIDTH_EASE_M   // g.widthM을 안 읽는다 = 슬라이더 死
after : halfWidthM = g.widthM / 2                           // 규약대로 «평면 폭»의 절반
```

되돌린 근거:
1. 104 §2는 스스로를 **항등 재표현**이라 적었고, `e`를 실제로 바꾼 §3 2단계는 34게이트
   위반으로 **실패·원복**했다 ⟹ 몸 도출 형식이 «다른 값»을 낸 적이 한 번도 없다.
2. 이 제품은 핏 **시뮬레이터**다. 옷 치수가 몸을 따라 자동으로 커지면
   「이 옷이 이 몸에 맞는가」라는 질문 자체가 사라진다.
3. `B/4 + e`(e = 104의 역산값)는 `0.55/2`와 **비트 동일**이다(실측 확인).
   ⟹ 기본 슬라이더 55cm에서 기준선 A가 그대로 나온다.

**몸은 폭 말고 전부에 여전히 관여한다** — 진동깊이(`B/4 + 3cm`) · 목선(목밑둘레) ·
능선 앵커 · 외곽선. 폭만 슬라이더가 정한다.

## §2 bodySize 배선 — **범위 초과로 멈춤(미집행)**

프롬프트의 판단 조항(「연속이 필요하면 그 사실을 보고하고 멈춘다」)에 따라 **멈춘다.**
코드 판독 결과 **이산 fixture 선택으로는 부족하다**:

| 근거 | 실측 |
|---|---|
| 마네킹은 **연속**으로 변형된다 | `Mannequin.tsx:263-299` — 키·가슴·팔·다리·어깨너비 5축을 본 스케일에 lerp로 건다. 이산 상태가 아니다 |
| fixture는 **1축 3점**뿐 | 가슴 대역 폭 실측 base 31.38cm / v110 34.70cm / v120 37.91cm — 가슴둘레 축만 3점. 슬라이더 범위는 70~140이고 나머지 4축은 fixture가 아예 없다 |
| 스냅은 결함을 남긴다 | 가장 가까운 fixture로 붙이면 «그리는 몸»과 «제도가 보는 몸»이 여전히 달라진다 — P1 §2가 찾은 바로 그 결함이 대부분의 슬라이더 값에서 그대로 남는다 |

**연속 몸에 필요한 것**(다음 판 견적): 브라우저에서 살아있는 마네킹을 굽는 경로가
필요하다. 조각은 이미 있다 — `meshCollision.MannequinCollisionMesh.bake(root)`(스킨/본
변형 반영) · `buildTorsoProxyCapsules(어깨L, 어깨R, 키, 가슴)`. **문제는 위치다**:
지금 그 조립은 `Garment.tsx`(v1 컴포넌트) 안에 있고 `?patterncore=1`에서는 **마운트되지
않는다**. 게다가 `exportCollision`은 v1 워커의 `init`/`step`이 이미 돈 뒤에야 동작한다
(`lastInitLayoutRef`/`lastStepPoseRef` 의존).
⟹ v1과 무관한 **몸 추출 모듈 신설**(bake + 팔 선분 + 어깨 본 + 캡슐 + layout topY/centerZ)
이 필요하고, 슬라이더가 움직일 때마다 재굽기 + 풀 시뮬(10~60s) 재실행 정책도 정해야 한다.
이 판의 정의역을 넘는다.

### 그래서 지금 무엇이 보이는가 (실측 · 스크린샷)

몸 가슴둘레 100 → **129**로 올리고 착장하면:
- 정합 채널 **9종 전부 기준선 A와 동일** — 패턴·물리는 커진 몸을 **한 번도 못 본다**
- 화면은 마네킹이 옷을 통째로 뚫고 나온다(밑단 띠와 소매 조각만 남는다)
- v1의 착용 경고 배너는 **뜬다**(「가슴둘레 129cm에는 품 58.5cm 이상이 필요합니다」)
  — 그러나 v2 경로는 그 게이트를 안 읽고 그대로 돈다(P1 ⑤ · 다음 판)

### §4-2 슬라이더별 동작 (P1 §2 대비)

| 슬라이더 | 값 | P1 §2 | P3 결과 | 착장 결과 |

| **몸 가슴둘레** | 100→129 | 마네킹만 · 옷 뚫림 | **미배선(§2)** | 9채널 **기준선 A와 완전 동일** · 화면은 몸이 옷을 뚫는다 |

**어깨너비를 일부러 안 배선한 근거**: 그 값은 fixture 포즈의 핀 간격
`|pinL.x − pinR.x| = 44.9995105850059cm`에서 나오고, 슬라이더 기본값은 45cm다.
배선하면 **기본 슬라이더에서 패턴이 바뀌어 기준선 A가 깨진다** — 프롬프트의 판정 기준으로
「배선이 값을 오염시킨 경우」다. 배선하려면 어깨 핀 자체가 슬라이더에서 나와야 하고,
그건 §2(몸 배선)와 같은 문제다. `PatternPreview`의 정적 배치도 같은 이유로 fixture 포즈를
쓰게 맞췄다(워커와 «같은 옷»을 그려야 한다).

### §4-3 극단값 — **크래시 0 · 실패 미발화**

| 조합 | 결과 |
|---|---|
| 품 35cm(최소) | DONE f=270 · 15.6s · cov 18.7% · maxStrain **3.081**(정점 64) · 밑단 합 72.80cm · 관통 164/3734 |
| 총장 40cm + 품 35cm(둘 다 최소) | DONE f=260 · 9.8s(크롭탑) |
| 몸 가슴둘레 129cm | DONE f=260 · 50.1s(옷이 몸을 못 덮는다 — §2) |

**실패 경로는 이번 극단값에서 발화하지 않았다.** 코드 배선은 되어 있으나 «실패 화면»을
실측하지는 못했다 — 그대로 적는다(만들어내지 않는다).

관련 관측 1건: 104 §3은 `e=3cm`(= 몸판 반폭 21.0cm ≈ 품 42cm 등가)에서 34게이트를
던졌는데, **이번 품 35cm(반폭 17.5cm)는 더 좁은데도 DONE**이다. 두 값은 같은 방향의
극단인데 결과가 갈린다 ⟹ 104의 throw를 「폭이 좁아서」로 귀속하면 안 된다.
**원인 미상**으로 남긴다(이번 판의 표적이 아니다).
