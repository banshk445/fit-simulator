## §4 구도 편차 1건 — **Chrome 디버깅 인포바(58pt)**

**사실**: 이 판은 「착장하기」를 눌러야 해서 페이지에 JS를 넣을 채널이 필요했고,
그 채널(`claude-in-chrome`)은 탭에 디버거를 붙인다 ⟹ Chrome이 상단에
「'Claude'에서 이 브라우저에 대한 디버깅을 시작함」 **인포바**를 띄운다.
- 인포바 높이 **57.5pt**(캡처 실측: 어두운 띠가 115px에서 끝난다 · 레티나 2배).
- 그만큼 **앱 뷰포트가 짧아진다**: 820pt → 762pt(−7.1%). 폭·창 크기·카메라 프리셋·
  크롭 식은 그대로이므로 **세로 화각은 같고 가로가 넓어진다**(three.js는 세로 fov 고정).
- 캡처 파일은 P27b와 같은 2234×1640px이고, **상단 115px이 인포바**다.

**왜 그대로 뒀나 — 대안 3종이 다 막혔다**
1. 화면 좌표 클릭(System Events) — **osascript에 보조 접근 권한이 없다**(오류 −25211).
2. AppleScript로 페이지 JS 실행 — Chrome의 「Apple Events의 자바스크립트 허용」이 **off**.
3. 창을 58pt 키워 뷰포트를 되돌리기 — **`bounds` 설정이 먹지 않는다**(값이 그대로 돌아온다).

**해소 경로(사용자 1회 조치)**: 시스템 설정 > 개인정보 보호 및 보안 > **손쉬운 사용**에서
`osascript`(또는 터미널)를 허용 ⟹ 인포바 없는 «평범한» 탭에서 버튼을 눌러 재촬영할 수 있다
(드라이버는 저장소 밖 임시 파일로 이미 있다 · 코드 0줄 유지).

## §6 등재만 (구현 금지)

1. **P27b 실패의 뿌리 = 경로 선택** — P27b는 `?autofit=1&newcore=1`(v1 라이브 경로)로 찍었다.
   그 경로에는 **착장 상태기계가 없고**, 제품 축 P 계열의 9채널·DONE은 전부
   `?patterncore=1` 경로의 것이다. **촬영 프롬프트가 URL을 지정하지 않으면 재발한다.**
2. **품이 촬영 조건에서 빠지면 BLOCK을 못 본다** — 가슴 129의 BLOCK 하한 품은 58.5cm.
   후보: 몸 치수만 적힌 촬영 판에서 CC가 `checkGarmentFit`을 먼저 인쇄하고 시작한다(배선 0).
3. **`capture.ts`는 버튼을 못 누른다** — 착장 완료 화면이 필요한 회차마다 손 경로가 된다.
   후보: `?dressnow=1` 같은 자동 클릭 파라미터. **이번 변수가 아니다**(코드 0줄 판).
4. **인포바 편차**(§4) — 해소는 권한 1건.
