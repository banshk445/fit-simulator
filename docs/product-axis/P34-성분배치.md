## §1 규칙 — **성분별 개별 배치** (문턱 0)

### §1-1 채택한 규칙과 그 근거

종전에는 후보 화소 **전량의 단일 bbox 하나**를 옮겼다(`:155-184`). 그래서 목 리브/
라벨 69px이 프린트 본체 866px과 한 상자에 묶여 상단을 끌어올렸다(P33 §1-3).

**채택**: 성분을 하나로 묶지 않고 **각 성분을 자기 상대 자리에 개별 배치**한다.

```
for (part of parts)                       // 경계에 안 닿는 8-연결 성분 각각
  destW = panelW      × (part.w / gr.w)
  destH = destW ÷ (part.w / part.h)       // 성분별 종횡비 보존
  destX = panelW      × ((part.x − gr.x) / gr.w)
  destY = OUTPUT_SIZE × ((part.y − gr.y) / gr.h)
```

**문턱 0인 이유**: 성분을 «고르지» 않는다. 「최대 성분만」·「면적비 N% 이상」 같은
**선택 규칙이 아예 없으므로 새 눈대중 문턱도, 그 문턱의 반례도 생기지 않는다.**
P33 §6이 적은 반례(가슴 + 소매 프린트)는 **둘 다 제자리로 가는 것**이 정답인데,
개별 배치가 정확히 그렇게 한다(§2 프로브 ⑤에서 실측).

**재사용한 것 — 새 규칙 0**:
- 8-연결 성분 분리 기계: 78회차 재스캔 G2′(`:199-245`)가 **이미 계산하던 것**.
- 집합 정의: **「프레임 경계에 닿는 성분 제외」** — G2′가 쓰던 규칙 그대로.
  배경은 정의상 경계에 닿는다는 78회차 근거를 그대로 승계한다.

### §1-2 구조 확인 — 가능한가

| 확인 항목 | 결과 |
|---|---|
| 성분 분리 기계 존재 | **있다**(`:199-245`) — 종전에는 문턱 발동 시에만 돌았다 |
| `findPrintBoundingBox` 외부 계약 | **모듈 내부 함수**(export 아님 · 호출부 1곳) ⟹ 반환 형태를 `{box, parts}`로 넓혀도 밖이 안 흔들린다 |
| `box` 산출 경로 | **비트 동일 유지** — 성분 분리를 항상 돌리되 `box`를 내는 분기 순서는 그대로 |
| `onRescan` 판별자 의미 | **보존** — 1패스 통과 시 발화 0(「재스캔 미실행」의 뜻을 P34가 안 바꾼다) |
| v1 · `?autofit=1` · 크롭 실패 | `garmentRegion` 없음 ⟹ **상수 폴백 그대로**(계산 비트 동일) |

### §1-3 비용

`drawImage` 호출이 성분 수만큼 는다. **실측**: 실사용 23성분에서 합성 **18.2ms**,
성분 1개인 프로브가 23.3~30.1ms. **성분 수가 비용을 지배하지 않는다**(스캔·대표색
산출이 지배적). 프레임당이 아니라 **업로드당 1회**다.

### §1-4 잡음 성분이 흩어진 경우 — 미리 적는다

수십 px 잡음이 옷 전역에 있으면 **원본과 같은 자리에 그대로 찍힌다**. 개별 배치의
정의상 그렇고, **원본과 같아 보이는 것이 기대값**이다(종전 단일 bbox는 잡음 하나가
상자를 프레임 전체로 키워 프린트를 통째로 버리게 만들었다 — 그 실패가 사라진다).
실사용 23성분 중 21개가 잡음/프린트 조각인데 전부 제자리로 갔다(§2).
