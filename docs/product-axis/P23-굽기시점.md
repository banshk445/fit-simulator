## §1 잔차 판정이 놓치던 것 — **값으로 확인한 뒤 고쳤다**

### §1-1 종전 판정은 무엇을 보는가 — **스케일 lerp의 목표 대비 편차 하나**

`Mannequin.tsx`의 스케일 루프가 `mannequinPoseRef.maxScaleResidual`에
`max |현재 − 목표|`를 쓴다. 순회 대상은 **전체 키 배율 + 팔·다리·어깨 본 스케일 +
몸통 둘레 본 + 상쇄 본**이다. 그리고 `bodyReady`(P17)와 `run()`의 `settled`는
`frames ≥ 1 && maxScaleResidual ≤ POSE_SETTLE_EPS` 하나만 본다.

**몸 스냅샷이 실제로 읽는 값은 그 안에 없다.** `bodySnapshot`은
`getWorldPosition`으로 **어깨·팔꿈치·손의 월드 좌표**를 뜬다 — 스케일 배율이 아니라
그 배율과 A포즈 회전이 합성된 결과다. **팔 관절은 판정에 빠져 있었다.**

### §1-2 그래서 얼마나 이른가 — 추이 실측(0.5초 간격)

```
경과ms  frames  스케일잔차   팔 이동량(m)  스케일정지프레임
    0       0   Infinity     Infinity      0
  751       2   1.77e-8      1.27e-7       0   ← 종전 판정은 **여기서** 통과한다

 …(17초까지)   1.33e-15     1.1e-16~4.4e-16  0
```

**두 가지가 동시에 드러났다.**

① **잔차는 0으로 가지 않는다 — 1.33e-15에서 평탄해진다.** lerp는 고정점에 닿으면
`lerp(a, target, t) === a`가 되어 **값이 멎지만** 목표와의 편차는 남는다.
⟹ 「멎었는가」는 잔차 문턱으로 판정할 수 없다. **문턱이 아니라 「변화량 0」이 답이다.**

② **종전 판정 통과(0.75s)와 고정점(3.3s) 사이가 2.5초다.** 그 사이에 구우면 몸 메시가
실행마다 다르다 — P22 §2-4의 「1.5s 프로토콜 1/3 · 15s 3/3」이 정확히 이 구간이다.

③ **팔 이동량은 끝내 0이 되지 않는다.** 1.1e-16~4.4e-16 m(= y≈1.2m에서 **1 ULP**)로
영구 진동한다. A포즈 루프(`pointBoneTowardWorldDirection`)가 **매 프레임 현재 월드
행렬에서 방향을 다시 떠서** 회전을 다시 맞추는 되먹임이라 고정점이 없다.
`armStillFrames`는 17초 동안 **한 번도 0을 벗어나지 않았다.**

### §1-3 수리 — 「굽어도 되는 시점」의 정의를 바꾼다

```ts
export function poseStopped(eps = POSE_SETTLE_EPS): boolean {
  return mannequinPoseRef.scaleStillFrames >= 1 && mannequinPoseRef.maxArmDeltaM <= eps;
}
```

- **스케일**: 프레임 간 **비트 동일**을 요구한다 — **문턱 없음**(위 ①이 이유).
- **팔 포즈**: 기존 `POSE_SETTLE_EPS`를 그대로 쓴다(§1 조항 「재사용」). 위 ③ 때문에
  «멎음»을 요구할 수 없다 — 요구하면 영원히 안 끝난다(갈래 D). **값은 안 바꿨다.**
- `bodyReady`(P17)와 `awaitMannequinSettled`가 둘 다 이 함수를 통과해야 한다.
- **상한**: `POSE_STOP_TIMEOUT_MS = 5000`. `awaitMannequinSettled`가 **이미 쓰던 5000ms**에
  이름을 붙인 것이다 — **새 값 0**. 상한에 걸리면 경고를 찍고 그대로 굽는다(함정 25).
- 실행마다 `[dress·P23] 굽기 — 대기 …ms · 멎음 예/아니오 …` 를 남긴다.

**새 상수 0 · 새 문턱 0 · `POSE_SETTLE_EPS` 값 무수정 · 물리 0줄.**

### §1-4 `bodyReady`의 뜻이 바뀐 결과

버튼이 켜지는 시점이 **약 0.8s → 약 3.6s**로 늦어진다(§2 실측 3607~4001ms).
그 대가로 **같은 슬라이더 = 같은 결과**가 된다(반팔·긴팔). 폴링 주기는 400ms → 100ms로
좁혀 지연이 판정 자체보다 커지지 않게 했다.

## §5 등재 — 남은 한계

1. **팔 포즈는 비트 결정적이 되지 않는다.** A포즈 루프의 되먹임 구조 때문이고
   대기로는 해소 불가(실측 17초 · `armStillFrames` 0 · 하한 1 ULP).
   ⟹ **밴드 on 경로의 비결정성은 이 구조를 바꾸지 않는 한 남는다.**
2. **기준선 B-2의 지위 갱신**: P22 §5가 「경계에서 멀다는 우연」으로 적었는데,
   이 판 이후 밴드 0은 **몸 입력이 비트 동일**이라 우연이 아니다.
   다만 **팔 채널이 흡수되는 것**은 여전히 경계 의존이다 — 완전한 구조적 안전은 아니다.
3. **버튼 지연 약 3.6초**(§1-4). 화면에는 「마네킹 불러오는 중」이 그동안 뜬다.
4. **밴드 0 착장 실패**(P22 §7-2)는 이 판 6회에서 재현되지 않았다 —
   **해소 단정 0**. 재현 조건을 잡지 않았다.
