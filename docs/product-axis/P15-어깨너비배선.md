## §0 결론

```
① 옷 어깨너비 슬라이더는 **이미 제도까지 도달한다**  — 회차 전제(「마지막 미배선」)가 거짓
② 진짜 결함은 배선이 아니라 **하한 클램프**   — 몸 어깨 45cm에서 옷 30~38cm 구간이 죽어 있었다
③ 클램프 폭은 **몸을 따라 움직인다**          — 몸 35/45/55cm → 하한 32.6/38.0/43.4cm(최대 33.5% 사장)
④ 상한도 있다                                  — 옷 55cm는 DONE, **62·70cm는 착장 실패**(S1 예산 초과)
```

**처방은 UI 3건뿐이다**(라벨 2 + 클램프 고지 1). 물리·제도·배선은 한 줄도 안 바꿨다.

## §1 전제 확인 — **P3 §4-2의 사유는 유효하지 않다. 다른 이유로 유효하다**

### §1-1 배선 경로 (코드 사실)

```
슬라이더 garmentSize.shoulderWidth
  → bodySnapshot.bakeBodySnapshot : computeShoulderPin(L, R, shoulderWidth/100/2)
  → fixture.pose.pinLeft / pinRight
  → patternDressCore.garment()   : shoulderWidthM = |pinLeft.x − pinRight.x|
  → patternDraft                 : shoulderHalfM = shoulderWidthM / 2  → 어깨선·암홀·몸판 테이퍼
```

**끊긴 데가 없다.** 슬라이더는 **핀을 통해** 제도에 도달한다.
`DressButton`이 `shoulderWidthM`을 `garmentDims`로 «넘기지 않는» 것은 맞지만,
그건 **넘길 필요가 없어서**다 — 라이브 스냅샷 경로에서는 핀이 이미 슬라이더에서 나온다.
(넘기지 않는 것이 의미를 갖는 곳은 **커밋 fixture 폴백 경로** 하나뿐이고, 그 경로는
몸 슬라이더도 반영하지 않는 회귀 대조용이다.)

### §1-2 실측 — 슬라이더가 제도를 움직인다

계기 신설 1건(`[patternPreview·P15]` · 인쇄 전용). 착장을 돌리지 않아도 슬라이더 즉시 반영.

| 옷 어깨너비 슬라이더 | 핀 간격 | **제도 어깨너비** | 어깨선 | 어깨경사 |
|---|---|---|---|---|
| 30cm | **37.9930cm** | **37.99cm** | 11.07cm | 10.9° |
| 38cm | 37.9996cm | 38.00cm | 11.08cm | 10.9° |
| 45cm (기본) | 44.9995cm | 45.00cm | 14.64cm | 10.9° |
| 55cm | 54.9994cm | 55.00cm | 19.73cm | 10.9° |
| 70cm | 69.9992cm | 70.00cm | 27.36cm | 10.9° |

38cm 이상에서는 **슬라이더 그대로 따라간다**. 30cm만 37.99로 삼켜진다.

### §1-3 「44.9995cm」의 정체 — **fixture 때문이 아니다**

P3 §4-2는 44.9995를 「커밋 fixture 포즈의 값」으로 봤다. **라이브 몸에서도 44.9995다.**
원인은 fixture가 아니라 **기하**다: `computeShoulderPin`이 핀을 «중심→관절» 방향으로 미는데
그 방향에 y·z 성분이 있어 **x 투영에서 cos만큼 준다**(cos ≈ 0.9999889 · 각도 ≈ 0.27°).
45.0000 − 44.9995 = **0.0005cm = 5µm**. 어느 채널에도 안 잡힌다.

⟹ 회차 배경의 「P5b가 0.45000을 실측했다」는 **반올림 인쇄**였고, 44.9995는 살아 있다.
다만 **P3의 판단(배선하면 오염된다)은 이 값 때문에 성립하지 않는다** — 배선은 이미 돼 있고
5µm은 오염이 아니다.

### §1-4 **진짜 결함 — 하한 클램프**

`computeShoulderPin`:

```
floor = |center − joint| + PIN_MIN_CLEARANCE(1cm)     ⟹ 어깨너비 하한 = 관절 간격 + 2cm
halfWidth = Math.max(garmentHalfWidthM, floor)         ⟹ 그보다 좁은 입력은 «조용히» 삼켜진다
```

**몸에 따라 움직인다**(실측):

| 몸 어깨너비 | 어깨 관절 간격 | **옷 어깨너비 하한** | 죽은 구간(슬라이더 30~) | 슬라이더 범위(40cm) 대비 |
|---|---|---|---|---|
| 35cm | 30.62cm | **32.62cm** | 30 ~ 32.6 | 6.6% |
| **45cm (기본)** | 35.99cm | **37.99cm** | 30 ~ 38.0 | **20.0%** |
| 55cm | 41.36cm | **43.36cm** | 30 ~ 43.4 | **33.5%** |

**클램프 자체는 결함이 아니다** — 어깨 핀이 몸 어깨 관절 «안»으로 들어가면 안 된다는
물리적 제약이고 그 상수(1cm)에 근거가 붙어 있다. **결함은 그것이 «조용»했다는 것**이다.

### §1-5 기준선 예측 — **깨지지 않는다**

배선할 것이 없으므로(§1-1) 제도·물리에 들어갈 변경이 0이다. ⟹ 기준선 B-2 불변 예측.
**§3에서 실측으로 확인했다.** P3의 판단을 뒤집을 근거가 없으므로 **뒤집지 않는다** —
P3이 미룬 「배선」은 애초에 필요 없었고, P3이 걱정한 오염도 나지 않는다.

## §2 처분 — **UI 3건 · 물리 0줄**

| # | 항목 | 처분 |
|---|---|---|
| 1 | **라벨 겹침** — 몸·옷 둘 다 「어깨너비」 | **「어깨너비(몸)」 / 「어깨너비(옷)」**로 갈랐다. 값·범위·배선 불변 |
| 2 | **규약** | 어깨너비는 **반둘레가 아니다** — 품(55cm = 반둘레)·소매통과 달리 **어깨점 사이 직선 거리 전체**다(`patternDraft.ts` `shoulderWidthM` 주석이 이미 그렇게 적고 있다). 45cm = 어깨점 간격 45cm. 코드 주석에 명기했고 이 문서가 정본이다 |
| 3 | **클램프 고지** | 입력이 하한에 걸리면 슬라이더 아래에 **「실제 적용 XX.Xcm — 이보다 좁게는 못 준다(어깨 관절 + 여유 1cm). 더 좁히려면 «어깨너비(몸)»을 줄이세요.」** 를 띄운다. 하한은 `PIN_MIN_CLEARANCE`를 **export해서 같은 상수에서 도출**한다(같은 수를 두 번 적지 않는다 · 함정 12). **이미 일어나던 일을 보이게 할 뿐 — 물리 0줄** |

`PIN_MIN_CLEARANCE`는 **값·용법 불변**이고 `export`만 붙였다. v1 경로도 같은 클램프를
쓰므로(`Garment.tsx`가 같은 함수를 부른다) 이 고지는 v1에서도 사실이다.

### §3-3 착장 실패 — **상한이 있다**

```
55cm  DONE f=260
62cm  **착장 실패 — S1 f=1314: S1 예산 초과(seamGap 7.3mm)**   (S3 f=690까지 갔다가 RETRY 후 실패)
```

**크래시 0 · P4 §3 실패 표시 정상 동작**(붉은 문구로 사유가 뜬다).
**상한은 55 ≤ x < 62 사이**이고 **더 좁히지 않았다** — 문턱 사냥은 이 판의 범위 밖이다.
슬라이더 최대 70cm는 **기본 몸에서 착장 불가**라는 사실만 등재한다.

### §3-4 몸 ↔ 옷 동시 이동 — **충돌한다(하한을 통해)**

```
몸 어깨너비 55cm + 옷 어깨너비 38cm  →  화면 고지 「실제 적용 43.4cm」  →  DONE f=270
   cov 5.2% · 자기교차 1732 · 관통 78/5204 · 밑단 110.78cm · 목선 링 60.19cm
```

둘은 **하한을 통해서만** 상호작용한다: 몸이 넓어지면 옷의 하한이 올라가 옷 입력을 삼킨다.
그 삼킴이 이제 **화면에 뜬다**(§2-3). 다른 충돌 경로는 없다(몸판 반폭 등은 무관).

## §5 다음 판이 이어받을 것

1. **어깨너비 슬라이더 범위** — 하한 30cm는 몸에 따라 6.6~33.5%가 사장되고, 상한 70cm는
   **기본 몸에서 착장 불가**다. 범위를 몸에서 도출할지(하한 = 관절+2cm), 아니면 고지로 충분한지 —
   **이 판은 고지만 했다.** 범위를 손대면 v1 슬라이더도 같이 움직인다.
2. **착장 상한의 자리** — 55 ≤ x < 62. 실패는 `S1 예산 초과`(봉합이 안 닫힌다)이고
   **원인 귀속은 안 했다**.
3. 커프 밴드 · fixture 재생성 · 캡 높이 붕괴 — 전부 이월.
