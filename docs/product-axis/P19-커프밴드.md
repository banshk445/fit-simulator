## §1 소매 배치 일반화 — **항등** (P18 §4-8 해소)

종전 배치는 리터럴 두 벌이었다:
`[[SLEEVE_R, armPlus, +1], [SLEEVE_L, armMinus, −1]]` — **소매가 정확히 2매**라는 전제.

**장착 표**로 옮겼다:

```ts
const sleeveMounts: { panel: number; arm: PatternArm; flipSign: number }[] = [...];
for (const { panel, arm, flipSign } of sleeveMounts) { …기존 코드 그대로… }
```

소매 역할 패널이 몇 매든(밴드 포함) **같은 코드로** 감긴다. 티셔츠 표는 종전과
같은 순서·같은 값이라 **비트 동일**이다.

**게이트(커밋 `598cf86`)**: 하네스 938줄 쌍 diff **0줄** · `dress-state` md5 불변 ·
`patternHash 9f7ba80b3497` **불변** · 반팔 B-2 · 긴팔 P13 값 일치 · v1 게이트 4종 ·
`check:pattern`/`boundary`/`outline`/`topology` · tsc · build.

⟹ **P18 §4 표의 8번을 지운다.** 남은 티셔츠 전제는 **9곳**(§6).

## §2 밴드 패널 신설 — 도출과 결정

### §2-1 실행 «전»에 정한 것

| 항목 | 결정 | 근거 |
|---|---|---|
| **둘레** | **소맷부리 둘레 그대로**(P13 도출식) | 새 상수 0. 밴드는 소맷부리에 붙는 띠이므로 둘레가 같아야 한다 |
| **높이(밴드 폭)** | **슬라이더 「커프 밴드」 · 기본 0 · 범위 0~10cm** | **도출을 못 찾았다.** 저장소에 밴드 «높이»의 근거가 될 실측이 없다 — 손목 둘레(P11)도 소매통도 높이를 주지 못한다. 회차 조항대로 **상수로 박지 않고 치수로 낸다** |
| **총 소매길이 규약** | 밴드는 소매길이 **«안»에 든다** — 원통이 `sleeveLength − band`까지 가고 밴드가 그 아래를 채운다 | 슬라이더 「소매길이 22cm」의 뜻이 안 바뀐다(어깨~소맷부리 끝). **UI 라벨 변경 불필요** |
| **이중층** | **하지 않는다**(단층 밴드) | 접힘은 양안정이라 물리로 강제할 층이 따로 필요하고 위상이 한 단계 더 복잡해진다. 「소맷부리가 마감된다」는 목적은 단층으로 달성된다 |
| **시접** | 기존 규칙 재사용(`SEAM_REST_LENGTH` 6.00mm · `limitStrain` 1.2) | **새 문턱 0** |

### §2-2 만든 것

- **제도**: `PanelName.cuff` 패널 1매(윗변·좌변·아랫변·우변 4세그먼트).
  `SeamSpec.kind = "cuff"` 시접 **2벌** — ① 소매 소맷부리 ↔ 밴드 윗변 ② 밴드 통 닫기(우변↔좌변).
  (P18이 값만 넣어두고 아무도 안 만들던 자리를 채웠다.)
- **조립**: 밴드 좌우 한 벌 → 패널 **6매**, 역할 `[torsoFront, torsoBack, sleeve×4]`.
  미러 표에 `4↔5` 한 벌 추가. 이름 맵에 `cuff → 패널 5`.
- **배치**: **새 코드 0줄** — §1의 장착 표에 두 줄을 더한 것이 전부다.
- **치수**: `cuffYM`(소맷부리 패턴 y)를 dims에 실었다. 밴드가 없으면 `sleeveLengthM`과 같다.

실측 확인(슬라이더 5cm · 반팔):

```
소맷부리 반폭 17.43cm(둘레 34.87) · cuffY 17.00cm(소매길이 22.00 − 밴드 5.00)
정점 5204 → 5258 · 시접 240 → 288쌍 · 종류별 {shoulder 38, side 62, armhole 124, sleeveUnder 10, cuff 54}
```

**밴드는 실제로 만들어진다.**

### §2-3 **착장 실패 — 값과 자리**

| 조건 | 결과 |
|---|---|
| 반팔 · 밴드 **5cm** | **착장 실패 — S1 f=1247: S1 정체(seamGap 9.7mm, 60프레임 무개선)** (RETRY 1회 후) |
| 반팔 · 밴드 **2cm** | **착장 실패 — S1 f=1138: S1 정체(seamGap 9.9mm, 60프레임 무개선)** |
| 반팔 · 밴드 **0(기본)** | **DONE f=292** · 기준선 B-2 전량 일치 |

**크기 의존이 아니다** — 2cm와 5cm가 같은 시그니처다. **구조적**이다.
크래시 0 · P4 실패 표시 정상(붉은 문구로 사유가 뜬다).

**진단 1건(계기 신설)** — 배치 시점 시접 갭을 종류별로 인쇄한다
(`[patternPreview·P19]` · 인쇄 전용 · 물리 0줄):

```
밴드 off  shoulder 38쌍 31.0cm · side 62쌍 31.0cm · armhole 124쌍 5.1~21.2cm · sleeveUnder 16쌍 2.0~2.2cm
밴드 5cm  … sleeveUnder 10쌍 2.0~2.1cm · **cuff 54쌍 0.0~22.2cm**
```

- `0.0cm` = 소매 소맷부리 ↔ 밴드 윗변 — **겹쳐 있다(정상)**
- **`22.2cm` = 밴드 통 닫기 변** — **그만큼 벌어진 채 S1이 시작한다.**
  S1이 9.7~9.9mm에서 멈추는 것과 자리가 맞는다.

**원인 귀속은 하지 않았다.** 22.2cm는 밴드 원통의 지름(11.1cm)보다 **2배 크다** —
한 원통 위의 두 점으로는 나올 수 없는 값이라 **배치 사상이나 시접 짝에 결함이 있다**는
뜻이지만, 어느 쪽인지는 안 봤다(진단 미실시 · §4 「멈추고 보고」 조항).

### §2-4 하네스는 밴드를 **못 본다**(확인함 · 추측 아님)

`check:pattern`·`dress:pattern`은 `garmentDims`를 자기가 만들고 그 안에 `cuffBandM`이
없다 ⟹ **밴드 미발동**. 회차가 예상한 그대로다(P12 §4-1과 같은 계열).
그래서 **밴드 시접을 볼 수 있는 자리는 브라우저 로그뿐**이고, §2-3 계기를 거기에 붙였다.

### §4-1 `dress-state` md5 갱신 — **좌표는 안 바뀌었다**(A/B로 증명)

`14e50b8919a63a7f9799220b86e508a9` → **`2501239ab06a678cd956d73be8e14159`**

md5가 갈려 **그 자리에서 멈추고 원인을 특정했다.** 변경 전/후 파일을 각각 만들어 대조:

```
positions 15,732개  **전량 동일 (True)**
patternHash · fixtureHash · frames · state   전부 동일
garmentDims 외 다른 키 차이                  **없음**
garmentDims  before {lengthM, widthM, shoulderWidthM, sleeveLengthM, sleeveWidthM}
             after  … + **cuffBandM: 0**      ← 갈린 이유는 이 한 항뿐이다
```

⟹ **물리·기하는 비트 동일이고 덤프의 메타 한 항이 늘었다.**
덤프에서 `cuffBandM`을 빼면 md5는 지킬 수 있지만 **덤프가 옷을 완전히 기술하지 못하게** 된다
(밴드를 켠 실행을 덤프만 보고 구분할 수 없다). 그래서 **정본을 갱신한다.**

**부수 사실**: `public/dress-state.json`은 **`.gitignore`에 있다**(추적 대상 아님).
P10~P18이 「git clean」으로 함께 확인해 온 것은 이 파일에는 해당하지 않았다 — md5만 유효한 채널이다.
