## §2 UI 정리 (새 기능 0)

| 항목 | 처리 |
|---|---|
| **경고 문구 중복** | 상단 오버레이와 좌측 패널에 같은 `fit.message`가 두 번 떴다. **오버레이에서 뺐다** — 사유 본문은 좌측 패널(치수를 고치는 자리)이 지고, 오버레이는 짧은 상태만 낸다 |
| **상태 표시 일관화** | 한 곳(`status`)에서 만든다: 대기 「치수를 맞춘 뒤 «착장하기»를 누르세요 (약 15~40초)」 / 진행 「S2 f=150/260」 / 완료 「DONE f=260 · 15.1s」 / 차단 「이 치수로는 착용 불가 — 좌측 안내 참고」 / 실패는 붉은색 |
| **첫 진입 안내** | 위 「대기」 문구가 그 역할을 한다(예전에는 빈 칸이었다) |
| **핏 리포트 stale 방지** | P8에서 이미 처리(실행 시점 슬라이더 서명과 다르면 감춘다). 착장 전에는 「이 치수로 «착장하기»를 누르면 표시됩니다」 |
| **권장값 vs 슬라이더 범위** | **확인 결과 문제 없음 · 조정 불필요.** 품 슬라이더는 35~90cm이고 권장값 최대는 가슴 140cm에서 71.5cm다(차단 최소 63.5cm). 전 범위에서 사용자가 따를 수 있다 |

`Controls.tsx`는 손대지 않았다(배너가 이미 그 자리에 있다).

## §3 배포 — GitHub Pages

### 먼저 고쳐야 했던 것: **프로덕션에 v2가 없었다**

`FitCanvas.tsx`가 `import.meta.env.DEV && query.get("patterncore")==="1"`로 막고 있었고
`PatternPreview`도 DEV 삼항으로 감싸 **프로덕션 번들에서 import 자체가 잘렸다**
(fixture 1.8MB를 dist에서 빼려던 조치). 그러면 데모 URL이 성립하지 않는다.

⟹ 동적 import는 그대로 두고 **마운트만 파라미터로 가른다**. 파라미터 없는 진입은
그 청크를 **받지도 않는다**(코드 분할). 기본 거동 무변경(v1).

부수 효과로 **메인 번들이 작아졌다**: `index` 1,287kB → **560kB**, fixture는 별도 청크
1,789kB(패턴 경로에서만 로드).

### 배포

```
브랜치  gh-pages (orphan · dist/ 내용 + .nojekyll)
URL     https://banshk445.github.io/fit-simulator/
빌드    Pages status = built
```

`vite.config.ts`의 `base: "./"`가 이미 상대 경로라 서브패스 배포에 그대로 맞았다.
