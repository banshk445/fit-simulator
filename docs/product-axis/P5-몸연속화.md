# P5 — 몸 연속화 (몸 추출 모듈 · fixture 정책) — **미완 · 정지**

**기점**: `cdd9abc` (P4)
**상태**: §1 모듈은 섰고 v1·스크립트 회귀는 전부 통과했다. 그러나 **§3의 기본값 회귀가
미충족**이다 — 라이브 몸이 커밋된 fixture와 다르다. **원인은 특정했고 수정도 넣었지만
브라우저 검증을 끝내지 못했다.** §4(슬라이더 5축 표)·§2(정책 확정)는 미착수다.
「거의 같다」로 넘기지 않는다는 조항대로, 완료로 적지 않는다.

## §1 몸 추출 모듈 — 됨

`src/lib/bodySnapshot.ts` 신설(**물리 신규 0줄**). 조각은 전부 이미 `src/lib/`에 있었고
`Garment.tsx`(v1) 안에 있던 **조립 순서만** 옮겼다.

```ts
computeArmShapes(bones, sleeveType, sleeveLengthM): { left, right } | null
bakeBodySnapshot(input, collisionMesh): { fixture: PatternDressFixture; bakeMs; capsuleMs } | null
```

`bakeBodySnapshot`이 하는 일 = v1 `exportCollision`과 **같은 조립**:
`collisionMesh.bake(root)` → 어깨 본 월드좌표 → `computeShoulderPin(…, 옷어깨너비/2)` →
`topY = max(핀 y)` · `layout.centerZ = 핀 z 중점` → `buildTorsoProxyCapsules(어깨L, 어깨R,
키, 가슴)` → `collision.centerZ = proxy.centerZ`. 두 `centerZ`가 서로 다른 출처라는
v1의 구분도 그대로 유지했다.

**v1 항등 추출**: `Garment.tsx`의 `computeArmShapes`는 이제 공유 함수를 부르는 5줄이다.
인자·순서·식 무변경. 스크래치 벡터 2개도 함께 이사했다.

**`exportCollision`의 init/step 의존이 풀렸다**: 포즈와 레이아웃을 워커 메시지 이력이
아니라 **씬에서 직접** 도출하므로, v1 워커가 돌지 않아도(= `?patterncore=1`) 몸을 뜰 수 있다.

**어깨 본 공급**: `Mannequin`이 이미 `nodes`를 갖고 있으므로 거기서 `findShoulderBones`를
불러 `mannequinBonesRef`에 등록한다(같은 결과의 두 번째 출처를 만들지 않는다).

배선: `DressButton`이 클릭 시 스냅샷을 떠서 워커에 넘기고, 워커는 `fixture`가 오면 그것을,
없으면 **커밋된 fixture로 되돌아간다**(회귀 경로 유지 · 제거 0).
`PatternPreview`도 같은 스냅샷을 쓴다 — 안 그러면 정적 배치와 착장 결과의 패턴이 갈려
정점 수까지 달라지고 결과 반영이 거부된다.

### **미충족 — 기본값에서 라이브 몸 ≠ fixture**

슬라이더 기본값(키 170 · 가슴 100 · 팔 60 · 다리 85 · 어깨 45)에서 실측:

| 채널 | 커밋 fixture | 라이브 스냅샷 | 판정 |
|---|---|---|---|
| 몸 정점 수 | 15,882 | 15,882 | 같음 |
| topY | 1.4304 | 1.4304 | 같음 |
| centerZ(layout / collision) | −0.02787 / −0.02787 | −0.02787 / −0.02787 | 같음 |
| 어깨 핀 간격 | 0.45000 | 0.45000 | 같음 |
| 팔 길이 | 0.22 | 0.22 | 같음 |
| **몸 y 범위** | **0.000 ~ 1.700** | **0.004 ~ 1.769** | **다름** |
| **몸 x 범위** | **−0.545 ~ 0.544** | **−0.890 ~ 0.890** | **다름** |
| 결과 패턴 정점 | 5,244 | **5,115** | **다름** |

**포즈·핀·레이아웃은 전부 일치하고 «메시만» 다르다.**

### 원인 특정 (코드)

`Mannequin.tsx`는 두 가지를 **마운트 이후에** 적용한다:
1. **팔 A포즈** — `useFrame` 안에서 `pointBoneTowardWorldDirection(bone, …, (±0.6, −1, 0))`
   (`ENABLE_ARM_SWAY_DEBUG = false` · 고정 0.6). **첫 프레임 전에는 GLTF 원본 T포즈**다.
2. **단위 정규화** — `scene.scale.setScalar(unitScale)`를 effect에서 건다
   (`unitScale = 1.70 / 원본 bbox 높이`).

`PatternPreview`의 굽기는 **마운트 직후 effect**라 이 둘보다 앞선다 ⟹ 구워진 것은
**T포즈·미정규화 몸**이다. 실측이 정확히 그 모양이다: x ±0.890(팔이 수평으로 벌어짐) ·
y 최대 1.769(1.70으로 안 줄어듦).

### 넣은 수정 (미검증)

`mannequinRef.ts`에 `mannequinFramesRef` + `awaitMannequinSettled(minFrames = 2)`를 넣고,
`Mannequin`의 A포즈 `useFrame`이 매 프레임 카운터를 올리게 했다. `PatternPreview`는
굽기 전에 그것을 기다리고, `DressButton`은 가드만 둔다(클릭 시점이면 이미 지났다).

**이 수정이 실제로 fixture와 일치시키는지 확인하지 못했다.** 브라우저 검증이 아래 §7의
환경 문제로 막혔다.

## §2 재굽기 비용 — 1점만 실측 · 정책 미확정

`collisionMesh.bake(root)` **125ms**(1회 · 정점 15,882). 착장 ~20~60s 대비 **0.2~0.6%**다.
이 수치대로면 「착장 시 매번 굽는다」가 타당하다 — 캐시가 필요 없다.

**다만 이 125ms는 §3에서 문제가 된 «정착 전» 굽기의 값**이라 재측정이 필요하고,
`StaticGeometryGenerator` 인스턴스 재사용 시의 2회차 비용도 안 쟀다. **정책을 확정하지
않는다**(프롬프트: 추측으로 정하지 말고 재고 정한다).

## §4 슬라이더 5축 동작 표 — **미착수**

§3의 기본값 회귀가 안 닫힌 상태에서 5축 표를 내면 「무엇에 대한 변화인지」가 정의되지
않는다. 회귀가 닫힌 뒤에 잰다.

P3 §2가 등재한 「몸이 옷을 뚫는」 화면의 해소 여부도 같은 이유로 미확인이다.
**P4의 임시 배지는 코드에서 걷어냈다** — §3이 안 닫힌 지금은 그것이 **이르다**.
다음 판이 회귀를 닫거나, 닫지 못하면 배지를 되살려야 한다.

## §5 `CHEST_PERIMETER_RATIO` — **출처 특정 완료**(실측 나란히 내기는 미완)

두 값이 1.421배 어긋나는 이유는 **같은 몸을 다른 방식으로 재기 때문**이고, 코드에서 확정된다:

| 계기 | 방법 | 성격 |
|---|---|---|
| `bodyMeasure.girthOfSlice` (→ `chestGirthM` 84.01cm) | 각도 bin마다 축에서 **가장 가까운** 표면점을 고르고(`if (d < bestR[b])`) 그 점들의 볼록껍질 둘레 | **안쪽 포락선** — 팔이 붙어 있어도 몸통 표면을 잡는다 |
| `garmentFitLimits` (→ 119.4cm) | 어깨선 아래 10~25cm 슬랩의 **XZ convex hull 둘레 최댓값**(팔 제외는 슬랩 내 최대 빈틈) | **바깥 포락선** — 어깨·겨드랑이 바깥 윤곽을 포함한다 |

⟹ **103 계기 결함 ②(같은 가슴둘레를 84.01 ↔ 119.4로 잰다)의 정체는 「최근접 bin 포락선
vs 볼록껍질」이다.** 둘 다 자기 목적에는 맞는 값이고 어느 쪽이 틀린 것이 아니다 —
**같은 이름(`가슴둘레`)으로 부른 것이 결함**이다(함정 13 계열).

프롬프트대로 **상수는 바꾸지 않았다.** 재도출은 게이트 문턱이 움직이는 별도 판이다.

## §7 이 판을 막은 환경 문제 (등재)

1. **R3F 캔버스 크기 측정 실패** — 페이지 로드 후 `<canvas>`가 300×150(기본값)에 머물고
   Canvas 자식이 아예 렌더되지 않는다. **P5 코드와 무관하다**: 변경분을 전부 stash하고
   dev 서버를 재시작하고 새 탭에서 열어도 재현됐다. `window.dispatchEvent(new Event('resize'))`
   한 번이면 972×819로 정상화된다. 브라우저 검증 시 **로드 후 resize를 한 번 쏠 것**.
2. **캡처 PNG 65개가 작업 트리에서 지워져 있었다**(13:30 · 같은 폴더에 `.DS_Store` 생성).
   저장소 코드와 무관한 외부 요인으로 보이며 `git checkout -- docs/`로 전량 복구했다.
   **커밋된 것은 손상되지 않았다.**
