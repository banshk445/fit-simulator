## §2 수리 — **굽기 직전에 기다린다**(sticky는 그대로 둔다)

```ts
if (!poseStopped()) {
  setNote("포즈 정착 대기 중…");
  const r = await awaitMannequinSettled();     // 상한 POSE_STOP_TIMEOUT_MS 재사용
  if (!r.ok) console.warn("[dress·P25] 굽기 전 대기가 상한 도달 … 그대로 굽는다");
  setNote("착장 중…");
}
```

### §2-1 `bodyReady`를 non-sticky로 만들지 «않은» 이유

1. **슬라이더는 드래그다.** non-sticky면 값이 바뀌는 내내 버튼이 꺼져 조작이 끊긴다.
   재고정이 4.6~5.0초(P24 §3-5)라 한 번 만질 때마다 5초씩 잠긴다.
2. **`bodyReady`의 뜻은 「마네킹이 왔는가」**(P17 §2)이고 「멎었는가」는 다른 축이다.
   한 상태에 두 뜻을 얹으면 이름과 실제가 어긋난다(함정 13 계열).
3. **대기가 필요한 자리는 굽기 직전 한 곳뿐**이다. 여기 두면 진입점이 하나여서 누락이 없다
   (P20·P21의 「여러 자리 중 하나를 빠뜨림」 실패를 구조로 피한다).

**새 상수 0** — 상한은 `POSE_STOP_TIMEOUT_MS`(5000ms) 그대로.

### §2-2 대기 중 화면

버튼은 `busy`로 비활성이 되고 옆 문구가 **「포즈 정착 대기 중…」** 으로 바뀐다.
그 뒤 「착장 중…」으로 넘어간다. 실측으로 확인했다(§3-1 첫 실행).

### §3-2 원인 — 스케일 lerp가 **비정수 target에서 고정점이 없다**

**`scaleStillFrames`가 96까지 올랐다가 7로 떨어지고 4~17을 오간다. 안 멎는다.**

기전: `lerp(a, target, t)`의 `t = 1 − 0.001^delta`는 **프레임 delta에 의존**한다.
고정점 근방에서 `(target − a)·t`가 `ulp(a)/2` 경계에 걸치면, delta가 큰 프레임에서는 `a`가
1 ULP 움직이고 작은 프레임에서는 안 움직인다.
**target이 1.0(기본값)이면** `a`가 1.0에 «정확히» 도달해 `target − a = 0`이 되어 완전히 멎지만,
**target이 1.1처럼 이진수로 정확히 표현되지 않는 값이면** 영원히 1 ULP 진동한다.

⟹ **P23·P24가 얻은 「스케일 비트 동일」은 기본값(배율이 정확히 1.0)에서만 성립한다.**
`poseStopped()`가 통과하는 «순간»이 실행마다 달라지고, 그 순간의 몸 메시가 다르다.
콘솔에도 그대로 찍힌다 — `A포즈 고정 → 해제 → 고정(정지 1프레임)`이 반복 발화한다.
