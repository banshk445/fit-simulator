## §1 설계 — 실행 «전» 확정분과 그 근거

### §1-1 폴백 확인이 «설계를 바꿨다» (프롬프트 지시 순서대로 먼저 확인)

지시: 「`cropToGarmentRegion` 실패 폴백에서 이 상대 좌표가 어떻게 되는지 먼저
확인한다」. 확인 결과 **전제가 틀렸다** — 폴백이 하나가 아니다.

`cropToGarmentRegion`은 **10개 반환 지점 중 9개가 `URL.createObjectURL(file)`**,
즉 원본 URL 문자열이다. 호출자는 그 문자열만으로 다음 셋을 **구분할 수 없다**:

| 반환 지점 | 성격 | 프레임이 곧 옷인가 |
|---|---|---|
| `:114` `fullW<4` · `:150` ctx 없음 · `:158` 캔버스 오염 · `:208` 빈 이미지 · `:259` 전경 못 찾음 · `:333` 너무 작게 잘림 · `:363` octx 없음 · `:386` blob 없음 | **분석 실패** | ✗ (상대 좌표 무의미) |
| `:263-265` `FULL_FRAME_SKIP_FRACTION 0.92` 초과 — 「플랫레이류, 자를 필요 없음」 | **성공(자를 게 없음)** | **✓** (전경 bbox = 옷) |
| `:396-398` 크롭 성공 | **성공** | ✓ (단 **패딩 4% 포함**) |

⟹ 「크롭 실패 = 상수 폴백」이라는 이분법으로는 **플랫레이 경로를 잘못 버린다**.
그래서 계약을 **`{url, garment}`** 로 넓혔다 — `garment`는 **출력 프레임 안에서
옷이 차지하는 픽셀 박스**이고, `null`이 곧 「상대 좌표를 낼 근거 없음」이다.
**`url` 값 자체는 종전과 동일**하다(거동 변화 0인 채로 사실만 내보낸다).

또 하나: 크롭 출력은 옷 박스 **+ `PADDING_FRACTION` 4%**다. 프레임 기준으로
상대 좌표를 내면 그만큼 어긋나므로(70cm 패널에서 약 2.6cm — 목표 ±2cm를 넘는다)
**옷 박스를 출력 원점 기준으로 환산해 함께 낸다**. 새 상수 0.

### §1-2 배치식 — 새 상수 0

캔버스 세로 `[0, 512]`가 패널 `v[1, 0]`(어깨선→밑단) 전체이고 가로 `[0, panelW]`가
패널 `u[0, uMax]` 전체다(**P31 §1-2 실측**). 그래서 옷 박스 안 상대 좌표를 그대로
곱하면 같은 자리가 된다.

```
gr = garmentRegion                       (원본 프레임 픽셀)
destW = panelW      × (printBox.w / gr.w)
destH = destW ÷ 원본종횡비                (종횡비 보존 — 종전과 같다)
destX = panelW      × ((printBox.x − gr.x) / gr.w)
destY = OUTPUT_SIZE × ((printBox.y − gr.y) / gr.h)
```

### §1-3 눈대중 상수 2개 = **폴백 전용으로 강등**(삭제 0)

`PRINT_WIDTH_FRACTION 0.45` · `PRINT_TOP_FRACTION 0.25`는 `garmentRegion`이
없을 때만 쓰인다. 소비자 3종이 그 경로에 남는다: **v1 `Garment.tsx:341`**(opts
미전달 ⟹ **계산 종전과 비트 동일**) · `?autofit=1`(`useFitStore.ts:224`) ·
크롭 분석 실패.

**폴백 클램프 + 고지**(P15 선례): `destH`에 상한이 없어 종횡비 0.5면 밑단 3cm
앞까지 내려간다(P31 §2-3). 캔버스 하단 초과 시 **종횡비를 지킨 채 폭도 같은 배율로
축소**하고 `console.warn`으로 축소 전/후 값을 남긴다 — 조용히 자르지 않는다.

### §1-4 알려진 한계 (설계 단계에서 명기)

옷 박스는 사진 속 옷의 **외곽**이라 반팔이면 **소매를 포함**한다. 앞판 패널 폭(품)
보다 넓으므로 **가로** 상대 크기는 그만큼 작게 잡힌다. 세로에는 영향이 없고(총장
대 총장), 중앙 배치 로고는 중앙에 남는다. 이 판에서 보정하지 않는다.

### §2-2 프로브 ③(y=580)이 «검출 층»에서 탈락한다 — 2/2 재현

원래 등록한 ③(밑단 근처 y=580)은 프린트가 **아예 안 그려졌다**.

```
대표색 rgb(30, 30, 60)  ← 원단(200,200,200)이 아니라 «배경»이다
프린트 bbox 479×678px · 프레임 비율 92.2% × 92.2%
PRINT_MAX_FRAME_FRACTION **발동**(프린트 버림)
```

**기전**(값으로 특정 · 반증 실험 통과): 크롭 출력은 옷 + 패딩 4%라
`borderRepresentativeColor`의 **테두리 띠 8%**(`BORDER_BAND_FRACTION`)에 배경과
원단이 **거의 반반** 들어온다(산식: 배경 ≈ 55.6k px vs 원단 ≈ 57.8k px = **51:49**).
프린트가 그 띠 안으로 들어오면 원단 픽셀을 그만큼 빼앗아 **최빈값이 배경으로
뒤집힌다**. 그러면 옷 전체가 「원단과 다른 색」 = 프린트로 잡혀 92.2%가 되고
문턱이 발동해 프린트가 버려진다.

**반증 실험**: 블록을 띠 밖으로만 올린 y=520은 **정상 통과**(§2-1 ③′).
y=580은 **2/2 재현**. ⟹ 「띠 진입」이 원인이라는 것이 값으로 확정된다.

**이것은 P32가 만든 것이 아니다** — `borderRepresentativeColor`도 패딩도 손대지
않았고, 합성이 받는 이미지가 종전과 같다. **선재 결함이며 P32가 처음 드러냈다.**

> 실측하지 않았다**(함정 13 계열 · 판독을 실측으로 승격).
> **진짜 자리는 `findPrintBoundingBox`다** — 목 리브/라벨 성분(69px)이 프린트 본체
> (866px)와 **한 bbox로 묶여** 상단을 끌어올린다. 정본은 P33 §1-3.

**무엇을 잡았는가 — 값으로**: `garmentSegmentation.ts:242-268`의 「얼굴/목 피부 구간」
스캔이 **프린트를 얼굴로 오인**한다. 피부 판별자(`:31`)로 원본을 대역별로 재면

| 대역 | 피부 오탐률 |
|---|---|
| y 0~300 (어깨·목) | **0.00%** |
| y 330~780 (**프린트**) | **5.74%** |
| y 800~1000 (밑단) | **0.00%** |

**이미지 전체에서 「피부」는 프린트 안에만 있다**(곰 캐릭터의 갈색 털).
`SKIN_ROW_ENTER_FRACTION 0.4` / `EXIT 0.25`는 **전경 대비 비율**이라 검정 원단
위의 이 오탐이 문턱을 넘고, `garmentTop`이 프린트 직전 행으로 올라간다.

**이 오탐은 저장소가 이미 알고 있었다** — `:270-275` 주석이 「곰 캐릭터 그래픽의
갈색 털이 '피부'로 오탐되는 경우」를 명시하고, 그래서 **좌우 narrowing과
paint-over는 `sawSkinBand`로 막아 뒀다.** 그런데 **`garmentTop` 트리밍만 안 막혀
있다**(`:268`은 「못 찾았으면 안 자른다」일 뿐, 「잘못 찾았으면」은 없다).

화면: `docs/captures/P32-프린트배치/실사용-상대승계-DONE.jpg`
(v2 `?patterncore=1` · DONE f=514 · 49.7s). **판정은 전략 세션 몫**(CC 화면 판정 0).

### §2-4 `uMax` 경합(P31 §5-1)은 **악화되지 않는다**

합성은 여전히 매번 두 번 돌고 첫 판 `uMax=1` · 둘째 판 `0.7857`이며 **마지막이
이긴다**(변화 없음). 상대 승계는 `uMax`를 `panelW`에만 쓰고 `relX/relY/relW`는
`uMax`와 **무관**하므로, 경합이 흔드는 양은 종전과 같은 «가로 폭·중심» 하나다.
세로는 `uMax`를 안 쓴다 ⟹ **경합 노출면이 늘지 않았다.** 수리는 별도 판.
