## §1 무엇을 어떻게 일반화했나

### §1-1 `panelStarts[2]` 관례 → **패널 역할 표**

종전 소비자는 「인덱스 2 이상이면 소매」로 패널을 갈랐다(`patternDressCore` **8곳**).
그 관례는 몸판2/소매2에서만 참이고 셔츠(앞판 2매)에서 곧바로 깨진다.

```ts
export type PanelRole = "torsoFront" | "torsoBack" | "sleeve";
export interface PanelTopology {
  roles: readonly PanelRole[];
  panelOf(vertex): number;          // 정점 → 패널
  roleOf(vertex): PanelRole;        // 정점 → 역할
  panelsWithRole(role): number[];   // 역할 → 패널 목록
  isTorso(vertex): boolean;         // 종전 `i < panelStarts[2]`와 «같은 판정»
}
```

티셔츠 구성은 `["torsoFront","torsoBack","sleeve","sleeve"]`이고 **종전과 같은 분할**이다
(§3-1이 전 정점 5244/5244 일치를 확인했다).

바꾼 자리: 밑단 사슬(패널 «인덱스 범위» → **역할**) · 34게이트 몸판/소매 분해 ·
자기충돌 y 술어 · 핏 리포트 앞/뒤 메시 선택 · 소매 정점 수집 · P14 관통 패널 귀속 ·
소맷부리 사슬(「마지막 소매 패널」을 역할에서 고른다).

### §1-2 리졸버 배열 `[front, back, null, null]` → **역할로 채운다**

```ts
const meshResolver = createPanelSplitResolver(
  g.topology.roles.map((role) => (meshFor(role) ? … : null)),   // 길이 = 패널 수
  g.panelCounts,
);
torsoPanels: [...panelsWithRole("torsoFront"), ...panelsWithRole("torsoBack")]
```

패널이 몇 개든, 앞판이 둘로 갈려도 성립한다. 티셔츠에서는 **종전과 같은 배열**이다.

### §1-3 `mirrorOf` 소매 2↔3 하드코딩 → **미러 표**

패널마다 둘만 말한다:

| 표 | 뜻 | 티셔츠 값 |
|---|---|---|
| `mirrorPanel[p]` | 미러 상대 패널(자기 자신이면 «패널 안»에서 미러) | `[0, 1, 3, 2]` |
| `mirrorLocal[p]` | 패널 «안» 정점 사상(null = 항등) | `[mFront.mirrorOf, mBack.mirrorOf, null, null]` |

전역 맵이 **한 루프**로 나온다. 종전 코드는 「패널 0·1은 자기 안에서, 2↔3은 통째로」가
박혀 있었다.

### §1-4 `PanelName` · `SeamSpec.kind` 확장 + 전수 레코드 해체

- 값 추가만: `PanelName`에 `cuff | placket | collar`, `SeamSpec.kind`에 같은 셋.
  **기존 값 의미 불변 · 지금은 아무도 만들지 않는다.**
- 진짜 결합이던 `Record<PanelName, PanelMesh>` / `Record<PanelName, number>`를 **Map**으로
  풀었다 — 종전에는 이름을 하나 더하면 그 두 줄이 곧바로 타입 에러였다(전수 레코드).
  이제 **제도가 실제로 낸 패널만** 담고, 없는 패널은 조용히 `undefined`로 흐르지 않고 throw한다.

### §1-5 게이트(`check:pattern`)도 같이 일반화

「게이트가 티셔츠만 통과시키면 리팩터가 반쪽이다」 조항 이행:

- `p=3..0` 역순 색인 **2곳** → `topology.panelOf`
- 패널명 배열 `["앞판","뒤판","소매L","소매R"]` → **역할에서 뽑는 `panelLabels()`**
  (같은 역할이 여럿이면 번호를 붙인다 — 셔츠 앞판 2매가 읽힌다)
- 변이 대상 엣지: 「인덱스가 뒤판 구간」 → **「역할이 뒤판」**

**로그 1줄이 더 정확해졌다**(숫자·판정 불변):
`소매 474×2` → `소매L 474 / 소매R 474`.

## §4 **여전히 티셔츠를 전제하는 자리 — 전량 10곳**

일반화한 것은 **소비 층**(패널을 어떻게 «가르는가»)이다.
**생산 층**(패널을 어떻게 «만드는가»)은 그대로이고, 그게 다음 판의 일이다.

| # | 자리 | 무엇을 전제하나 | 누가 푸는가 |
|---|---|---|---|
| 1 | `patternGarment:251-254` `draft.panels[0]/[1]/[2]` | 제도가 **정확히 3매**(앞·뒤·소매)를 낸다 | 셔츠 |
| 2 | `patternGarment` `panelRoles` 리터럴 | 역할 배열이 **손으로 적혀 있다** — 제도에서 도출해야 한다 | 셔츠 |
| 3 | `patternGarment:314` `mirrorPanel` 리터럴 | 미러 짝이 손으로 적혀 있다(§1-3 표는 일반이나 **값**은 티셔츠) | 셔츠 |
| 4 | `patternGarment:353` `panelIndexByName` | 이름 → 패널이 1:1이다. 셔츠 앞판 2매는 **1:다**가 된다 | 셔츠 |
| 5 | `patternGarment:326` `necklineRing` | 목선이 앞·뒤 **닫힌 고리**다. 앞여밈은 고리가 **열린다** | 셔츠 |
| 6 | `patternGarment:475` `neckSamplesOf = [0,1]` | 목선 표본이 패널 0·1에서 나온다 | 셔츠 |
| 7 | `patternGarment:528·547` `panelIdx === PANEL_PAT_FRONT ? +1 : −1` · `mapTorso` | 몸판이 **평면 2매**로 앞뒤 오프셋 배치된다 | 셔츠 |
| 8 | `patternGarment:566` 소매 배치 `[SLEEVE_R, armPlus] / [SLEEVE_L, armMinus]` | 소매가 **정확히 2매**이고 각각 한 팔에 감긴다 | 커프 밴드 |
| 9 | `patternDraft:530` `checkDraft`의 `panels[0]/[1]` · `draftTshirtPattern` | 제도 함수 자체가 티셔츠다 | 셔츠 |
| 10 | `patternDressCore` `anchorList`(어깨 능선) · `sim.setCollarRing` | **어깨로 매달리고 목선이 닫힌 고리**다 | 셔츠 |

> **⚠ 절 신설(P21 §1-4) — 이 표에 「조립 층」이 빠져 있었다.** 표는 **소비 층**(패널을 어떻게
> 가르는가)과 **생산 층**(패널을 어떻게 만드는가)만 갈랐는데, 그 사이에 **조립 층**
> (패널 배열 → 전역 버퍼)이 따로 있다. 그래서 P20의 `p < 4` **4곳**(2D·삼각형·UV·엣지)도
> P21의 **2곳**(`selfCollisionMinDistM`·`quality`)도 이 표 밖이었다.
>
> ```
> 조립 층
>   해소  pos2 · tris/panelTriRanges · uv · edgePairs        (P20)
>   해소  selfCollisionMinDistM · quality                    (P21)
>   남음  necklineRing(패널 0·1 고정) → 아래 5·6과 같은 자리
>   천장  pairKey 총 정점 < 1,000,000
> ```

**커프 밴드는 8번 하나만 풀면 된다**(밴드도 소매 역할로 두면 §3-3이 통과한다).
**셔츠는 1·2·3·4·5·6·7·9·10을 함께 푼다** — P7-scope §2-2의 P2급 산정 그대로다.

## §5 다음 판이 이어받을 인터페이스

```ts
// 패널을 «만드는» 쪽이 채울 것
panelRoles: PanelRole[]                 // 패널마다 역할 하나
mirrorPanel: number[]                   // 미러 상대 패널(자기 자신 가능)
mirrorLocal: (Int32Array | null)[]      // 패널 안 정점 사상(null = 항등)
meshByPanel / panelIndexByName: Map     // 이름 → 메시·패널(전수 레코드 아님)

// 패널을 «가르는» 쪽이 쓸 것 — 인덱스를 직접 비교하지 말 것
g.topology.roleOf(v) / isTorso(v) / panelsWithRole(role) / panelOf(v)
```

**규약 1줄**: 새 소비자는 `panelStarts[n]` 비교를 쓰지 않는다. 역할을 묻는다.
그 규약이 깨졌는지는 `npm run check:topology`가 아니라 **grep으로** 본다(§4 표가 현재 전량이다).
