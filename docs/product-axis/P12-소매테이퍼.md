## §1 도출 — **실행 «전»에 확정한 식** (사후 조정 0)

```
커프 반폭  = ( 팔 축 수직 단면 둘레(호장 = cuffY) + ARMHOLE_ARM_CLEARANCE_M ) / 2
소매 반폭(y) = base + (커프반폭 − base) · (y − capHeight) / (cuffY − capHeight)     ← 직선
```

### §1-1 여유(ease) — `ARMHOLE_ARM_CLEARANCE_M = 0.020` **재사용**

회차 문언이 제시한 후보를 그대로 채택했다. 같은 파일·같은 옷·같은 계열(「팔이 통과할
최소 여유」)이고, 104 §3이 `ARMHOLE_DEPTH_EASE_M`을 같은 논리로 재사용한 선례가 있다.
**다른 값을 쓰지 않았으므로 근거를 따로 적을 것이 없다. 새 손 상수 0.**

### §1-2 호장 대응 — **타입 분기가 없다** (성립 확인)

「호장 위치에 해당하는 프로파일 값을 쓰면 타입 분기 없이 둘 다 성립하는지」가 회차 질문이었다.
**성립한다.** 근거는 코드 사실이다:

> 배치가 소매를 `trueShoulder + d·y + (원주 항)`으로 놓는다(`patternGarment` 소매 절 ·
> 「패턴 y가 곧 팔 축 방향 거리」라고 그 주석이 이미 적고 있다).
> ⟹ **패턴 y = 팔 축 호장**이고, `cuffY = capHeight + underSleeve = sleeveLengthM`이다.

그래서 반팔은 y=22cm(위팔 자리), 긴팔은 y=58cm를 **각자 알아서 집는다**. 분기 0.

**단, 긴팔은 정의역을 벗어난다** — 팔 폴리라인은 47.1cm이고 소매는 58cm다.
**외삽하지 않고 끝값을 쓴다**(`girthAtArc`): 그 끝값이 P11이 정의한 「손목 = 손 직전」
14.88cm다. 이것이 이 판에서 유일하게 «규칙»을 새로 정한 자리이고, 상수는 아니다.

| | cuffY | 그 자리 팔 둘레 | **커프 둘레(제도)** | 종전 |
|---|---|---|---|---|
| 반팔 | 22.00cm | 24.36cm(위팔) | **26.36cm** | 36.00cm |
| 긴팔 | 58.00cm | 14.88cm(손목 · 정의역 끝값) | **16.88cm** | 36.00cm |

### §1-3 테이퍼 곡선 — **직선을 쓴다** (「팔을 따라가는 것이 기본」 조항에 대한 답)

**따라갈 수 없다**: 캡 쪽 끝은 암홀↔소매산 이즈 이분법이 `base`(18cm)로 못박고 있어
프로파일 값(반폭 14.62cm)으로 내리면 소매산 둘레·암홀 정합이 깨진다. 즉 이 구간은
팔을 «따라가는» 곡선이 아니라 **두 구속(암홀 / 손목) 사이의 전이**다.

직선이 안전한지는 **수치로 확인했다**(프로파일 42표본 전량에 0.5cm 간격 대조):

| | 최소 여유(소매 둘레 − 팔 둘레) | 자리 |
|---|---|---|
| 반팔 | **+2.11cm** | y=21.8cm(소맷부리 직전) |
| 긴팔 | **+2.08cm** | y=57.8cm(소맷부리 직전) |

- 전 구간에서 **여유(2.00cm) 이상** — 끼임 0. 구속점은 소맷부리 자신이다.
- 직선은 프로파일 추종보다 **항상 느슨한** 쪽이다(반폭 최대 +3.41cm@y=12.3cm).
  추종으로 바꾸면 «더 조이는» 방향이고 팔꿈치(23.30cm)에서 여유가 줄어든다.

⟹ 곡선을 도입할 근거가 없다. `CurveDef`에 폴리라인 종류를 새로 만들지 않았다(위상 불변).

### §1-4 팔 실측이 없으면 — **종전 직통 원통**

`body.armSection`이 null이면(P10 이전 커밋 fixture · 전신 인덱스 없음) 커프 반폭 = `base`다.
그 경로는 **비트 동일**이고, 그래서 Node 하네스는 **종전 옷을 계속 돈다**(§4 등재).

⟹ **기준선 B는 이 판에서 갱신된다.** 새 정본은 위 표의 「반팔 후」 열이다

**미학 판단은 사용자 몫이다**: 반팔이 「낙낙한 통」에서 「위팔에 붙는 소매」로 바뀐다.
지표가 아니라 취향의 문제라 자체 선언하지 않는다 — §3-4 캡처를 보고 판단해 주기 바란다.
되돌리려면 반팔에만 여유를 키우는 것이 아니라 **타입 분기**를 넣는 결정이 필요하다.

### §4-1 ⚠ 등재 — **하네스와 제품이 «다른 옷»을 돈다**

이 판부터 Node 하네스(`dress:pattern` · `check:pattern`)는 **직통 원통 소매**를,
브라우저 제품 경로는 **테이퍼 소매**를 돈다. 원인은 커밋 fixture가 P10 이전 판본이라
팔꿈치·손 좌표가 없다는 것 하나다(P11 §2-2가 `armProxyGirthM`을 전환하지 않은 것과 **같은 이유**).

- **좋은 점**: 기준선 A(하네스)와 `dress-state` md5가 이 판에서도 유효하다.
- **나쁜 점**: 하네스 숫자가 더 이상 제품의 소매를 대표하지 않는다.
- **해소 경로**: fixture 재생성. CLAUDE.md가 「fixture 재굽기는 기준선 A 전량 무효 ⟹
  **별도 판**」으로 못박고 있으므로 이 판에서 하지 않는다.
