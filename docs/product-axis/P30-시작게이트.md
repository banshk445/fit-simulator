## §1 확인 (코드 고치기 «전»)

### §1-1 `base` 세 조건이 백그라운드에서 갖는 값

`DressButton.tsx:78~79`(수리 전 줄번호)

| 연언지 | 식 | 백그라운드에서 | 막는가 |
|---|---|---|---|
| ① 렌더 프레임 | `mannequinPoseRef.frames >= 1` | **거짓** — rAF가 멎어 `frames`가 **0에 고정**된다(P29 §3-7 실측: 93분 후에도 0) | **이것이 막는다** |
| ② 스케일 잔차 | `maxScaleResidual <= POSE_SETTLE_EPS`(1e-4) | 초기값 그대로 · **막지 않는다** | 아니오 |
| ③ 본 준비 | `mannequinRootRef.current && b.left && b.right` | GLB는 캐시에서 75ms에 도착하고 컴포넌트가 서면 채워진다 · **막지 않는다** | 아니오 |

⟹ **거짓인 것은 ① 하나**다. ②③은 백그라운드와 무관하다.

### §1-2 `:89` 상한 탈출의 도달 조건

```
:80   if (!base) return;          ← 여기서 되돌아간다
:81   const waited = …
:82   if (poseStopped()) { …준비 완료… }
:89   else if (waited > POSE_STOP_TIMEOUT_MS) { …그대로 굽는다… }
```

**`:89`는 `base`가 참일 때만 평가된다.** 즉 도달 조건은 「프레임이 돌고 있고, 잔차는
작은데, **멎지는 않았다**」 하나뿐이다 — 전경에서 스케일 lerp가 진동할 때(P25 §3-2가
등재한 상태)가 그 경우다. 전경에서는 도달한다.

**백그라운드에서는 ①이 거짓이라 `:80`에서 되돌아가므로 `:89`에 «영영» 못 간다.**
`setInterval`은 백그라운드에서도(≈1s로 느려진 채) 계속 돌지만 매번 `:80`에서 끝난다.
관측과 일치한다 — 93분을 둬도 버튼이 안 켜졌고 화면은 「마네킹 불러오는 중」이었다.
P23 §1이 상한을 둔 취지(**「말없이 막아 두지 않는다」** · 함정 25)가 이 경로에서만
성립하지 않았다.

### §1-3 `document.hidden` / `visibilitychange`

`src/` 전체에 **0건**(grep). 새로 읽어야 한다.

**「`frames` 정체만으로 판별」은 택하지 않았다** — 프레임이 0인 사유가 백그라운드
하나가 아니기 때문이다(GLB 지연 · 컨텍스트 소실 · 첫 마운트 전). 정체만 보면
**서로 다른 사유에 같은 문구**를 붙이게 되고, 그것이 함정 10(항목명이 다음 진단을
오도한다)의 형태다. `document.hidden`은 **표준 플랫폼 관측값**이고 한 줄이며 새 상수가
필요 없다 ⟹ 사유를 «가르는» 데만 쓰고, 가르지 못하는 경우에는 정체 사실만 말한다.

### §1-4 P17 ㉯(마네킹 준비 전 실행 차단)와의 관계

**그 차단은 이 판이 없애는 대상이 아니다.** P17 §2가 값으로 확정한 것 — 준비 전에
누르면 조용히 커밋 fixture(P10 이전 판본)로 돌고 미리보기가 정착 좌표를 정적 배치로
덮는다. 그것이 배포 화면 실패의 뿌리였다.

⟹ 이 판의 표적은 **「차단」이 아니라 「침묵」**이다. 버튼은 계속 비활성이고,
바뀌는 것은 **왜 비활성인지 화면이 말하느냐**뿐이다.

## §2 수리 — 고지 (강행 0)

`DressButton.tsx` 2곳. **`base` 가드를 없애지 않았다** — 그 «앞»에 상한 검사를 하나 두고,
넘으면 사유 문구를 상태에 싣는다. `bodyReady`는 **여전히 참이 되지 않는다.**

```
if (!base) {
  if (waited > POSE_STOP_TIMEOUT_MS) setStallNote(document.hidden ? …탭이 뒤에 있다… : …정체 사실…);
  return;                    ← 차단 유지. 굽지 않는다
}
setStallNote(null);          ← 준비되면 문구를 거둔다
```

**「그대로 굽게」 만들지 않은 이유(금지 조항)**: `frames === 0`은 포즈가 **정착하지 않은**
상태다. 그 상태로 구우면 P23~P27이 닫은 비결정성이 되살아난다(P25 §3-2 스케일 lerp
고정점 부재 · P26 §3-2 누적 회전 · P27 §3-1이 그 대가를 실측했다). **강행 0.**

문구는 **관측한 것만** 말한다.

| 조건 | 문구 |
|---|---|
| `document.hidden` | 「이 탭이 뒤에 있어 마네킹 준비가 멈췄습니다 — 앞으로 두면 이어서 진행됩니다」 |
| 그 외 | 「마네킹 준비가 N초째 진행되지 않습니다 (렌더 프레임 F)」 |

두 번째 문구는 **원인을 단정하지 않는다** — 「브라우저가 …」 같은 귀속을 쓰지 않고
경과 시간과 프레임 수라는 **관측값 둘**만 낸다.

상태 표시는 P9 §2대로 한 곳(`status`)에서 만든다 — `!bodyReady`일 때 문구가 있으면
그것을(`text-amber-300`), 없으면 종전 「마네킹 불러오는 중」을 낸다.

**복구 경로 무손상**: 전경으로 돌아오면 rAF가 재개 → `frames`가 오르고 `base`가 참 →
`setStallNote(null)` → 종전 경로 그대로 `poseStopped()`를 거쳐 `bodyReady`.
**새 분기는 «막힌 동안»에만 산다.**

**계기 영향 0**: `mannequinPoseRef` · `stopWaitMs` · `__fitDebug.poseState()` 무수정.

**⚠ 이 고지의 실효 범위(자체 판정)**: 백그라운드 문구는 사용자가 **돌아온 직후 잠깐만**
보인다 — 돌아오면 1~2초 안에 준비가 끝나 문구가 거둬지기 때문이다. 실효가 큰 쪽은
**전경에서 프레임이 0인 채 멎는 경우**(컨텍스트 소실 · GLB 실패 등)이고, 종전에는 그
경우도 「불러오는 중」으로 **무한히 침묵**했다. 두 경우가 같은 분기를 쓴다.

### §8-9-5 §2 고지의 오귀속 — **범위 축소 · P31 우선순위 «낮음»**

§8-4는 오귀속 위험을 일반적으로 적었으나 **실측이 범위를 좁힌다**:

- **전경 분기는 오귀속하지 않는다** — P30b 2차에서 WebGL이 죽고 `hidden: false`였을 때
  「마네킹 준비가 215초째 진행되지 않습니다 (렌더 프레임 0)」가 **정확히** 떴다.
  관측값만 말하는 문구라 사실과 어긋나지 않았다.
- **오귀속은 「배경 + WebGL 사망」이 «동시에» 성립할 때 한 경우뿐이다** — 그때만
  「탭이 뒤에 있어 …」가 원인을 잘못 단정한다.

⟹ **P31 수리 우선순위 «낮음»**. 처방 후보 ㉮㉯㉰은 §8-4에 그대로 둔다(착수 0).
