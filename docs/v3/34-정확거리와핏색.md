### §0-1a **CC 의 구현 판단 1건 — 집행 «전»에 등재한다**

```
 §0-1 의 처방은 「거리 = **three-mesh-bvh** 최근접점 질의」다. **CC 는 그 대신
 `src/v3/instruments.ts` 의 `exactBodyDist` 를 쓴다.** 이유를 먼저 적고 집행한다(사후 정당화 아님):
  ㉠ **같은 양을 이미 «게이트»가 그것으로 잰다** — `makeBodyDistance().bodyClearance` 가
     ③a 관통을 `exactBodyDist`(삼각형별 최근접점 · 균일 격자 후보)로 판정한다.
     리포트가 «다른 구현»을 쓰면 **자기검사가 두 구현의 차이를 재게 되고**, 그것은
     **[[함정/함정22-두계기다른판정]]** 이 경고하는 형태다. 같은 것을 쓰면 자기검사는
     **「리포트 ↔ 게이트」 일치**를 곧이곧대로 잰다.
  ㉡ **three-mesh-bvh 를 쓰는 저장소 코드는 `src/lib/bvhFromArrays.ts`(v2)뿐**이고
     **G1 이 v2 임포트를 0 으로 잠갔다**. v3 안에 BVH 를 새로 세우면 **같은 양의 세 번째 구현**이 된다.
  ㉢ `exactBodyDist` 는 **정확 거리**다(격자는 «후보 좁히기»일 뿐 값은 브루트포스와 같다 —
     `instruments.ts` 주석의 등재 문언). ⟹ **처방의 «의도»(포화 없는 정확 거리)를 그대로 만족한다.**
 **자기검사의 형태는 처방 그대로 유지한다** — 「밴드 «안»에서 정확 거리 ↔ SDF 최대차·일치율」.
 **전략 세션이 three-mesh-bvh 자체를 요구한 것이라면 이 판단을 물러야 한다** — 그 경우
 **다음 판의 몫**이고, 이 판은 위 근거로 진행한다.
```
