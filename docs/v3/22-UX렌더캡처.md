## §3 ㉡ 렌더 — **무변조 통과**

```
 대조  주입 «원본 파일»의 상태 페이로드 ↔ 렌더를 거친 «후» 패널이 내는 blob 의 상태 페이로드
   원본  faf4873fb33cfa371d5c105410aab479291f58602a7d0500ebf2347d9e2a91f9  (499,296 B)
   렌더 후 faf4873fb33cfa371d5c105410aab479291f58602a7d0500ebf2347d9e2a91f9  (499,296 B)
   ⟹ **한 비트도 바뀌지 않았다**
 헤더는 다르다(재발행) — `frame: 220 → 0` · `n`·`d`·배치 서명은 동일.
   **판정은 «상태 페이로드»로 한다** — 헤더의 frame 은 렌더가 아니라 «재발행»이 바꾼 것이다
 구조적 근거: 패널은 워커가 보낸 **Float32 사본**을 읽어 그린다. 물리 상태(Float64)에 쓰지 않는다
```

### §3-1 «렌더 기여» 목록 — 화면 결함을 물리로 오귀속하지 않기 위해

```
 이 렌더가 «하는» 것 — 전부 화면 층이고 물리와 무관하다
  (ㄱ) **Float64 → Float32 강등**(워커가 전송할 때). 표시 정밀도 손실이며 상태는 그대로다
  (ㄴ) **정사영**(원근 없음) · 등재 3뷰 프리셋(front · sideXplus · back) · 화면 위는 항상 +y
  (ㄷ) **z버퍼 가시성** · 삼각형 단위 **평면 셰이딩**(정점 노멀 없음 · 스무딩 없음)
       ⟹ **면이 각져 보이는 것은 렌더 기여다.** 물리 메시의 각도가 아니다
  (ㄹ) 색: 몸 [190,185,178] · 옷 [40,90,200] 고정. 재질·조명·그림자 **없음**
  (ㅁ) 화면 크기 300×420 로 스케일 맞춤(bounds = 몸+옷 합집합의 AABB)
 이 렌더가 «안 하는» 것: 노멀 재계산 0 · 스무딩 0 · 텍스처 0 · 후처리 0 · 애니메이션 0
```
