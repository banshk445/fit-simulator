## §1 최우선 — 물성 데이터와 제약 형태의 «대응» (**핵심 발견 · 갈래 필요**)

### §1-1 Wang 2011 모델이 실제로 어떤 형태인가 — ARCSim 소스 원문 [1차]

ARCSim 공개 포크(`jiongchen/arcsim`) 소스에서 **직접 읽었다**.

**원단 파일**(`materials/gray-interlock.json`) — 전량 인용:

```json
{
    "density": 0.187,
    "stretching": [
        [16.593832, -14.695990, 34.477123, 36.860302],
        [46.364765, 53.694656, 261.013855, -29.691301],
        [49.285110, 87.596100, 206.373993, 22.768457],
        [123.989220, 105.181770, 365.966217, 44.217571],
        [139.686325, 73.592560, 413.553162, -174.43853],
        [127.443810, 85.848587, 405.872833, 32.238411]
    ],
    "bending": [
        [23.191698e-6, 32.932217e-6, 34.406498e-6, 39.014420e-6, 23.382786e-6],
        [24.749964e-6, 18.651314e-6, 16.370552e-6, 25.095791e-6, 8.860165e-6],
        [14.267624e-6, 7.052906e-6, 14.515154e-6, 24.665127e-6, 19.383726e-6]
    ]
}
```

**구조체 정의**(`src/cloth.hpp`) — 원문:

```cpp
struct Material {
    double density; // area density
    StretchingSamples stretching;
    BendingData bending;
    double damping; // stiffness-proportional damping coefficient
    double strain_min, strain_max; // strain limits
    double yield_curv, weakening; // plasticity parameters
};
```

**핵심 타입과 소비 함수**(`src/dde.hpp`) — 원문:

```cpp
struct StretchingSamples {Vec4 s[40][40][40];};
struct BendingData {double d[3][5];};

void  evaluate_stretching_samples (StretchingSamples &samples, const StretchingData &data);
Vec4  stretching_stiffness (const Mat2x2 &G, const StretchingSamples &samples);
double bending_stiffness (const Edge *edge, int side, const BendingData &data, double initial_angle=0);
```

**파싱**(`src/conf.cpp`) — `load_material_data`가 `density`/`stretching`/`bending`을 읽고,
그 뒤 `density_mult`·`stretching_mult`·`bending_mult`·`thicken` 배율을 곱한다
(`density_mult *= thicken`). `StretchingData`는 **2×5 배열**이고 JSON 6행이
`d[0][0]`(→ `d[0][1..4]`로 복제) + `d[1][0..4]`로 들어간다.

### §1-2 그래서 무엇이 문제인가 — **신장은 직접 대응이 «안 된다»**

읽어낸 사실 3가지:

1. **신장 강성이 «현재 변형 상태의 함수»다.** `stretching_stiffness(const Mat2x2 &G, …)`가
   **그린 변형 텐서 G**를 받아 `Vec4`(강성 4성분)를 돌려준다. JSON의 6×4는 원자료이고,
   런타임 전에 **40×40×40 룩업 테이블**로 전개된다 — 즉 **변형 공간을 3축으로 이산화해
   강성을 표로 들고 있다.** 비선형이고 이방성이다.
2. **굽힘은 «엣지·면 단위 이면각 힌지»다.** `bending_stiffness(const Edge *edge, int side,
   …, double initial_angle)` — 엣지 하나와 그 한쪽 면, 그리고 정지 각도를 받는다.
   `d[3][5]`는 **방향 3 × 곡률 5**의 표다(축의 이름은 소스 주석에 없다 — §6 미확인).
3. **소성·변형 한계가 별도 항이다**(`strain_min/max` · `yield_curv` · `weakening`).
   v3 1차 범위 밖이지만 데이터에 딸려 온다는 사실은 적어 둔다.

**⟹ 대응 판정**: XPBD는 제약마다 **컴플라이언스 α = 1/k를 «상수»로** 준다. 그런데 위
모델의 신장 강성은 **매 시점 G에 따라 바뀐다.** 그러므로 **「Wang 값을 XPBD 신장 제약의
α에 그대로 넣는다」는 성립하지 않는다.** 설계 문서 §2-3이 걱정한 「수치를 못 읽었다」보다
**이것이 앞선 리스크**라는 전략 세션 지적이 **맞다.**

### §1-3 세 갈래 — 값과 근사 오차를 명시

| 갈래 | 내용 | 대가 | 판정 |
|---|---|---|---|
| **ⓐ 제약 형태를 모델에 맞춘다** | 서브스텝마다 현재 G에서 강성을 **룩업해 α를 갱신**한다(조각선형 XPBD). 삼각형 in-plane 제약 3~4개를 두고 각 α를 매 서브스텝 재평가 | XPBD 유도는 α **상수** 가정 위에 있다 ⟹ **엄밀 해가 아니라 근사**다. 서브스텝이 짧을수록 오차가 준다(small-steps와 궁합이 맞는다). 룩업 비용이 제약당 붙는다 | **1순위 후보** |
| **ⓑ 파라미터를 변환한다** | 작은 변형 대역의 **접선 강성 1점**만 뽑아 선형 이방 상수로 쓴다. 변환식 = `stretching_stiffness(G≈I)`의 Vec4를 warp/weft/전단 강성으로 사상 | **비선형성을 통째로 버린다.** 옷은 대부분 소변형이라 정지 형상에는 근사가 통할 수 있으나, **큰 변형(당김·눌림)에서 오차가 커진다**. 오차 크기는 **미측정** | 2순위 · S1에서 ⓐ와 값으로 비교 |
| **ⓒ 다른 데이터 소스** | KES-F 계열의 선형 파라미터를 직접 쓴다 | 카테고리 대표값 문제가 §2-3 그대로 돌아온다 | 후순위 |

> **[정정 · v3-03] 택일 «종결» — ⓐ 채택.** 아래 「이 판은 택일하지 않는다」는
> v3-01 시점의 상태다. v3-02 §4가 ⓑ의 대가를 값으로 냈고(주신장 ~2%에서 ±1% 초과 ·
> **오차 부호 일정** · 비용 1.46배), 전략 세션이 ⓐ를 승인했다. 설계 문서 개정 4 참고.
>
> **[정정 · v3-02] LUT은 40³이 아니라 30³이다** — `dde.cpp:34 nsamples=30`.
> 위 §1-1·§1-2의 「40×40×40」은 `dde.hpp`의 «선언 크기»를 본 것이다.

**이 판은 택일하지 않는다.** ⓐ가 1순위인 이유만 값으로 적는다 — small-steps는
서브스텝당 1반복이므로 **α 재평가가 「반복마다」가 아니라 「서브스텝마다」**이고,
그 주기가 곧 조각선형 근사의 구간이 된다. **택일은 S1에서 ⓐ·ⓑ를 같은 장면에서
돌려 값으로 한다.**

**굽힘은 대응된다** — 데이터가 이미 힌지형이다(§1-2 2번). §3 참고.

## §2 수치와 단위

### §2-1 확보한 것 [1차]

`gray-interlock` 1종의 전량 값을 §1-1에 인용했다. 형식이 확인됐으므로
**나머지 원단도 같은 경로로 읽을 수 있다**(`materials/*.json`).

| 항목 | 값/형식 | 비고 |
|---|---|---|
| `density` | 0.187 | 구조체 주석 **"area density"** = 면밀도 |
| `stretching` | 6행 × 4열 | → `StretchingData d[2][5]` → `StretchingSamples s[40][40][40]` |
| `bending` | 3행 × 5열 · 값 **7.05e-6 ~ 39.01e-6** | 방향 3 × 곡률 5 |

### §2-2 **단위는 «미확인»이다 — 그리고 그것을 푸는 방법이 있다**

소스 주석에 단위가 없고, 논문 본문 표를 아직 못 읽었다(§6). 추정은 하지만
**추정을 값으로 승격하지 않는다**:

- `density 0.187` — 면밀도가 **kg/m²**라면 187 g/m²로, 인터록 니트로서 **그럴듯한 크기**다.
  다만 **그럴듯함은 근거가 아니다.**
- `bending ~2.3e-5` — 굽힘 강성이 **N·m**(단위 폭당) 크기라면 원단으로서 그럴듯하다.

**⟹ 단위를 «역검증»한다**: 설계 문서 §3-1의 **외팔보(Peirce/ASTM D1388)** 시험이
바로 이 일을 한다. 어떤 단위 해석을 넣었을 때 **굽힘 길이가 실제 원단 범위로 나오는지**를
보면 해석이 맞는지 갈린다. **⟹ 단위 확정을 S2의 완료 조건에 붙인다**(설계 문서 개정분).

**이것이 v2 함정 13(문서에 적힌 숫자를 코드 확인 없이 상수로 승격)을 피하는 방식이다** —
숫자를 믿는 대신 **숫자가 만들어 내는 관측량으로 되짚는다.**

### §2-3 4종 대응 — **미정 유지**

원단 파일을 **1종만 읽었다**(`gray-interlock`). 10종의 목록·이름·물성 분포를 아직 못 봤으므로
면·데님·실크·니트에 무엇을 대응시킬지 **고를 근거가 없다.** 다음 판에서 목록 전량을
읽고 고른다. 「카테고리 평균이 아님」 명시 조항은 설계 문서대로 유지한다.

## §3 굽힘 형태 — 택일의 «사전 조건»이 정리됐다

| 질문 | 답 | 근거 |
|---|---|---|
| 두 형태의 입력 파라미터가 다른가 | **다르다** | 힌지형은 **엣지별 이면각 + 정지 각도**를 받고, 데이터도 그 형태다(`bending_stiffness(edge, side, …, initial_angle)`). Bergou 이차형은 **위치에 대한 이차 형식**이라 강성이 **상수 하나**로 들어간다 |
| 확보한 물성값을 둘 다 받을 수 있는가 | **아니다** | `d[3][5]`(방향 × 곡률)를 힌지형은 **그대로** 소비한다. 이차형은 **방향 의존과 곡률 의존을 둘 다 뭉개** 상수 하나로 만들어야 쓴다 |
| 이차형의 전제가 패턴 옷에 성립하는가 | **부분 성립** | 「평평한 정지 상태」는 **성립한다** — 2D 제도가 평면이므로 정지 이면각이 0이다. 「근사 등거리」는 **신장이 작을 때만** 성립하는데, 니트는 신장이 크다 |

**⟹ 정리**: **데이터를 살리려면 힌지형이다.** 이차형은 「최대 3배 빠르다」는 이점이 있으나
**물성 데이터의 방향·곡률 의존을 버리는 대가**를 치른다. 설계 문서대로 **택일은 S2에서
값으로** 하되, **비교 항목에 「데이터 손실」을 명시적으로 넣는다**(비용만 보면 안 된다).

## §4 드레이프 참값

### §4-1 확보한 것 [2차]

- **시편/원판 조합**: 시편 지름 **24 / 30 / 36 cm**, 지지 원판 **18 cm**.
  **30 cm 시편 + 18 cm 원판이 표준 조합**으로, 흐물흐물한 것부터 뻣뻣한 것까지
  가장 민감하며 **DC 30~98%**를 낸다.
- **시편 선택 규칙**: DC < 30% → 24 cm · 30~85% → 30 cm · > 85% → 36 cm.
- **원리**: 광원이 드레이프된 천의 그림자를 링 페이퍼에 투영, **그림자 면적 / 시편 면적**.
  **뻣뻣할수록 높다.**

**출처 등급 [2차]** — ISO 9073-9:2008 **원문은 유료라 못 읽었다.** 위 치수는 해설
문헌에서 확보한 값이다. **표준 원문 확인 전까지 [2차]로 표기해 둔다.**

### §4-2 **못 찾은 것 — 원단별 참값 표**

원단 종류별 드레이프 계수 참값 표를 **이번에도 확보하지 못했다.**
9종 원단의 실측 DC 표를 실은 공개 논문을 찾았으나 **본문 접근이 차단됐다**(HTTP 403).

**⟹ 설계 문서의 대안을 «확정»한다**: 절대 참값 대신 **상대 순서**로 판정한다.

**⚠ 그런데 순서의 근거도 아직 [미출처]다.** 「데님 > 면 > 니트 > 실크」는 통념이고,

- **[1차·확보]** 「DC는 뻣뻣할수록 높다」 — 시험 정의 자체.

  못 하면 **판정을 「원단 간 DC가 유의하게 갈린다」까지로 낮춘다**(순서는 안 건다).

## §5 미정 5건 중 «지금 닫은» 2건

### §5-1 `three-mesh-bvh` 부호 질의 — **없다. 대안 3종을 연다** [1차 · 로컬 소스]

설치본(`node_modules/three-mesh-bvh`)의 공개 API를 직접 확인했다.

| 확인 | 결과 |
|---|---|
| 부호 있는 거리 / 내포 판정 API | **없다**. `closestPointToPoint`는 **무부호** |
| 대신 있는 것 | `raycast` · `raycastFirst` · `intersectsGeometry` · `shapecast` · `CONTAINED` 상수(AABB 포함 판정용이지 점 내포가 아니다) |

**⟹ 부호는 «우리가» 만들어야 한다. 후보 3종**:

1. **레이 패리티** — `raycast`로 임의 방향 광선의 교차 수 홀짝. 라이브러리로 **가능**하고
   수밀 메시에서 **정확**하다. 비용이 최근접점 질의보다 크다(정점 수 × 광선).
2. **골격 기반 부호 샘플러** — v1 은행 자산 `bodySkeleton.ts` + `makeSkeletonSignedSampler`.
   **실측 등재분 있음**(어깨 대역 오분류 36.3%→1.8% · 몸통 9.6%→4.2%). 저렴하고 근사다.
3. **면 법선 내적** — 최근접 삼각형의 법선과의 내적 부호. **가장 싸고 가장 취약**하다
   (엣지·모서리 근방에서 뒤집힌다 — v1 Stage 1a가 이 계열에서 부호 모순 2.95%를 등재).

**이 판은 택일하지 않는다.** 다만 **설계 문서 §2-4의 「수밀 몸 메시」 제약이 1번을
가능하게 만드는 조건**임이 확인됐다 — 자르지 않은 메시라야 패리티가 정의된다.

### §5-2 `selfCollision.ts` 재사용 — **판정 형태는 못 쓴다 · 공간 해시만 후보** [1차 · 로컬 소스]

현재 구현이 무엇을 하는지 코드에서 확인했다:

| 항목 | 현재 구현 |
|---|---|
| 판정 형태 | **정점–정점 최소 거리** 밀어내기(`SELF_COLLISION_MIN_DIST = 0.01`) |
| 가속 | 균일 격자 **공간 해시**(셀 = minDist · 3×3×3 이웃) |
| 제외 규칙 | 같은 패널 **UV 반경 2 이내**(`SKIP_UV_RADIUS`) · 어깨~암홀 시접 구간 |
| 완화 | `RELAXATION = 0.3` under-relaxation |
| 주석이 밝힌 의도 | **「옷감 두께를 표현하려는 게 아니라 “겹쳐 보이는” 것을 막는 용도」** |

**⟹ 재사용 불가(구조적) — 이유 2가지**:

1. **점–점은 관통을 못 막는다.** 삼각형 사이를 정점이 통과하는 경우를 원리적으로 놓친다.
   v3가 필요한 최소 형태는 **점–삼각형 + 엣지–엣지**다. 주석 자체가 용도가 다름을 밝힌다.
2. **격자 인덱스 전제**(`panelCols`/`panelStarts` · UV 반경)가 붙어 있다. v3 메시는
   비정형이라 그대로는 못 쓴다. (P31이 예고한 「자기교차 채널이 실제로는 비인접 정점 쌍의
   문턱 위반 수」와 **같은 뿌리**다.)

**남기는 것**: **균일 격자 공간 해시**는 형태와 무관한 가속 구조라 **재사용 후보**다.

### §5-3 나머지 3건 — **미정 유지**

`patternGarment` 배치 · 렌더 층 · 계기 승계(`drapeMetrics`/`coverageMetric`).
**닫을 근거를 이 판에서 얻지 못했다.** 설계 문서의 미정 표기를 유지한다.

## §6 잔여 미확인 — 다음 판이 닫을 목록

| # | 미확인 | 왜 안 닫혔나 | 닫는 방법 |
|---|---|---|---|
| 1 | **물성 단위**(density·stretching·bending) | 소스에 주석 없음 · 논문 표 미독 | 논문 표 확보 **또는** S2 외팔보 역검증(§2-2) |
| 2 | **`BendingData d[3][5]` 축 이름** | 소스 주석 없음 | 논문 굽힘 절 |
| 3 | **`stretching` 6×4의 물리적 의미**(어떤 변형 상태 6개 · 어떤 성분 4개) | `evaluate_stretching_samples` 본문 미독 | `src/dde.cpp` 읽기 |
| 4 | **원단 10종 목록과 4종 대응** | 파일 1종만 읽음 | `materials/` 전량 |
| 5 | **드레이프 원단별 참값 표** | 논문 접근 차단(403) | 다른 공개 논문 · 표준 원문 |
| 6 | **4종 DC 순서의 출처** | [미출처] | 교재/논문 |
| 7 | ISO 9073-9 치수의 **1차 출처** | 표준 유료 | 표준 구매 또는 인용 논문 |
| 8 | §1 갈래 ⓐ/ⓑ **택일** | 값이 없다 | **S1에서 실측 비교** |
| 9 | 굽힘 힌지형/이차형 **택일** | 값이 없다 | **S2에서 실측 비교**(데이터 손실 항목 포함) |
| 10 | 부호 판정 3종 **택일** | 값이 없다 | **S3에서 실측 비교** |
| 11 | 미정 3건(배치·렌더·계기) | 근거 없음 | 해당 단계에서 |

**8~10은 «설계 미정»이 아니라 «측정 대기»다** — 단계가 오면 값으로 닫힌다.
1~7이 진짜 조사 잔여다.
