### §1-1 **선행 차단 1건 — v3는 UI 입력만으로 제도하지 못한다**

```
 v3S4.ts:109-112 이 «메타에서» 읽는 파생 치수 4종
   NECK_A 목선반폭 · ARM_G 암홀둘레 · CAP_H 소매산높이 · NECK_G 목선둘레
 그 메타(`scripts/fixtures/pattern-meta.json`)는 **v2 제도의 산출물**이다
 v2는 이 4종을 «몸에서» 뽑는다 — `patternDraft.ts:335-353`:
   neckHalfWidthM = bisect(...) · frontNeckDropM = neckHalfWidth + 상수 ·
   necklineGirth = 2×curveLength(...) · shoulderDrop = 몸 능선 기울기(`body.ridgeTopYAt`)
 ⟹ **v3-17 §1의 「치수는 데이터로 읽는다」가 실은 «v2 산출물에 의존»한다**
   UI가 주는 것은 store 6종뿐이고, 파생 4종은 «몸 + 규칙»에서 나와야 한다
```

**⟹ v3가 독립하려면 「몸에서 파생 치수를 뽑는 규칙」을 자체로 가져야 한다.**
v2는 그것을 `bodyGeodesic.ts`(503줄)·`bodyMeasure.ts`(541줄) 위에 세웠다.
**규칙을 «읽는» 것은 허용**되지만(v3-13 선례 — 데이터 읽기 ≠ 임포트) **코드 호출은 R4-3에 막힌다**
⟹ v3에서 **다시 도출**해야 한다.


## §3 UX 설계 후보 — 610초를 어떻게 다루나 (**설계만 · 구현 0 · 채택은 전략 세션**)

```
 ㉠ 진행률   v3는 «조기 종료»라 「정착 프레임 / 상한 600」이 자연스러운 진행률이다.
            더 좋은 것은 **창 순변위**(v3-22 채널) — 0.1mm로 수렴하는 값이라 «남은 정도»를 준다
 ㉡ 취소     워커 종료. v3는 프레임 경계에서 안전하다(체크포인트 구조가 이미 그 단위)
 ㉢ 백그라운드 완주  v2가 P30에서 「백그라운드 탭은 rAF가 멎어 frames가 0으로 고정된다」를
            등재했다(`DressButton.tsx:83-85`). **워커 자체는 계속 돈다** ⟹ v3도 같은 구조면
            완주한다. 다만 «진행률을 rAF로 세면» 같은 함정에 걸린다 — **워커가 프레임 수를 보내야 한다**
 ㉣ 재개     v3는 체크포인트가 «이미 있다»(pos+vel+헤더). 브라우저에선 IndexedDB로 옮기면 된다
 ㉤ 원단 선택  **S5 결과가 그대로 제품 기능이 된다** — 4종이 O4로 갈리는 것이 값으로 서 있다
            (v3-26 · 인접 차가 잡음 바닥의 5.4배). 「원단을 바꿔 보기」가 팔 수 있는 기능이다
 ㉥ 기다림의 성격  610초는 «한 번»이다. 치수를 바꾸면 다시 610초다 ⟹ **치수 편집 UX가
            「입력 → 확정 → 기다림」으로 바뀌어야 한다**(v2의 실시간 슬라이더와 다른 형태)
```
