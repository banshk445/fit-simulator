## §1 알파 합성 — **규약 등재 + 값 확인**

### §1-1 규약 (코드 주석 · 명기)

```
 **합성은 `canvas` 2D 의 «source-over»로 얹는다** — 대표색을 `fillRect` 로 깔고 `drawImage` 로 그린다.
 그 경로는 **소스 알파를 «구조적으로» 존중**한다:
   **α = 0** ⟹ 대표색 «그대로» ·
   **0 < α < 1** ⟹ **`out = src·α + 대표색·(1−α)`**(**premultiplied 내부 표현** ·
     `getImageData` 는 **non-premultiplied** 로 돌려준다 — 두 규약이 다르다는 사실을 명기한다).
 **알파 «없는» 포맷이면 전면 불투명으로 «그대로»** — **추측 매팅·배경 제거 알고리즘을 넣지 않았다**
   (**손 상수 0** · §0-2 금지 조항 준수).
```

### §1-2 값 확인 — **합성과 «같은 구조»로**

```
 `print-tee.png`(알파 62.3%)를 512×512 로 얹고 원본 알파와 대조:
   **완전 투명 163,456px → 대표색 유지 163,456px (100.00%)**
   **반투명 2,372px → 혼합식 `src·α + 대표색·(1−α)` 일치 2,372px (100.00%)**
 ⟹ **알파 존중이 «값으로» 성립한다.**
 **한계 병기**: 이 확인은 **합성 함수 «자체»가 아니라 그것과 «같은 구조»의 경로**로 했다 —
   그 자산은 **프레임 문턱이 발동**해 `compositePrint` 안에서는 **프린트가 그려지지 않기 때문**이다
   (v3-60 §1-4). **알파를 «가진 채 문턱을 통과하는» 자산이 저장소에 없다** ⟹ §2 갈래 B 와 같은 뿌리다.
```
