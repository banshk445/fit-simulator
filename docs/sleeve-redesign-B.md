# 소매 별개 조각 분리 (범위 B)

## 왜 A가 안 됐나 (확정된 사실)
- 소매와 몸통이 하나의 격자로 이어져 있어 암홀에 봉제선을 둘 자리가 없다
- armRowFactor의 테이퍼가 암홀 봉제선을 대신하고 있고,
  이게 단면을 찌그러뜨리는 원인이자 소매-몸통을 잇는 유일한 장치라
  분리가 불가능하다
- 게이트를 하드 분기로 빼면 row8↔row9가 20.89cm 벌어진다

## 목표 구조
- 소매를 독립 격자로 만든다 (자체 정점/제약)
- 몸판 암홀 가장자리와 소매 안쪽 가장자리를 봉제선 제약으로 연결
- 소매 단면은 팔 축에 수직인 링 (열=팔 축 위치, 행=둘레 각도)

**배경 확인**: `ClothSimulation`(clothPhysics.ts)은 이미 임의 개수의
`PanelDims[](cols/rows 독립)`을 지원하도록 일반화돼 있다(30번 리팩터 —
"몸판(앞/뒤판)과 소매(좌/우)를 진짜 하나의 파티클 배열로 합칠 수 있게
한다"는 그 시절 주석이 지금도 남아있다). 즉 물리 엔진 자체는 소매를
독립 패널로 되돌리는 걸 이미 전제로 설계돼 있고, `buildConstraints()`도
패널마다 따로 격자 위상을 도는 구조라 새 패널을 추가해도 이 함수는
안 건드려도 된다.

**다만** `garmentWorker.ts`에서 `PARTICLES_PER_PANEL`/`PANEL_FRONT`/
`PANEL_BACK`(정확히 2패널·동일 크기라는 전제)을 쓰는 곳이 28군데다 —
자체충돌 범위 슬라이싱, 메시 충돌 앞/뒤 분리, 캡슐 충돌 앞/뒤 분리 등.
소매 패널을 추가하면 이 전제가 깨지는 지점들을 하나씩 확인해야 한다 —
범위 B 착수 전에 미리 알아두시라고 남긴다(지금 결정할 항목은 아님).

## 결정이 필요한 것

### 1. 몸판 암홀 가장자리를 어떻게 정의할 것인가

**추천**: `torsoColumnRange(xMin, xMax)`(이미 있음, buildGarmentSim.ts)로
몸판 폭을 그대로 자르고, 암홀 가장자리는 열 `x=xMin`과 `x=xMax`를
`y=0`(어깨선)부터 `y=armholeStartRow`(현재 `ARMHOLE_ROW_FRACTION=0.18`→
row 5)까지의 세로선으로 정의한다.

근거: 이 경계(`armholeStartRow`)는 이미 코드 전체에서 "암홀 끝~옆선
시작" 지점으로 취급되고 있다 — `SHOULDER_CAP_SKIP_END`(캡슐 충돌 스킵
구간), `addTorsoSideSeamConstraints`가 봉제선을 시작하는 행이 정확히
이 값이다. 새 경계를 발명하지 않고 이미 코드 전체가 합의하고 있는
값을 그대로 재사용하는 게 제일 안전하다.

### 2. 소매 격자의 해상도

**추천**: 둘레 12정점 × 길이 12행, 좌우 소매 동일(반팔/긴팔 구분 없이
행 수 고정 — 길이 차이는 정점 간 rest length로만 반영, 밀도는 안 바꿈).

근거: 둘레는 각진 티가 안 나 보이는 최소선이 대략 12각형 안팎이다(6~8은
갑옷처럼 각져 보였던 46번의 과거 실측 기록과 같은 함정). 길이는 시각적
곡률보다 드레이프(처짐) 표현이 관건이라 몸판(28행/70cm)만큼 촘촘할
필요는 없어 보인다 — 다만 이건 실측 없이 고른 값이라 사용자 확인이
필요하다. 좌우 소매 합쳐 12×12×2=288정점 추가(현재 44×28×2=2464의
~12%) — 46번에서 있었던 프레임드랍 이력을 감안하면 이 정도가 안전선.

### 3. 봉제선 제약 대응

**추천**: 소매 둘레 해상도를 **2×(armholeStartRow+1)**로 맞춰서(질문2와
연동 — armholeStartRow=5면 12), 몸판 암홀 가장자리(앞판 6정점 + 뒤판
6정점)와 소매 링의 앞반/뒤반을 정점 인덱스로 1:1 직접 대응시킨다.
재표본화(리샘플링)나 최근접점 탐색 없이 인덱스만 맞추면 끝난다.
제약은 기존 봉제선 함수(`addTorsoSideSeamConstraints`,
`addNecklineSeamConstraints`)와 같은 패턴 — `sim.addConstraint(a, b,
restLength)`, restLength는 `SEAM_REST_LENGTH`(6mm, 기존 시접 관례값).

근거: 기존 봉제선들이 쓰는 `SEAM_EASE_ROWS`/`SEAM_EASE_START` 완만한
전환(0.03m→6mm로 서서히)은 "공유 격자 위에서 앞뒤판이 억지로 다른
지점에 있다가 갑자기 붙는" 문제를 완화하려던 것이었다 — 소매가 진짜
독립 패널이 되면 애초에 배치 단계에서 암홀 가장자리에 맞춰 놓을 수
있으므로 그 힘겨루기 자체가 없다. 처음부터 `SEAM_REST_LENGTH` 그대로
써보고, 실측에서 찢어짐/뾰족함이 보이면 그때 이즈인을 추가하는 순서를
권한다(없어도 될 걸 미리 넣지 않는다).

### 4. 텍스처 UV

**추천**: 소매에는 텍스처를 아예 안 씌운다 — `compositeGarmentTexture`가
이미 계산하는 `borderRepresentativeColor`(원단 대표색, RGB)를 소매
머티리얼의 `color`로 직접 쓴다. UV 매핑 자체가 필요 없어진다.

근거: 지금 구조에서도 소매는 실질적으로 원단 대표색만 보인다 — 프린트
박스는 가슴 중앙에 고정 배치되고 폭도 전체의 45%뿐이라(`PRINT_WIDTH_
FRACTION`) 소매 열까지 닿지 않는다. 즉 "소매에 텍스처 캔버스를 UV로
새로 매핑"해도 결과물은 지금과 사실상 같은 단색인데, 그 결과를 얻으려고
UV 좌표 재계산 + 별도 지오메트리 UV 어트리뷰트를 추가하는 건 들이는
공에 비해 얻는 게 없다. 대표색을 재질 색으로 직접 물리는 쪽이 훨씬
단순하고, 프린트가 실제로 소매까지 이어지는 올오버 프린트 옷은 애초에
`compositeGarmentTexture`가 지금도 못 다루는 별개 한계라(README 참고)
이 결정이 그 한계를 더 나쁘게 만들지 않는다.

## 봉제선 조사 결과 (확정, frame 180)
- 몸판 암홀 12정점 = 앞판 row0~5(col=xMin) + 뒤판 row0~5
- 좌표: front row0~5 = (0.217,1.441,-0.029)(0.204,1.413,0.009)
  (0.205,1.387,0.019)(0.208,1.359,0.023)(0.211,1.329,0.017)
  (0.212,1.298,0.004); back row0~5 = (0.217,1.439,-0.029)
  (0.208,1.412,-0.060)(0.209,1.386,-0.068)(0.209,1.355,-0.073)
  (0.209,1.322,-0.066)(0.210,1.292,-0.051)
- 순서(둘레 wrap): idx0-5=front row0-5, idx6-11=back row5,4,3,2,1,0(역순).
  "반전/오프셋/리샘플링 불필요"는 봉제선(수직) 대응 한정이었다 — 링 wrap
  (둘레) 순서엔 틀렸다. 정정.
- 봉제선 대응(수직, 몸판↔소매): 소매 idx k ↔ 몸판 armholeVertex[k], 1:1
  직접 대응 유지(기존 결정 맞음)
- 근거(실측): 역순 인접 12변 0.20~5.54cm 고름, 급점프 없음. 정순
  (idx6-11=back row0-5)은 idx5↔6=14.49cm, idx11↔0=15.08cm 대각선 급점프.
  어깨 wrap(idx11↔0) 0.20cm로 사실상 닫힘, 겨드랑이(idx5↔6) 5.54cm 최대
- 정정(조사 완료): addSleeveUnderarmSeamConstraints(row9)와
  addSleeveArmholeSeam(row5)는 겹치는 파티클이 없는 별개 시스템 — row9는
  구 플랩(현재 렌더링되는 옷)의 겨드랑이 봉합, row5는 새 독립 소매 패널의
  암홀 경계. 통일 불필요, 둘 다 각자 시스템에서 유효.
- addSleeveUnderarmSeamConstraints는 지금 통째로 남긴다. 삭제 대상이
  아니라 5번(몸판 기존 소매 열 제거 + 렌더링을 새 패널로 전환)에서 구
  플랩과 함께 통째로 제거될 코드.
- 렌더링 확인: frontRenderGeometry/backRenderGeometry(Garment.tsx, COLS
  전체 폭)가 여전히 화면에 실제로 그려지는 메쉬 — 구 플랩 기준. 새 소매
  패널(PANEL_SLEEVE_LEFT/RIGHT)은 gridDebug에서만 쓰이고 화면엔 아직
  안 나타남. 4번(봉제선 연결) 완료 후에도 화면 변화 없음이 정상 — 5번에서
  렌더링을 전환해야 눈에 보인다.
