## §1-① 형식 사실 — 48 B/정점 = **위치 f64×3 + 속도 f64×3**

### 로더가 읽는 식(파일:줄 · 원문)

```
 src/v3/dressRun.ts:144   const need = 4 + hl + hdr.n * 3 * 8 * 2;
 src/v3/dressRun.ts:145-146   if (need !== total) throw new Error(`주입 상태: 헤더의 n=${hdr.n} 이면 …`)
 src/v3/dressRun.ts:148   const nb = sc.n * 3 * 8;
 src/v3/dressRun.ts:149   sc.s.pos.set(new Float64Array(inp.injectState.slice(4 + hl, 4 + hl + nb)));
 src/v3/dressRun.ts:150   sc.s.vel.set(new Float64Array(inp.injectState.slice(4 + hl + nb, 4 + hl + 2 * nb)));
```

⟹ `3 * 8 * 2` = **24 B(위치) + 24 B(속도) = 48 B/정점** · 배치는 **위치 블록 전체 → 속도 블록 전체**다
(정점별 인터리브가 아니다). 헤더는 `[u32 길이][JSON]` 이고 `n` 이 필수다(`:143`).

### T포즈 정본 blob 으로 교차 확인

```
 public/v3diag/v3-77/settled-c100-h155-s45_L.bin
   헤더 {"frame": 200, "n": 9948, "d": 0.009, "place": "0.016437/0.002000/0.222500/0.049844"}
   본문 **477,504 B** ÷ n 9948 = **48.0 B/정점** · 검산 `4 + hl + n×48` = **477,586** = 파일 크기 ✅
```

⟹ 판정문의 진단(제품 로더 48 B ↔ v4-48 포장 24 B)이 **코드와 정본 파일 양쪽에서 확인**된다.
v4-48 포장은 «위치만» 넣어 정확히 절반이었다(9490×24 + 헤더 = 227,870 수신).
