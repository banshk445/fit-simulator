### §0-4 집행 «전» 사전 결정 5건 (값을 보기 «전»에 적는다)

```
 ㄱ **① 「비트 대조」의 정의** — 두 실행의 최종 `pos` 필드를 **원시 바이트**로 비교한다
   (`pos.to_numpy()` = f32 · `tobytes()` 의 sha256 일치 + `np.array_equal`). `vel` 도 같이 센다.
   보조로 **최대 좌표차 · 다른 정점 수**를 항상 인쇄한다(같아도 0 으로 인쇄된다).
   ★ 두 실행은 **같은 프로세스 · 같은 컴파일 산출**로 돌린다 — 이 판이 묻는 경쟁은
   «커널 «안»의 쓰기 경쟁»이지 컴파일 재현성이 아니다. 상태는 같은 `pos0/vel0` 로 되감는다.

 ㄴ **② 「병렬화됐는가」의 확인 경로 3종** — 셋 다 적는다.
   ㉠ 코드 인용(파일:줄) ㉡ Taichi 문서 근거(최상위 루프만 병렬 · `loop_config`)
   ㉢ **기계 검사** — 「실행 순서 각인」 커널을 만들어 `serialize` 유무로 각각 돌린다.
      `ord[i] = cnt[None]; cnt[None] += 1` 이면 «진짜 직렬»일 때만 `ord == [0..N-1]` 이다.
      `full.py:233-234` 와 **같은 중첩 모양**(최상위 1회전 + 안쪽 range) 도 같이 잰다.

 ㄷ **④ 계기** — `ti.init(kernel_profiler=True)` + `ti.profiler.get_kernel_profiler()`.
   커널 «횟수»는 ㉠ 프로파일러 레코드 ㉡ 코드에서 센 수(직렬 = 창당 1 · 색분할 = 29×서브스텝)
   **둘 다** 적는다. 어긋나면 어긋난 채로 적는다.
   **오버헤드 추정치** = 같은 프로세스에서 «빈 커널»을 10만 회 띄운 벽시계 / 횟수
   (계산 0 인 커널이므로 이 값이 launch 하한이다). 비 = (추정 launch 총비용) / (벽시계).

 ㄹ **④ 는 직렬판·색분할판 «둘 다»** 60프레임으로 잰다 — 배수 대조가 채널이기 때문이다.
   프로파일러가 시간을 바꿀 수 있으므로 **v4-10 의 비프로파일 벽시계와 나란히** 적는다.

 ㅁ **③ 선행 조건 불성립 시** — ①이 (가) «그리고» ② 에서 `serialize=True` 가 확인되면
   「진짜 직렬판」은 **만들 대상이 없다**(이미 그것이다). 그 경우 ③ 은 **(다) 실행 불가**로 적고
   사유에 «선행 조건 미충족»을 쓴다. **사후 갈래 신설 0** — 이 결정은 값을 보기 «전»에 적는다.
```
