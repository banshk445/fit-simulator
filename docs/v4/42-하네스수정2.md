## §1-① 색인 전송 — **코드 사실 정정 + 「실행당 1회」 고정**

### 코드 사실(§0-4ㄱ · 읽기만)

| 자리 | 사실 |
|---|---|
| `V4AposeGrid.tsx` 칸 루프 안 | 전송은 **세 개뿐**이다 — `l3ap-body-<칸>-a35.bin` · `…-a35.json` · `l3ap-origin-<칸>-a35.json`. **색인 전송은 루프 «안»에 없다** |
| 같은 파일 루프 «뒤» | `l3ap-grid-index-a35.json` 을 **실행마다 한 번** 보낸다(v4-40 판본에서도 그랬다) |

★ **정정(다툼 0 · 판정문 문언은 그대로 옮겨 적었다)** — 「색인이 **칸마다** 전송돼 카운트 소진」은
코드에 그런 자리가 없다. 관측(수신기가 받은 6개가 전부 색인)과 코드가 함께 서는 해석은 하나다:
**실행이 6번 있었고, 매 실행이 27칸 «전부» 실패해 몸 bin 은 0개 · 색인만 1개씩 나갔다**
(판정문 ㉡ 「몸 bin 수신 0 = 칸들이 export 전 실패」와 정확히 맞는다). 결함이 **CC 귀책**이라는 판정은
그대로 받는다 — 실패만 한 실행이 수신기 `--n` 카운트를 먹게 둔 것이 하네스의 결함이다.

### 수정

```
 const 반출건수 = out.filter((x) => x.반출 === "3").length;
```

⟹ **실행당 최대 1회**(종전과 같다) **그리고 반출 0건이면 0회**. 부분 실패(일부 칸만 성공)면 **1회 보낸다**
— 판정문의 「실패 칸 존재 시에도 1회」 조항 그대로다. 색인 자체는 `window.__v4aposeIndex` 와
