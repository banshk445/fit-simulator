# ① 제도 — 어깨 경사 자유도

## ①-1 지금 무엇이 없는가 (코드 사실)

```
 현행 패턴의 어깨 이음선은 **수평 직선**이다 —
   `shL = line([−SW/2, **L**], [−NECK_A, **L**], N_sh)`   ← 두 끝의 `py` 가 **같다**
   `shR = line([ NECK_A, **L**], [ SW/2,  **L**], N_sh)`   (`garmentScene.ts:416-417`)
 그리고 배치의 수직 사상이 `y = Y_TOP − (L − py)`(`:602`)이므로
   **`py = L` 인 모든 점이 «단 하나의 높이» `Y_TOP` 으로 간다.**
 ⟹ 「어깨선이 수평」은 **배치의 성질이 아니라 제도의 성질**이다. 배치는 이미 `py` 가 다르면
    다른 높이로 보낸다 — 즉 **제도에 경사를 넣으면 배치는 그대로 «따라온다»**.
 ★ 몸은 수평이 아니다 — v5-10 §1-① 실측: 목 밑동과 어깨끝의 높이 차
   `Y_NECK − Y_TOP` = **82.2598 mm**(mst-over · SW 52) / **48.5991 mm**(supima · SW 44.5).
   v5-10 이 낸 「늘림 필요 하한」 **1.09960 / 1.05531** 은 **전부 이 수직 상승**에서 왔다
   (`Δx` 가 `SH_LEN` 과 정확히 같다 ⟹ 초과분 = 상승분).
```

## ①-2 형식화 — `SH_DROP` 한 항 (낙차형)

```
 정의   `SH_DROP` [m] = **목점과 어깨점의 «패턴상» 수직 낙차**. 어깨 이음선을 다음 직선으로 바꾼다:
          shL = line([−SW/2, **L − SH_DROP**], [−NECK_A, **L**], N_sh)
          shR = line([ NECK_A, **L**], [ SW/2,  **L − SH_DROP**], N_sh)
 앵커   ★ **동시에 앵커를 정정한다**(§0-2ㄹ) — `py = L`(= 목점)이 **`Y_NECK`** 으로 가야 한다:
          `y = **Y_NECK** − (L − py)`   ⟹ `Y_HEM = **Y_NECK** − L`
        근거 = 실측표 정의 「총장 = 옷을 눕혀 **뒷목 중심**에서 밑단까지」(`specToPattern.ts:6` 원문).
        지금은 그 길이를 **어깨끝 높이**에 매달고 있어 밑단이 `Y_NECK − Y_TOP` 만큼 내려가 있다.
        ⟹ **앵커 정정은 «선택»이 아니라 정정이다.** 그리고 정정하면 다음이 성립한다:
          어깨점의 3D 높이 = `Y_NECK − SH_DROP`  ⟹ **`SH_DROP = Y_NECK − Y_TOP` 이면 어깨점이 정확히
          몸의 어깨끝 높이 `Y_TOP` 에 앉는다.**
 각도형 (대안 표기) `SH_ANGLE = atan(SH_DROP / SH_LEN)` — 같은 자유도의 다른 이름이다.
        실측 기준 각도 = atan(82.2598 / 174.969) = **25.19°**(mst-over) ·
                        atan(48.5991 / 137.443) = **19.48°**(supima)
        ★ 낙차형을 **권하는 이유(사실)** — 제도 관행이 낙차(inch)로 적고(①-3), 코드가 이미
          `py` 좌표로 돌며(`line([x, py], …)`), 각도형은 `SH_LEN` 에 종속돼 **두 항이 엉킨다**.
 6번째 자유도 현행 5항(`L · W · SW · SLEN · ARM_G`)에 **`SH_DROP` 한 항**을 더한다.
        실측표(총장·가슴단면·어깨너비·소매길이·밑단단면)에 **없는 항**이다 ⟹ v5-1 규율대로
        **템플릿 상수로 이름과 값을 공개**한다(`TEE_TEMPLATE` 에 `ARM_G` 와 나란히).
```

### (a) 의류 제도 관행 상수 — **1차 출처 2건 확인**

★ **열어 보지 못한 것 2건(자기신고)** — 검색 결과 중 `theshapesoffabric.com`(HTTP **401**)과
`mellysews.com`(본문에 어깨 경사 값 **없음**)은 **인용하지 않았다**. 또 검색 요약에 나온 비례식

(값을 적지 않는다 · §0-4ㄱ).

```
 환산(1 in = 25.4 mm · 손 환산만) — 2 in = **50.8 mm** · 1¼ in = **31.75 mm** ·
   2½ in = **63.5 mm** · 3 in = **76.2 mm**  ⟹ **관행 범위 50.8 ~ 76.2 mm**(표준 63.5)
 ★★ 우리 몸 실측과의 대조 — `Y_NECK − Y_TOP` **48.5991 mm**(SW 44.5) / **82.2598 mm**(SW 52)
   ⟹ SW 44.5 는 관행 하한(50.8) **바로 아래 2.2 mm**, SW 52 는 상한(76.2) **바로 위 6.1 mm**.
   즉 **관행 범위가 우리 몸의 레귤러~드롭숄더 구간을 «거의 그대로» 덮는다**(우연이 아니라
   관행이 사람 몸에서 나온 값이라는 방증 — 다만 **이것은 대조이고 인과 단정 0**).
 ★ **앞/뒤 차이**(1¼ ↔ 2 in)를 현행 패턴은 **표현할 수 없다** — 앞판과 뒤판이 **같은 `topB`** 를
   쓴다(`:426-427` · §0-2ㄷ). 앞/뒤를 가르려면 **`topB` 를 둘로 나누는 자유도**가 추가로 필요하다
   (이 설계서는 그것을 **2세대의 «선택 항목»으로만** 등재한다 · 첫 판은 앞뒤 공통 `SH_DROP` 하나).
 장   문헌 근거가 있고 **몸에 종속되지 않는다**(옷은 옷의 값을 갖는다 · v5-1 정신).
 단   체형 3구간(2 / 2½ / 3 in)을 **어느 구간으로 놓을지**를 또 골라야 한다 ·
      드롭숄더(SW 52)는 관행 상한을 **넘는다**(82.26 > 76.2) ⟹ 관행 밖 값을 쓰는 근거가 필요하다.
 v5-1 규율 적합성 **적합** — 이름(`SH_DROP`)·값·출처(URL)를 `TEE_TEMPLATE` 에 적으면 숨은 상수 0.
```

### (b) 몸에서 도출 — `SH_DROP = Y_NECK − Y_TOP`

```
 장   ★ **어깨점이 정확히 몸의 어깨끝에 앉는다**(①-2 앵커 정정과 맞물려 자동으로) ·
      드롭숄더든 레귤러든 **한 식으로** 덮는다(SW 의 함수라 v5-7b 가 특정한 「절벽 = SW」와 정합) ·
      새 상수 **0**(`Y_NECK`·`Y_TOP` 은 이미 도출값이다).
 단   ★ **옷이 몸에 종속된다** — 같은 옷을 다른 몸에 입히면 **패턴이 달라진다**.
      이것은 v5 의 축(「옷을 데이터로 받는다」)과 **정면으로 어긋난다**:
        · 실측표만으로 패턴이 결정되지 않는다(몸이 있어야 패턴이 나온다)
        · 같은 상품의 패턴이 **몸마다 달라져** 「이 옷의 패턴」이라는 말이 성립하지 않는다
        · v3 정답지·v4 108칸 계정의 「같은 옷」 정의(`CLAUDE.md` v4 트랙)와 충돌 가능
      ⟹ **이 단점을 «등재»한다**(판정문 지시). 다만 **부분 채택**의 길이 있다(아래 ①-4).
 v5-1 규율 적합성 **부적합**(숨은 상수는 0 이지만 «옷 ← 몸» 방향 의존이 생긴다)
```

# ② 배치 — «내려 입히기» 절차 설계

## ②-1 능선의 `z` — v5-10 이 남긴 «산출 불가»의 해법 후보

```
 문제(실측) — 「띠 안 최상단」 규칙은 `y` 는 정하지만 `z` 를 정하지 못한다.
   z 폭 **100.093 mm** · 인접 표본 z 차 **중앙 17.111~19.486 mm · 최대 74.625 mm** ⟹
   폴리라인이 `SH_LEN` 의 **6.99~7.22배**로 부푼다(v5-10 §1-①㉢).
 ★ **후보 4종**(나열만 · 고르지 않는다)

 후보 1 — **두 끝점 + 몸 표면 최단 경로(측지선)**
   끝점 = 목 밑동 링의 어깨 쪽 점 ↔ `(±SW/2, Y_TOP, z(Y_TOP))` · 그 사이를 **몸 메시 위 최단 경로**로.
   장 — 잘 정의된다(측지선은 유일하지 않을 수 있으나 길이는 유일) · v5-10 의 **직선 하한**
        (19.2396 / 14.5044 cm)과 **위아래로 끼인다**(측지선 ≥ 직선) ⟹ 늘림 필요분이 **구간으로 확정된다**.
   단 — 저장소에 측지선 계기가 **없다**(새 알고리즘) · 메시 해상도에 민감.
 후보 2 — **평면 절단** — 두 끝점과 «몸 중심축»을 지나는 평면으로 몸을 잘라 그 단면의 위쪽 호를 쓴다.
   장 — `planeSection(nx, ny, c)` 가 **이미 있다**(`:94-111` · 지금은 수평면만 쓴다) ⟹ 인자만 일반화.
        z 가 평면에 의해 **결정된다**(임의성 소멸).
   단 — 평면 선택이 규칙이 된다(어느 평면인가 = 새 규칙 1개) · 어깨 위가 평지라 단면 호가 짧은 구간에서
```
