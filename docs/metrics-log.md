# 측정 로그

드레이프 개선(A안 → B안 재설계)의 매 단계 실측을 누적 기록한다. 한 실행 =
블록 하나, 파일 끝에 append. 코드 커밋과 구분되도록 이 파일 커밋은
`metrics: <단계명>` 으로만 쓴다.

**측정 하네스 두 종류를 섞지 말 것**

- `npm run sweep:pattern` — 12콤보, 캡슐 충돌만(BVH/자체충돌/스무딩 없음).
  절대값이 브라우저와 구조적으로 다르다. A단계 기록이 이쪽이다.
- `FIXTURE=scripts/fixtures/collision-fixture.json npm run sweep:pattern` —
  브라우저 스냅샷으로 워커 전체 파이프라인 재현(품55/소매통18 단일 조합).
  브라우저 실측과 seamGap/bodyGap이 자릿수까지 일치한다(M0 검증). M1 이후
  기록은 전부 이쪽이다.

스위치: `NEWCORE=1`(암홀 용접+직결 렌더) `FRICTION=1`(SDF 마찰)
`MU=0.4`(마찰 계수) `SIDEDNESS=1`(반평면 클램프 복원) `SMOOTHING=0`(스무딩
끔) `SMOOTH_BLEND=0.3`(라플라시안 blend) `COVERAGE_DUMP=경로`(노출 좌표).

지표 정의는 `src/lib/drapeMetrics.ts` / `src/lib/coverageMetric.ts` 주석 참고.
**개명 공지(2026-07-28)**: bodyGap → **capsuleGap** — 토르소 캡슐 근사
기준임을 이름에 박음(절대 목표 오용 차단, 함정 6번). 아래 이력 블록의
bodyGap 표기는 당시 기록 그대로 둔다(= capsuleGap과 동일 지표).
메시 기준 어깨 안착은 별도 지표 **shoulderSeatMm**(무부호)가 담당.
**지표가 전부 통과해도 화면이 실패할 수 있다** — A-③·C가 그랬다. 최종
판정은 사용자 화면 확인이다.

배열 **앞에 그대로 두고** 사이 표본을 뒤에 덧붙여, `positions.set(front, 0)`

(`torsoColMin/Max`). 각각 넥밴드와 시임 브리지·암홀 용접이 파티클 좌표를
그대로 읽어 붙는 자리라, 그 선이 휘면 밴드가 뜨고 이음매가 갈라진다.

## 2026-07-29 몸 메시 손상 규명·수정 + ① 문턱 재검증 **통과**

### 1. 임계 이분 탐색 — 분기가 아니라 **시간에 따른 지수 발산**

가슴 101~106을 1cm씩 구워 손상 정점 수를 셌다:

| 가슴 | 굽는 시점 | 손상 정점 | 성한 부분 |
|---|---|---|---|
| 100 | 25s | 0 | Y 0~1.700, \|x\|max 0.545 |
| 101 | 9s | 0 | 정상 |
| **101** | **25s** | **6,172 (38.9%)** | Y 0~1.700, \|x\|max 0.222 |
| 102 | 3s | 0 | **Y 0~8.39, \|x\|max 2.09**(발산 중) |
| 102 | 20s | 6,172 (38.9%) | 〃 |
| 103~106 | 8s | 6,172 (38.9%) | 〃 |

같은 가슴 값이라도 **늦게 구울수록 손상이 커진다**. 38.9%가 상수였던 건
분기가 아니라 **포화**(Float32 3.4e38)였고, 102를 3초에 구우면 Y가 8.4까지
커진 중간 상태가 잡힌다. 가슴이 클수록 발산이 빠르다. → 수치 발산 확정.

### 2·4. 손상 집합의 정체와 상류 원인

손상 집합은 가슴 값과 무관하게 동일했고, 성한 부분의 `|x|max`가 0.222m
(몸통 폭) — 즉 **팔 전체**다. 팔 본에 매 프레임 적용되는 것은
`pointBoneTowardWorldDirection` 하나뿐이고, 그게 원인이었다:

```
bone.quaternion.premultiply(localDelta)   // 매 프레임 누적 곱
```

`localDelta`는 부모의 월드 쿼터니언으로 컨쥬게이트해 만든다. 그런데
`getWorldQuaternion`은 월드 행렬을 분해하는 것이라, **조상에 비균등
스케일이 있고 그 아래 회전이 섞이면 결과가 순수 회전이 아니다** — 크기가
1이 아닌 쿼터니언이 나온다. 그게 프레임마다 복리로 곱해져 지수로 커진다.
가슴 100은 몸통 스케일이 정확히 1이라 이 조건이 안 생긴다.

**수정**: `parentWorldQuat.normalize()` + `premultiply(...).normalize()`.
물리 상수·솔버는 건드리지 않았다(마네킹 본 수학 버그).

### 3. StaticGeometryGenerator 재사용 — 반증 불필요

발산이 bake 이전(본 변환)에서 일어나는 것이 확정돼 3번 실험은 하지 않았다.
`bake`는 이미 손상된 본 행렬을 성실히 구웠을 뿐이다.
(먼저 배제한 가설: 어깨·목 역스케일. `?nocounter=1`로 1에 고정해도 38.9% 동일.)

### 게이트 — 전부 통과


785~810행). `SUBSTEP_DT`·`MAX_SUBSTEPS`는 식에 들어가지 않는다.
새 이름에 **축(열)** 과 **시점(호출 시점 1장)** 을 박고, 출력 라벨도
`columnRipple(열 방향 공간 4차차분 · 최종프레임 1장 · 정규화 없음)`으로
바꿨다. 옛 로그 블록의 표기도 전부 새 이름으로 통일했다(값 무변경).

### 계기 사실

1. **정규화 없음.** 값은 위치 조합의 mm 그대로. 공간 파수 k 이득
   = (4sin²(k/2))² — 순수 교대(파장 2열) 16 / 파장 4열 4 / 파장 6열 1.0.
   따라서 mean 14.99mm는 어디에도 15mm 변위가 아니다: 순수 교대 환산
   진폭 **0.937mm**. 창 평균 열간격 23.18mm(파장 2열 = 46mm).
   같은 14.99를 파장 4열(93mm) 매끈한 폴드 진폭 3.7mm도 낸다 —
   **파장 대역을 구분하지 못한다**(2차차분 곡률계 문제의 한 등급 위).
   3차 이하를 정확히 소멸시킨다는 주석 자체는 옳다.
2. **창이 좁다.** 앞/뒤판 · row1~5 · 열 13~30 = **표본 180개**.
   (창 지정은 열 xMin..xMax=11..32이나 4차차분이 양끝 2열씩 먹는다.)

### 공간 분포 (최종 프레임)

- 분포(mm): min 0.55 / p25 4.51 / med 9.37 / p75 22.14 / p90 34.51 /

  내부(x17 7.3 ~ x27 11.2)의 **2~4배**.
- 행별: row1 21.0 / row2 20.8 / row3 7.5 / row4 12.6 / row5 13.1.
- 패널별: 앞 17.3 / 뒤 12.7(뒤가 max 보유).

### 시간 채널과의 불일치

마지막 20프레임 Δ20 max = **4.57mm/프레임 @ 앞판 x21,y1**. x21은 열별
평균 8.7mm로 창 최저권 — **프레임당 가장 크게 움직이는 정점이 공간 상위
집합에 없다.** 정착 문턱 5.6mm/프레임은 환산 진폭 0.937mm의 6배라
"정착 65f"는 mm급 시간 떨림의 부재를 증명하지 못한다.
**공간 채널(columnRipple)과 시간 채널(Δ20)은 같은 정점 집합을 가리키지
않는다.**

팔축·골격 분기를 지지**하는 것으로 해소된다(어깨 대역 오분류 radial 36.3%
vs 골격 1.8%, 변이 역검증 98.2%). **게이트 승격은 하지 않는다 —
"승격 후보, 화면 대조 대기"**: 부호오판후보 29%에 천의 관통 성분이 섞여
있어 그 둘을 가르는 화면 대조가 남았다(규범 6: 승격 시 식 재도출).
