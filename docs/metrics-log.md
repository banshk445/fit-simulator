# 측정 로그

드레이프 개선(A안 → B안 재설계)의 매 단계 실측을 누적 기록한다. 한 실행 =
블록 하나, 파일 끝에 append. 코드 커밋과 구분되도록 이 파일 커밋은
`metrics: <단계명>` 으로만 쓴다.

**측정 하네스 두 종류를 섞지 말 것**

- `npm run sweep:pattern` — 12콤보, 캡슐 충돌만(BVH/자체충돌/스무딩 없음).
  절대값이 브라우저와 구조적으로 다르다. A단계 기록이 이쪽이다.
- `FIXTURE=scripts/fixtures/collision-fixture.json npm run sweep:pattern` —
  브라우저 스냅샷으로 워커 전체 파이프라인 재현(품55/소매통18 단일 조합).
  브라우저 실측과 seamGap/bodyGap이 자릿수까지 일치한다(M0 검증). M1 이후
  기록은 전부 이쪽이다.

스위치: `NEWCORE=1`(암홀 용접+직결 렌더) `FRICTION=1`(SDF 마찰)
`MU=0.4`(마찰 계수) `SIDEDNESS=1`(반평면 클램프 복원) `SMOOTHING=0`(스무딩
끔) `SMOOTH_BLEND=0.3`(라플라시안 blend) `COVERAGE_DUMP=경로`(노출 좌표).

지표 정의는 `src/lib/drapeMetrics.ts` / `src/lib/coverageMetric.ts` 주석 참고.
**지표가 전부 통과해도 화면이 실패할 수 있다** — A-③·C가 그랬다. 최종
판정은 사용자 화면 확인이다.

**기준선**: 제거 ① 상태(신 코어, 마찰 μ=0.6, sidedness off, 스무딩 0.5).
**관찰**:
1. **하드 실패** — 앞뒤판 실제 교차가 0에서 31~36개(최대 11mm) 발생.
   CLAUDE.md 게이트의 즉시 원복 조건.
2. **원인**: 마네킹 메시의 삼각형 와인딩 불일치. `signedClearance`는 면
   법선 내적으로 부호를 정하는데, 그 영역에서 부호가 뒤집힌 필드가
   구워지고 기울기가 몸 안쪽을 가리켜 파티클을 관통시킨다. 같은 와인딩
   문제를 `coverageMetric`에서 이미 실측해 방사방향 교정으로 우회한
   전례가 있다(그때는 mid-back 버킷이 93~96% "노출"로 나왔다). 팔 제외/
   포함 두 필드 모두 교차가 나므로 절단 경계 문제가 아니다.
3. **②의 전제가 이 측정으로 기각됨** — ripple mean이 3.22 → 3.21(팔제외)
   / 2.98(팔포함)으로 거의 불변. **잔물결의 원인은 BVH 면 법선의
   삼각형 단위 튐이 아니다.** M2-2의 ripple −29%도 마찰의 접선 억제
   효과였고, 발생원은 아직 미규명이다.
4. 부수: SDF 밀어내기는 BVH보다 26% 빠르다(23.0→17.4ms). 부호 문제를
   해결하면 성능 이득은 실재한다.
